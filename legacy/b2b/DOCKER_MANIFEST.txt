USAGE
================================================================================

Development (with hot reload):
  $ docker-compose up

Production (with nginx reverse proxy):
  $ docker-compose -f docker-compose.yml -f docker-compose.prod.yml up -d

View logs:
  $ docker-compose logs -f

Access services:
  Frontend: http://localhost:5173 (dev) or http://localhost (prod)
  Backend: http://localhost:8000/api/
  MinIO: http://localhost:9001
  Database: localhost:5432
  Redis: localhost:6379

Run migrations:
  $ docker-compose exec backend python manage.py migrate

Create superuser:
  $ docker-compose exec backend python manage.py createsuperuser

Monitor Celery:
  $ docker-compose logs -f celery-worker

NOTES
================================================================================

1. Build Arguments:
   The frontend Dockerfile accepts build-time args:
   - VITE_API_URL: Backend API URL (injected at build time)
   - VITE_WS_URL: WebSocket URL (injected at build time)
   
   Example:
   docker-compose build --build-arg VITE_API_URL=https://api.example.com frontend

2. SSL Certificates:
   For production, place SSL certificates in:
   - nginx/ssl/railtech.crt (full chain)
   - nginx/ssl/railtech.key (private key)
   
   Then uncomment the ssl_certificate directives in nginx/nginx.conf

3. Environment:
   Copy .env.example to .env and configure for your environment.
   Never commit .env with sensitive data to version control.

4. PostgreSQL:
   Supports both local (Docker) and remote (Neon, RDS, etc.)
   via DATABASE_URL environment variable

5. MinIO Buckets:
   Automatically created by minio-init service on first run:
   - public: Publicly accessible files
   - private: Private/authenticated files
   - temp: Temporary uploads

6. Redis:
   Separate Redis instances for Channels (WebSocket) and Celery
   to avoid interference.

7. Celery:
   Supports multiple workers and queues:
   - default: General tasks
   - pdf: PDF generation
   - imports: Excel/CSV imports

8. WebSocket:
   Daphne ASGI server with 1-hour timeout for long-lived connections.
   Proxied through Nginx with WebSocket upgrade headers.
