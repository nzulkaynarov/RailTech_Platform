# Smart Commit

Создай осмысленный коммит для текущих изменений.

## Инструкции

1. Выполни `git status` и `git diff --staged` (если нет staged файлов — `git diff`)
2. Проанализируй все изменения и определи:
   - Тип изменения: `feat`, `fix`, `refactor`, `style`, `docs`, `chore`, `perf`, `test`
   - Область (scope): название компонента, модуля или фичи
   - Краткое описание на **русском языке** (основной язык проекта)

3. **ОБЯЗАТЕЛЬНО** выполни полную сборку перед коммитом:
   ```bash
   npm run build
   ```
   Если сборка падает — **исправь ошибки** перед коммитом. НЕ коммить сломанный код.

4. Быстрая проверка дизайн-системы:
   ```bash
   grep -r 'text-\[10px\]\|bg-industrial\|text-industrial\|border-industrial' src/ --include='*.tsx' -l
   grep -r '#[0-9a-fA-F]\{6\}' src/ --include='*.tsx' -l
   ```
   Если найдены нарушения — исправь перед коммитом.

5. Добавь изменённые файлы в staging (`git add` — только релевантные файлы, НЕ используй `git add .`)
6. Создай коммит в формате:

```
<type>(<scope>): <описание>

<подробности если нужно>
```

## Примеры

```
feat(QuoteBuilder): добавить редактирование маржи по строкам
fix(authStore): исправить рефреш токена при 401 ответе
refactor(PublicCatalog): вынести логику поиска в отдельный хук
style(ProductCard): обновить стили для тёмной темы
```

## Важно

- НЕ пушь автоматически — только коммит
- НЕ добавляй файлы `.env`, `node_modules`, или файлы с секретами
- Если изменений нет — сообщи об этом
- Используй `git add` для конкретных файлов, не `git add -A`
- **НИКОГДА не коммить если `npm run build` падает**
