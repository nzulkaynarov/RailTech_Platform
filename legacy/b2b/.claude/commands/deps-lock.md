# Deps Lock

Проверка, что хеш-локи бэкенда не разошлись с исходниками зависимостей (INF-05).

Это **локальный аналог джобы `deps-lock` из CI** — единственного гейта, у которого до сих пор
не было команды. Пока CI репозитория лежит (GitHub-hosted раннеры не выдаются), правка
зависимостей не проверяется вообще ничем, а расхождение всплывёт только при сборке образа.

## Почему это важно

`backend/requirements.txt` и `requirements-dev.txt` — **генерируемые** хеш-локи, руками их не
правят (правило INF-05 в CLAUDE.md). Меняют floor/cap в `requirements.in` / `requirements-dev.in`
и **пересобирают** лок. Если забыть пересборку, лок и исходник разъезжаются: локально ставится
одно, в образе — другое.

## Инструкции

1. **Проверить, что рабочее дерево чистое по локам** — иначе `git diff` ниже покажет чужие правки:
   ```bash
   git status --short -- backend/requirements.txt backend/requirements-dev.txt
   ```

2. **Поставить pip-tools ТОЙ ЖЕ версии, что в CI.** Другая версия даёт другой лок — ложный дрейф:
   ```bash
   pip install "pip-tools==7.5.3"
   ```
   Ставить в отдельное окружение (venv на хосте), не в контейнер backend: в образе pip-tools нет,
   и сети у контейнера тоже нет.

3. **Пересобрать оба лока** — команды дословно как в CI, порядок важен (`-dev` компилируется
   с ограничением по основному локу):
   ```bash
   cd backend
   pip-compile --quiet --generate-hashes --no-strip-extras --output-file=requirements.txt requirements.in
   pip-compile --quiet --generate-hashes --no-strip-extras -c requirements.txt --output-file=requirements-dev.txt requirements-dev.in
   ```

4. **Проверить дрейф:**
   ```bash
   git diff --exit-code -- requirements.txt requirements-dev.txt
   ```
   - Код возврата `0` — локи в порядке, ничего не коммитить.
   - Непустой diff — **лок был устаревшим**. Пересобранные файлы и есть правильные:
     закоммитить их вместе с правкой `.in`, из-за которой возник дрейф.

5. **Если pip-compile падает на сборке psycopg2:** нужны системные заголовки Postgres
   (`libpq-dev` в Debian/Ubuntu, `brew install libpq` на macOS). psycopg2 в этом проекте
   намеренно собирается из исходников, а не `-binary` (INF-09).

## Ограничения

Лок зависит от платформы и версии Python. CI компилирует на **linux + Python 3.12**; пересборка
на macOS может дать другой набор маркеров. Если diff выглядит как расхождение по платформе, а не
по вашим правкам — пересобирайте внутри linux-контейнера с сетью либо доверьтесь CI, когда он
оживёт, и не коммитьте такой лок.

## Итог

- ✅ Локи синхронны с `.in` / ❌ дрейф в `requirements.txt` и/или `requirements-dev.txt`
- Если был дрейф — какие пакеты изменились (первые строки diff) и что закоммичено
