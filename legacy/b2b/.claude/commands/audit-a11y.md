# Accessibility Audit

Проведи аудит доступности (a11y) указанного компонента или страницы.

## Аргумент

$ARGUMENTS — путь к файлу или имя компонента (например: `src/pages/Dashboard.tsx`, `LoginPage`)

## Инструкции

### 1. Прочитай компонент и все его дочерние компоненты

### 2. Проверь по чеклисту

#### Семантический HTML
- [ ] Используются семантические элементы (`<main>`, `<nav>`, `<section>`, `<article>`, `<header>`, `<footer>`)
- [ ] Заголовки (`h1`-`h6`) используются иерархически
- [ ] Списки используют `<ul>`/`<ol>`/`<li>`
- [ ] Таблицы имеют `<thead>`, `<th>`, `scope`

#### Изображения и медиа
- [ ] Все `<img>` имеют `alt` атрибут
- [ ] Декоративные изображения: `alt=""`  или `aria-hidden="true"`
- [ ] Информативные изображения: описательный `alt`

#### Формы
- [ ] Все `<input>` связаны с `<label>` через `htmlFor`/`id` или обёрнуты в `<label>`
- [ ] Обязательные поля отмечены `aria-required="true"` или `required`
- [ ] Ошибки валидации связаны через `aria-describedby`
- [ ] Группы полей используют `<fieldset>` + `<legend>`

#### Клавиатурная навигация
- [ ] Все интерактивные элементы доступны через Tab
- [ ] Фокус видим (focus ring не скрыт)
- [ ] Нет ловушек фокуса (focus traps) кроме модальных окон
- [ ] Модальные окна ловят фокус и возвращают его при закрытии
- [ ] Кнопки используют `<button>`, а не `<div onClick>`

#### ARIA
- [ ] `aria-label` или `aria-labelledby` для элементов без видимого текста
- [ ] `aria-expanded` для раскрывающихся элементов
- [ ] `aria-live` для динамического контента (toast, ошибки)
- [ ] `role` используется только когда нет подходящего семантического элемента

#### Цвет и контраст
- [ ] Текст не полагается только на цвет для передачи смысла
- [ ] Интерактивные элементы имеют не-цветовые индикаторы (underline, icon)


### 4. Предложи исправления

Для каждой критической и серьёзной проблемы покажи конкретный код-фикс.
