## Итог

Платформа в целом работоспособна: авторизация, все разделы админки, REST API (≈30 эндпоинтов) и Sentry работают. Найдено **2 серьёзных** и **2 средних** дефекта, плюс несколько мелких. Критичнее всего — нерабочий WebSocket (нет real-time) и полный краш UI при устаревшем деплое.

## 🔴 Серьёзные

### 1. WebSocket / real-time не работает
- `wss://b2b.railtech.uz/ws/notifications/?token=…` — **таймаут** (нет open / error / close).
- Заведомо несуществующий путь `/ws/__nonexistent__/` виснет **точно так же** → проблема не в токене и не в пути, а в самом `/ws/`: nginx принимает TCP/TLS, но upgrade до WebSocket не завершается ни для какого пути.
- **Причина (вероятно):** в nginx для `location /ws/` не проброшены заголовки `Upgrade`/`Connection` или нет `proxy_pass` на Daphne; либо Daphne/Channels недоступен; либо лежит Redis Channels (`redis:6379`).
- **Влияние:** нет живых пуш-событий (новая сделка, бид, сообщение, смена KYC). Деградация мягкая — уведомления держатся на REST-поллинге `/notifications/` (200), поэтому при перезагрузке страницы они есть.
- **Что проверить:** конфиг `location /ws/` в `nginx/nginx.conf` (заголовки upgrade, proxy_pass на backend:8000); жив ли Daphne; `redis-cli ping` на 6379.

### 2. Полный краш UI при устаревшем деплое (stale chunk)
- При переходе в «Тендер-предложения» — белый экран «Что-то пошло не так / `Failed to fetch dynamically imported module: …/AdminSupplierBidsPage-BUFZQKk3.js`», ID `ERR_UI_CRASH`.
- После hard-reload тот же чанк подгрузился, но **с другим хешем** — `AdminSupplierBidsPage-CBrIMd5f.js` (200). Классический рассинхрон: вкладка держала старый `index.html`, новый деплой заменил хеши и удалил старые чанки → старый чанк 404 → error boundary роняет весь экран.
- **Влияние:** любой пользователь с вкладкой, открытой до последнего деплоя фронта, при навигации в lazy-роут получает полный краш и вынужден перезагружаться вручную.
- **Sentry сработал** (событие ушло в sentry.io → 200) — мониторинг ошибок жив.
- **Что сделать:** обработчик ошибки загрузки чанка с авто-reload; либо хранить старые чанки N дней после деплоя; либо PWA-апдейт с тостом «доступна новая версия».

## 🟠 Средние

### 3. Перемежающийся 502 на карточке компании
- `GET /api/v1/accounts/companies/36/` и `/companies/36/team/` — **502 Bad Gateway** на первом запросе, ретрай проходит (вкладка «Команда» сначала висит на скелетоне, со 2-й попытки подгружает OWNER).
- **Причина (вероятно):** холодный старт Neon Cloud / мёртвые соединения в пуле `dj-db-conn-pool` (описано в CLAUDE.md «Common Pitfalls»).
- **Что сделать:** pre-ping/health-check соединений пула, keep-alive до Neon, авто-ретрай на бэке или сброс пула при 502.

### 4. Дубли стран в справочнике с разной ставкой НДС
- В «Справочники → Страны» два набора с конфликтующим НДС:
  - `GER`/Germany — **12%** vs `DE`/Германия — **19%**
  - `RUS`/Russia — **12%** vs `RU`/Россия — **20%**
  - `CHN`/China — **12%** vs `CN`/Китай — **13%**
  - аналогично `KAZ`/`KZ`, `UZB`/`UZ`.
- Набор с 3-буквенными кодами (CHN/GER/KAZ/RUS/UZB, англ. названия, без ISO alpha-2, плоский НДС 12%) выглядит как остаток seed-данных.
- **Влияние:** риск неверного НДС в расчёте цен в зависимости от того, какая запись выбрана.
- **Что сделать:** удалить дубли-заглушки, оставить корректный набор с ISO alpha-2 и реальными ставками.

## 🟡 Мелкие

5. **`/health/` отдаёт SPA, а не бэкенд.** `https://b2b.railtech.uz/health/` → 200, но тело — `index.html`, не JSON Django health. Публичный health-чек не доходит до backend (внешний мониторинг получит ложный «healthy»).
6. **`GET /accounts/subscriptions/mine/` → 403 на каждой загрузке дашборда** у платформенного админа (у него нет членства в компании, подписки быть не может). Безвредно, но шумно — фронту стоит не дёргать этот вызов для админа.
7. **Хлебные крошки показывают сырой ключ роута** `admin-bids` вместо локализованного заголовка на странице «Тендер-предложения» (пробел в i18n).
