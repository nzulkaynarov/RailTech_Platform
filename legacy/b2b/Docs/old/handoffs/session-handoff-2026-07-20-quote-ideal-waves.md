### 🚀 DT1 разбит на ДВА деплоя (устраняет окно 500-ошибок) — ПРОЦЕДУРА ПУША

Риск: `deploy-b2b.yml` применяет миграции (стр.175) ДО пересборки контейнеров (стр.180). Миграция DT1
делает `margin_percent` nullable и зануляет все строки; старый прод-код делит `None/100` → билдер КП
падает в 500 на всё окно сборки. **Решение (expand/contract):** отдельный переходный Deploy 1.

- **Deploy 1** (ветка `deploy1/dt1-null-guard-transitional`, tip `6011c90`, off `origin/main`): крошечная
  None-заплатка на текущий прод-резолвер — NULL-маржа не роняет `None/100`, а НАСЛЕДУЕТ маржу КП;
  позиционное переопределение НЕ включается (это Deploy 2). На сегодняшних NOT-NULL данных ветка мертва
  → цена байт-в-байт как на проде (price-neutral, доказано полным прогоном 1056 + 3 unit-теста guard).
- **Deploy 2** (`main`, tip `662d3fa`): полный DT1 + миграция. Во время окна миграции Deploy-2 живой
  код — уже Deploy-1 (None-safe), поэтому NULL-строки считаются корректно, 500 нет.

**Guard вмержен в `main` через `-s ours`** (дерево Deploy 2 НЕ изменилось — DT1 сам обрабатывает None;
guard записан только как ПРЕДОК). Поэтому оба пуша — чистый fast-forward:


## 🔴 Находки, которых не было в плане

### 1. B1 успел испортить 8 боевых документов
Запрос к проду (read-only): 6 договоров + 2 инвойса печатают сумму в UZS с чужим кодом валюты.
Худший — **CT-2026-00005: 68 565 766 523.59 «USD»** вместо сумов (~5,4 млн USD-эквивалента), то есть
завышение примерно в 12 700 раз на юридическом документе. **CT-2026-00003 и CT-2026-00004 подписаны
обеими сторонами.** Контрагент во всех случаях — ООО «Test buyer» (внутренние тесты), реальный клиент
не пострадал. Миграция `0063_fix_document_currency_from_quote` чинит строки, **сумм не трогает**
(явно запрещено в докстринге) и очищает `pdf_file`, чтобы протухшие PDF перерисовались.

### 2. Виртуализация грида не работала в обычном режиме (найдено ГЛАЗАМИ)
Замер в Chrome на КП из 61 позиции: контейнер `flex-1 overflow-auto` имел
`clientHeight === scrollHeight === 3639`, `scrollable: false`, **61 из 61 строки в DOM**, скроллилась
страница. В fullscreen — 577px, 22 строки, всё работает. Причина (нашёл агент волны D):
shadcn-обёртка `SidebarProvider` имеет `flex min-h-svh` — МИНИМАЛЬНУЮ высоту, а не определённую,
поэтому вся цепочка `flex-1 min-h-0` резолвилась по контенту. Починка: `h-svh` для fullBleed-страниц.
После: `499 / 3112`, `scrollable: true`, **20 строк в DOM**, страница не скроллится, итоги закреплены.
**Вся работа PR #339 до этого была мертва в дефолтном виде.**

Важный побочный вывод: строка занимает **59px**, а весь хром над гридом — **184px**. При высоте
строки 44px в ту же площадь влезет 10 строк вместо 7, то есть высота строки стоит примерно вшестеро
больше всего оставшегося хрома. Это **инвертирует** приоритет U7 из спеки (там он «низкий»).

### 3. Ловушка DT1 (устранена, но знать обязательно)
`QuoteItem.margin_percent` был `NOT NULL default=0`, а движок позиционное значение игнорировал.
Наивное «включение» приоритета обнулило бы маржу во ВСЕХ исторических КП. Решение: колонка nullable,
все значения → NULL («наследовать»), явный `0` впервые получает смысл «продать по себестоимости».
Свойство «нулевое изменение цен» доказано тестом с независимым оракулом старой формулы плюс
негативным контролем (удали шаг данных — тест падает).

### 4. 🚨 Порядок деплоя создаёт окно 500-ошибок
`deploy-b2b.yml`: миграции — **строка 175**, подъём контейнеров — **строка 180**. Между ними (время
docker build) новая схема живёт со старым кодом. Для DT1 это значит: колонка уже nullable и значения
занулены, а старый `pricing.py` делит `None / 100` → **любое сохранение позиции КП падает в 500**.
**Рекомендация: разбить DT1 на два мержа** — сначала код с резолвером (безопасен на обеих формах
данных), затем миграция схемы+данных. Правило применимо к любой миграции, где новый код обязателен.
