# ТЗ: фикс-волны «Документы 2.0» — по итогам адверсариального аудита

_Статус: **DRAFT — ожидает утверждения владельцем.** Аудит 2026-07-22 (после закрытия волн A–D, PR #383–#386): 3 параллельных адверсариальных аудитора (backend-корректность, frontend-тупики, benchmark-gap Odoo/B24/PandaDoc) + ручные проверки оркестратора. CRITICAL не найдено; ядро безопасности (SSTI/XSS/IDOR, снапшоты, нумерация, транзакционность) подтверждено чистым повторно._

## 0. Сводка дефектов (приоритизировано)

### БЛОК I — корректность инвойс-lifecycle (MAJOR, ломает данные)

| № | Дефект | Сценарий поломки | Фикс |
|---|---|---|---|
| I-1 | `record_payment` принимает DRAFT-инвойс (`billing.py` — статус-гейт только на CANCELLED) | Покупатель «оплачивает» невыставленный черновик → инвойс-зомби: PAID без issued_at/PDF, `issue` навсегда возвращает ALREADY_ISSUED, `cancel` — CANNOT_CANCEL_PAID, акт генерится по никогда-не-выставленному счёту | Гейт: оплата только ISSUED/PARTIAL/OVERDUE → `INVOICE_NOT_ISSUED` |
| I-2 | PATCH DRAFT-инвойса без гейта стороны (`views/billing.py` update → `update_invoice_draft` без проверок) | Покупатель (queryset даёт обе стороны сделки) и platform-admin-viewer редактируют due_date/notes ЧУЖОГО продавцовского черновика | `_assert_seller_may_act_on_invoice` перед правкой (закрывает и viewer-инвариант) |
| I-3 | Покупатель ВИДИТ DRAFT-инвойс до выставления (queryset не фильтрует статус по стороне) | Черновик продавца со всеми суммами виден клиенту до решения продавца (Odoo: draft клиенту не виден) | В `get_queryset`: DRAFT видит только seller-сторона (buyer-ветка `_billing_visibility_q` исключает DRAFT); CANCELLED остаётся видимым обеим (Odoo-канон) |
| I-4 | Идемпотентность `generate_invoice_from_contract` возвращает и CANCELLED (`billing.py:73`) | После «Отменить» перевыставить счёт по договору НЕЛЬЗЯ (тупик); авто-путь шлёт продавцу нотификацию-фантом по отменённому инвойсу | `.exclude(status__code=CANCELLED)` + фронт: на SIGNED-договоре кнопка снова активна после отмены |
| I-5 | Голые `.get(pk=…)` по внешнему id → 500 (`generate_invoice_from_contract`, `generate_act`, `record_payment`) | Кривой id из request.data → DoesNotExist → 500 вместо 400/404 | try/except → `{"detail":"NOT_FOUND"}` 404 |

### БЛОК II — «доставка письма» (P1, обрыв обещанного сценария)

| № | Дефект | Фикс (реюз существующей инфры) |
|---|---|---|
| II-1 | Сгенерированное письмо НЕЛЬЗЯ отправить: ни email, ни публичной ссылки (только download). Спека §1.3 обещала отправку | Публичный токен по образцу КП (`Quote.public_access_token`/revoked/expires — те же 3 поля на GeneratedDocument, миграция) + анонимная GET-вьюха ТОЛЬКО для ISSUED (throttle как `public_quote`) + action `send-email` через `send_templated_email` (образец — `send_quote_email`). Фронт: `DocumentActions` c `publicLink` (компонент уже умеет copyLink) + пункт «Отправить на email» |
| II-2 | Покупатель НИГДЕ не видит полученное письмо (queryset только компания-владелец; уведомления при issue нет). Спека обещала «полученные письма — read-only» | (a) `Notification` FK→deal при issue (как у инвойса); (b) расширить queryset реестра «Прочие»: + ISSUED-документы по сделкам, доступным пользователю (реюз `_user_can_access_deal`-логики / buyer-owning deal) — read-only, покупатель видит «полученные» с бейджем |
| II-3 | Письмо нельзя создать ИЗ КАРТОЧКИ СДЕЛКИ (мастер смонтирован только в реестре «Прочие») — анти-B24 | Кнопка «Создать документ» на странице сделки → существующий `DocumentCreateWizard` с новым пропом `defaultDealId` (предзаполненный контекст) |
| II-4 | В карточке сделки не видно её документов; в реестре «Прочие» нет фильтра по сделке | `?deal=<id>`-фильтр в queryset вьюхи (1 строка — параметр уже есть у attachments-паттерна) + фильтр в реестре + блок/ссылка «Документы сделки» в карточке сделки |

### БЛОК III — гигиена UI/API (MAJOR-минор)

| № | Дефект | Фикс |
|---|---|---|
| III-1 | DELETE использованного шаблона → неперехваченный `ProtectedError` → **500** | `except ProtectedError` → 400 `TEMPLATE_IN_USE`; фронт-тост «деактивируйте вместо удаления» |
| III-2 | Мастер предлагает ДЕАКТИВИРОВАННЫЕ шаблоны (`DocumentCreateWizard` не фильтрует `is_active`) | Фильтр `is_active` в пикере (образцы остаются) |
| III-3 | «Создать инвойс» из договора: кнопка не скрывается после создания, `['contracts']` не инвалидируется, успех без навигации («создал — а где он?») | Отдать `invoice_id` на Contract-сериализаторе → скрыть/заменить кнопку ссылкой на инвойс; успех → переход `#invoices`; инвалидация contracts |
| III-4 | `OtherDocumentsPage`/`CompanyFilesPage` — голый `<Table>` без mobile-фолбэка (нарушение канона ResponsiveDataTable для НОВЫХ страниц) | Портировать обе на `ResponsiveDataTable` c `onRowClick` (закрывает и клик-по-строке в «Файлах») |
| III-5 | Preview-эндпоинт без rate-limit (санитайз+рендер 100k на каждый вызов) | `ScopedRateThrottle` ~30/min |
| III-6 | Генерация/выпуск документов не гейтится CompanyRole-правом (любой член компании, включая buy-only-джуна) — спека §2 обещала `quote.build`-класс | `member_has_permission(user, company, "quote.build")` в generate/issue/cancel (утверждено спекой — не новая блокировка) |
| III-7 | Мелочь фронта: blob-catch глушит реальную ошибку (3 страницы, `translateApiError` мимо); InvoicesPage держит стейл-снапшот selected (не re-derive из кэша); flash шага 1 при закрытии мастера; preview-дебаунс дёргается от name/kind; статы «Файлов» не сходятся при kind=null; viewer-гейт defense-in-depth в настройках шаблонов | Пакет точечных правок |

### Отложено (P3/v2 — НЕ входит в фикс-волны, по запросу владельца)
Upload из реестра «Файлы» (файл уровня компании); letterhead-снапшот ISSUED-документа (сейчас живой бренд); предпросмотр шаблона по реальной сделке; сквозной поиск по документам + «недавние документы» на дашборде; системная инвалидация дашборд-статов после billing-мутаций (общий долг всего billing-слоя, не этой спеки).

## 2. Решения владельца (утверждено 2026-07-22)

**ТЗ УТВЕРЖДЕНО.** Рекомендации приняты целиком:
1. **II-2 видимость покупателю → ДА**: реестр «Прочие» показывает полученные письма read-only с бейджем «Получен» (+ уведомление при выпуске).
2. **II-1 email → ДА**: отправка письма с публичной ссылкой в теле, единый паттерн с КП.
3. **P3 → ОТЛОЖЕНО** (upload в «Файлы», letterhead-снапшот, сквозной поиск, дашборд-инвалидация — не входят в фикс-волны).

## 3. Что аудит подтвердил чистым (не трогаем)
SSTI/XSS/IDOR ядро генерации; снапшот values+body (не «плывёт»); нумерация под select_for_update; транзакционность issue (202-путь спасает упавший рендер); отмена чистит PDF; i18n-симметрия всех 4 неймспейсов; кэш-инвалидация generated-documents/templates; типы без as any; empty-states без тупиков; deep-link bounce — НЕ регресс (общее поведение всех doc-страниц: guard ждёт bootstrap).
