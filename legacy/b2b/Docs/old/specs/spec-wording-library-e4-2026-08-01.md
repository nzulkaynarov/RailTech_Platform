# E4 — библиотека согласованных формулировок (бенчмарк + план)

_Дата: 2026-08-01. Завершающий шаг спеки `spec-editable-outgoing-documents-2026-07-31.md`
(E1–E3 закрыты #493–#502). Повод: «юристы сторон могут не принять формулировки» — менеджеру
нужен ответ на возражение по пункту БЕЗ правки шаблона всей компании и без сочинения текста._

## 1. Эталоны

| Эталон | Паттерн | Суть |
|---|---|---|
| **Ironclad** | Playbook: preferred + fallback positions | Юрист заранее задаёт по пункту предпочтительную редакцию и 1–3 согласованных фолбэка по убыванию приоритета; ревьюер меняет пункт «в один клик» ТОЛЬКО на заранее одобренный вариант; выход за диапазон — эскалация |
| **DocuSign / Sirion / SpotDraft** | Contract playbook canon | preferred → fallback → red line; продавец договаривается в пределах диапазона, не зовя юриста |
| **PandaDoc** | Content library + content locking | Библиотека проверенных блоков/клауз, вставка в документ; свободная правка ограничена замками |
| **Odoo** | Default T&C | Дефолтный текст в настройках/шаблоне + правка per-quotation. Библиотеки фолбэков НЕТ — отсутствие тоже решение (Odoo не строит переговорный слой) |

Общий знаменатель: **менеджер в переговорах ВЫБИРАЕТ из заранее согласованных редакций, а не
пишет текст**; согласованность обеспечивает не гейт, а сам набор вариантов.

## 3. Волна E4

1. **Модель `CompanyWordingVariant`** (company, field из каталога D1, title, text) — библиотека
   компании, управляется правом `settings.edit` (то же, что формулировки D1).
2. **`Contract.wording_selections` / `Act.wording_selections`** (JSON {field: text}) —
   заполняются при создании договора / выпуске акта резолвом D1 (профиль → платформа), рендер
   читает их в приоритете. Это одновременно и per-deal выбор, и закрытие дыры E3.
3. **Выбор варианта на договоре**: `POST crm/contracts/{id}/select-wording/ {field, variant_id|null}`
   (null = вернуть дефолт компании) — только пока договор не подписан ни одной стороной;
   сбрасывает PDF, пишет ActivityLog. Продавец-сторона, той же цепочкой гейтов, что генерация.
4. **CRUD вариантов**: `crm/wording-variants/` (company-scoped).
5. **UI**: Настройки → Формулировки — варианты по каждому полю; карточка договора — селектор
   формулировок до подписания.

Не делаем: red-line эскалацию, AI-детекцию пунктов, счёт (у него нет прозаических пунктов).
