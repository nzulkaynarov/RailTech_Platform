# Tech-Debt Register (2026-06-12, updated 2026-06-14)

Remaining work after a large cleanup/hardening pass (tender removed, nav/dashboard
slimmed, prod download fixes, source-of-truth import file). Prioritized for the
next sessions. Context: the platform is single-seller (RailTech) on the
Buyer ↔ Seller КП model; competitive supplier bidding was removed.

**Strategy (set 2026-06-14):** the focus is **technical + UX stability first** —
make the system robust and pleasant to use across all roles. The **P0 commercial
blockers below (real payment / qualified e-signature / in-country DB) are
deliberately deferred** until that stability bar is met; they gate the *public*
roll-out, not the pilot.

## ✅ Resolved since 2026-06-12

- **Seller КП builder dead-end → full-page builder.** The line-item/price grid was
  crammed into the deal Sheet (`h-[520px]`, `max-w-6xl`) — the owner's blocker that
  kept b2b in pilot. Now a dedicated `DealQuotePage` at the `deal-quote/<dealId>`
  hash route; the sheet is a lightweight overview that links into it via
  "Открыть КП" / "Создать КП". React Query throughout (no `flowStore`).
  → PR `feat/seller-quote-builder-page`. Verified end-to-end in a real browser.
- **Manual "Add item" was broken.** `QuoteItem.frozen_currency` serialised as a PK
  while the grid sent (and `formatMoney` expected) the currency *code* → 400 on add.
  Fixed with a `SlugRelatedField(slug_field="code")` — code in both directions.
- **Local dev was unusable** (CORS, missing npm/rollup binary, uninstalled
  `@sentry/react`). vite dev now proxies `/api`+`/ws` to the backend (same-origin,
  no CORS); `@sentry/react` reinstalled (it is in the lockfile). SPA builds and runs
  locally again — browser verification is back on the table.
- **Caddy multi-tenant footgun.** A GradeSentinel deploy overwrote the shared
  `/etc/caddy/Caddyfile` and dropped the b2b vhost. Moved to the `import`/`conf.d`
  pattern — each project owns one fragment, deploys never touch the master.
  → merged PR #66.

## P0 — public roll-out blockers (DEFERRED until stability bar met)

Tracked, not in flight. See `tech_debt_payment_esign` notes for detail.

- **Real payment provider** (Click / Payme / Stripe / 1C). Today the subscription
  `pay/` and invoice `record-payment/` are a manual mode — any manager can mark
  paid without money moving. Needs webhook endpoints + a `PaymentProviderEvent`
  model for idempotency + HMAC/IP-allowlist.
- **Qualified e-signature (E-IMZO).** Today contract/act signing is a simple
  electronic signature (ПЭП — signer identity + timestamp in the PDF). For
  high-value contracts UZ requires E-IMZO; needs a `DigitalSignature` model +
  endpoint. The ПЭП fallback is acceptable for the pilot.
- **In-country database.** Prod DB is Neon (AWS Singapore): ~124 ms per query from
  the UZ VPS, and UZ data-localization law (ЗРУ-547) likely requires personal data
  on servers in Uzbekistan. Plan: a dedicated in-country Postgres box (Eskiz),
  `import`/conf.d-style one-DB-per-project + PgBouncer, `pg_dump` migration off
  Neon. Decision parked; candidate spec evaluated (2 GB box ≈ enough for pilot +
  3–6 projects with PgBouncer).

## P1 — Proactive E2E verification

Drive the full Buyer ↔ Seller cycle in a running browser
(заявка → КП → approval chain → accept → contract → invoice → payment →
fulfillment → CLOSED_WON) and fix every dead-end before users hit it. Several
prod defects this period were found reactively (export-template 401, заявка-import
dead-end); a scripted end-to-end pass catches them first. **Note:** a working
Playwright harness (auth-injection, screenshot probes) was used ad-hoc to verify
the КП builder — formalise it into `frontend/e2e/` so it runs in CI.

## P2 — Catalog single-product form (railway products broken)

- `components/Catalog`/`AdminCatalogPage.tsx` `ProductFormSheet`: the
  "Manufacturer" select lists `catalog.Manufacturer` (`brand`) options but writes
  to the **deprecated** `Product.manufacturer` (Company FK), so the canonical
  `brand` is never set. The form can't set `equipment_groups` or
  `manufacturer_part_number` → RAILWAY_MACHINERY products fail `full_clean()`
  (require ≥1 equipment group). Bulk Excel import is fine; only the single form
  is broken.
- `Product.manufacturer` (Company FK) is deprecated → migrate to `brand`
  (catalog.Manufacturer), swap the ~11 frontend readers, then drop the field.
- Catalog **bulk** import doesn't persist the uploaded file (only the deal заявка
  importer now does) → store the catalog import source file too (source of truth).

## P2 — Contract automation

- Auto-transition Deal → CLOSED_WON when its contract becomes SIGNED (currently a
  separate manual step). Note: `CONTRACT_SIGNED` stage is set at КП **approval**,
  before any contract exists — rename to `QUOTE_APPROVED` and reserve
  `CONTRACT_SIGNED` for a real signed contract.

- E-signature is a simple electronic signature (ПЭП, rendered in the contract PDF
  with signer identity + timestamp). Real E-IMZO/qualified signature is a future
  integration (see P0).

## Storage note

Production runs on **local FileSystemStorage** on the VPS (no MinIO; the provider
guarantees backups — owner's choice). All private documents are downloaded through
authenticated streaming endpoints (`…/download-pdf/`, `…/download/`,
`…/download-document/{id}/`), which work with both local and S3 storage. If
durable, versioned object storage is ever required, point the existing `MINIO_*`
env at an external S3-compatible service (Cloudflare R2 / Backblaze B2 / AWS S3) —
the `core/storage.py` abstraction already supports `S3Boto3Storage`, no code
change.
