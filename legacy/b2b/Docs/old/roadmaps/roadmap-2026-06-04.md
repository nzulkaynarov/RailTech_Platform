# RailTech — Optimization & Mass-Upload Roadmap (2026-06-04)

Consolidated scope from the full project audit (5 axes) + the product decisions
taken on 2026-06-04. Goal: a system that is clear, friendly, comfortable, and
stable for every user type, ready for a curated launch with one seller, many
products across many brands, and many buyers.

Execution rule: **phase → branch → CI → merge**, one coherent unit at a time.
Backend schema changes follow **expand/contract** (add new structure first,
remove the old in a later phase once proven).

## Product decisions locked on 2026-06-04
- **Identity:** everyone self-registers as a **Buyer (CLIENT)**. Selling is a
  curated capability: a company requests it (`CompanyRoleApplication`) and an
  admin approves (already built: `accounts/services/applications.approve_role_application`),
  or the admin onboards a seller/manufacturer directly in Unfold. Adds the
  CompanyType to the company.
- **Roles are KEPT** (corrects the audit's "delete WorkspaceRoles"): they drive
  **role-tailored cabinets** (owner / sales / finance / logist see different
  navigation & dashboards). Add a **FINANCE** role. Trim the set to real
  functions per company type. Backend enforcement stays light at launch (one
  trusted seller), tighten later.
- **Catalog = true PIM:** one canonical `Product` card, many `SupplierOffer`s
  (one per supplier). Buyer sees brand + country + the list of suppliers/prices.
- **Manufacturer = a Brand entity**, NOT a platform account. A foreign brand
  (e.g. Siemens) is never a user; it is a `Manufacturer` reference (name +
  country, optional link to a platform Company for local producers). `Product`
  points to it. Dedup key for PIM = brand + `manufacturer_part_number`/GOST.
- **Stock availability** (in-stock / pre-order / …) lives on `SupplierOffer`
  (`StockStatus`), because availability is per-supplier. `Product.status` is the
  PIM lifecycle (draft / published / archived) — a separate axis.
- **Onboarding fields** (minimal): ФИО, company name, position (free-text
  title), email (confirmation), phone (UZ mask `+998 XX XXX XX XX`,
  `^\+998\d{9}$`). First user → company **OWNER** (role picker hidden).
  **INN is dropped from registration** and collected later at KYC / before
  contracting — this also removes the "INN already taken" dead-end.
- **Mass upload = an ADMIN operation in Unfold.** Per row: supplier (INN of an
  approved SUPPLIER/MFG) + brand (name → Manufacturer, auto-create/pick) +
  product (name/part_no/GOST/category/uom/domain) + offer (price/currency/
  stock_status/lead/MOQ). true-PIM dedup of Product, upsert of SupplierOffer.

## Phases

### Phase 0 — Catalog schema foundation  ⏰ *do first, while catalog is empty (zero migration risk)*
EXPAND only (additive, nothing removed):
- New `catalog.Manufacturer` (Brand): `name` (unique), `country` (FK
  master_data.Country, null), optional `website`/`logo`, optional `company`
  (FK accounts.Company, null — local producer link), `is_active`.
- `Product`: add `brand` FK → Manufacturer (null), add `manufacturer_part_number`
  (indexed). Keep the old `manufacturer` (Company) FK for now, marked deprecated.
- Register `Manufacturer` in Unfold; expose brand additively in the Product
  serializer (brand, brand_name, country).
- Confirm `StockStatus` values (В наличии / Предзаказ / Нет / Под заказ).
- (CONTRACT — later phase) remove `Product.manufacturer` (Company) once `brand`
  is wired through admin/import/frontend and verified.

### Phase 1 — Identity & onboarding simplification
- Registration = 5 fields; first user → OWNER; **INN deferred**; phone +998 mask.
- "Request to sell" UI in the cabinet → `CompanyRoleApplication` → admin approve.
- Team invite flow: OWNER invites (`invite_workspace_member`) + `/accept-invite?token=` handler.

### Phase 2 — Role-tailored cabinets
- Rationalize WorkspaceRole set per company type; add FINANCE.
- Navigation/dashboards driven by role (logist→fulfillment, finance→billing,
  sales→deals, owner→all). Light backend enforcement at launch.

### Phase 3 — Mass product upload via Unfold  🚀 (headline)
- Importer: supplier(INN) + brand + product + offer → true-PIM dedup + offer upsert.
- Downloadable template (exact headers + allowed codes).
- Dry-run preview + row-level error report (django-import-export confirm step).
- Performance: bulk + post_save signal guard for large batches.
- Images out of scope for bulk (after, or via URL).

### Phase 4 — Journey clarity & friendliness
- KYC transparency (confirm email, status card, toast → profile link, drop stale
  doc requirement). Empty states with hint+CTA across lists. Jargon tooltips.
  Platform-admin welcome/onboarding.

### Phase 5 — Business-logic clarity
- Structured error catalog `{code, message}` (replace 40+ ad-hoc strings); FE i18n.
- Move auth logic (invite / update-capabilities) into services (Rule 8).
- Deal FSM review (QUOTE_SENT → CONTRACT_SIGNED before a signed contract exists)
  — needs a product decision.

## Sequencing
Phase 0 (now) → Phase 3 (depends on 0 + ≥1 approved seller from Phase 1/Unfold).
Phase 1 ∥ Phase 2 ∥ Phase 4 after the spine works. Phase 5 = final polish.

Status is tracked per-PR; this doc is the single source for the initiative.
