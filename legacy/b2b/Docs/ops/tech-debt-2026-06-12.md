# Tech-Debt Register (2026-06-12)

Remaining work after a large cleanup/hardening pass (tender removed, nav/dashboard
slimmed, prod download fixes, source-of-truth import file). Prioritized for the
next sessions. Context: the platform is single-seller (RailTech) on the
Buyer ↔ Seller КП model; competitive supplier bidding was removed.

## P1 — UX consolidation (the remaining "каша")

- **Two seller КП workspaces.** The seller can work a КП via the new
  `pages/DealsPage.tsx` (`DealDetailSheet` → `QuoteBuilderGrid` + approval chain)
  AND via the legacy `pages/flow/RequestDetailPage.tsx` (no line-item editor, its
  own FSM through `store/flowStore`). Same deal, two surfaces, different
  capabilities. **Action:** pick one canonical deal-detail surface per role and
  retire `RequestDetailPage` (and the `flowStore` flow) once the buyer path is
  moved onto it.
- **Buyer КП decision in 3 places** (RequestDetailPage, DealsPage sheet,
  QuotesPage) → collapse to one canonical buyer surface. Nav is already trimmed.
- **Dual state systems**: `flowStore` (RequestDetailPage) vs React-Query
  (`hooks/useCRM`, everywhere else) for the same mutations → unify to avoid
  cache-drift.

## P1 — Proactive E2E verification

Drive the full Buyer ↔ Seller cycle in a running browser
(заявка → КП → approval chain → accept → contract → invoice → payment →
fulfillment → CLOSED_WON) and fix every dead-end before users hit it. Several
prod defects this period were found reactively (export-template 401, заявка-import
dead-end); a scripted end-to-end pass catches them first.

## P2 — Catalog single-product form (railway products broken)

- `components/Catalog`/`AdminCatalogPage.tsx` `ProductFormSheet`: the
  "Manufacturer" select lists `catalog.Manufacturer` (`brand`) options but writes
  to the **deprecated** `Product.manufacturer` (Company FK), so the canonical
  `brand` is never set. The form can't set `equipment_groups` or
  `manufacturer_part_number` → RAILWAY_MACHINERY products fail `full_clean()`
  (require ≥1 equipment group). Bulk Excel import is fine; only the single form
  is broken.
- `Product.manufacturer` (Company FK) is deprecated → migrate to `brand`
  (catalog.Manufacturer), swap the ~11 frontend readers, then drop the field.
- Catalog **bulk** import doesn't persist the uploaded file (only the deal заявка
  importer now does) → store the catalog import source file too (source of truth).

## P2 — Contract automation

- Auto-transition Deal → CLOSED_WON when its contract becomes SIGNED (currently a
  separate manual step). Note: `CONTRACT_SIGNED` stage is set at КП **approval**,
  before any contract exists — rename to `QUOTE_APPROVED` and reserve
  `CONTRACT_SIGNED` for a real signed contract.
- A Celery-beat job to remind/expire unsigned contracts (`Contract.valid_until`
  exists but is never enforced). Quotes already expire via beat; contracts don't.
- E-signature is a simple electronic signature (ПЭП, rendered in the contract PDF
  with signer identity + timestamp). Real E-IMZO/qualified signature is a future
  integration.

## P3 — Minor / cosmetic

- `system-settings/` returns 401 on fresh load (request fires before the JWT is
  attached) — non-blocking, React-Query retries; gate the query on auth.
- Dead i18n keys for the removed tender/Smart Match (`supplierBids`,
  `sourcingMatch`) and `SupplierBidStatus` in `lib/codes.ts` — harmless, sweep.
- `SourcingRequestsPage` overlaps with Deals; `ClientsPage` lists ALL companies
  unfiltered and mislabels `user_count` as "deals".
- Cart submit serializes requested items into free-text `deal.notes` (not
  structured QuoteItems), so the seller gets a wishlist, not importable lines.
  Open decision: where a заявка's items live structurally
  (cart = notes vs Excel = QuoteItems).

## Storage note

Production runs on **local FileSystemStorage** on the VPS (no MinIO; the provider
guarantees backups — owner's choice). All private documents are downloaded through
authenticated streaming endpoints (`…/download-pdf/`, `…/download/`,
`…/download-document/{id}/`), which work with both local and S3 storage. If
durable, versioned object storage is ever required, point the existing `MINIO_*`
env at an external S3-compatible service (Cloudflare R2 / Backblaze B2 / AWS S3) —
the `core/storage.py` abstraction already supports `S3Boto3Storage`, no code
change.
