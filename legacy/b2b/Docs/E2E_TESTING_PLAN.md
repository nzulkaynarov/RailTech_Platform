# План сквозного тестирования (E2E & Integration)

Этот документ предназначен для Junior-тестировщика или разработчика для проверки целостности RailTech B2B Ecosystem после интеграции.

---

## 1. Инструментарий
- **Backend Integration:** `pytest` + `pytest-django`
- **Frontend E2E:** `Playwright` (рекомендуется) или `Cypress`
- **API Testing:** `Postman` или `Insomnia`

---

## 2. Критические сценарии (Чек-лист)

### 🔑 Блок А: Авторизация и Роли (RBAC)
- [ ] **A.1**: Вход под `ADMIN@railtech.uz`. Проверка доступа к `/admin`.
- [ ] **A.2**: Вход под `CLIENT`. Проверка, что в каталоге цены скрыты до авторизации.
- [ ] **A.3**: Попытка доступа Клиента в CRM (/crm/*). Должен быть редирект или 403.
- [ ] **A.4**: Обновление токена (Refresh Token) после 30 минут жизни Access токена.

### 📦 Блок Б: Каталог и Справочники
- [ ] **Б.1**: Загрузка динамических справочников (`/api/v1/master-data/currencies/`). Проверка, что фронтенд отображает актуальные валюты в селекторах.
- [ ] **Б.2**: Фильтрация каталога по доменам (`RAILWAY_MACHINERY`). Проверка, что отображаются только товары этого типа.
- [ ] **Б.3**: Поиск товара по частичному совпадению SKU или имени (Trigram Similarity).

### 📑 Блок В: CRM и расчеты (Landed Cost)
- [ ] **В.1**: **Smart Match**: Загрузка Excel файла в Сделку. Проверка, что Celery-задача завершается успешно.
- [ ] **В.2**: Проверка в Sourcing Hub: нераспознанные товары должны иметь статус `product = null`.
- [ ] **В.3**: **Расчет Quote**: Редактирование `DealItem` (изменение Logistics или Margin). Проверка, что `total_price` пересчитывается мгновенно (frontend) и корректно сохраняется в БД (backend).
- [ ] **В.4**: Экспорт PDF: Успешная генерация файла КП (Commercial Offer) с правильными расчетами.

### 💬 Блок Г: Real-time Интеграция
- [ ] **Г.1**: WebSocket соединение: Открытие чата в Сделке. Проверка появления статус-кода `101 Switching Protocols` в Network tab.
- [ ] **Г.2**: Отправка сообщения Менеджером $\rightarrow$ получение Клиентом без перезагрузки.
- [ ] **Г.3**: Центр уведомлений: Появление "красной точки" при изменении статуса Сделки.

---

## 3. Инструкция по запуску тестов

### Backend
```bash
docker-compose exec backend pytest
```

### Frontend (если установлен Playwright)
```bash
cd frontend
npx playwright test
```
