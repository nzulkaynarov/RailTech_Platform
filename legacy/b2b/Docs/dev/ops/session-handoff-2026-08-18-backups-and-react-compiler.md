## 2. Главное, что стоит унести с собой

**Бэкап, существование которого нельзя проверить снаружи, бэкапом не является.** До сегодняшнего дня «OK» в логе означал лишь «`pg_dump` завершился». Битый дамп выглядел бы так же, а если бы cron перестал запускаться — сигнала не было бы вовсе. Теперь дамп ЧИТАЕТСЯ `pg_restore`, статус машиночитаемый, и спрашивает его **соседняя машина**: свой скрипт не может пожаловаться, что его самого перестали запускать. Две ловушки поймал прогон ломаным входом — `pg_restore` надо звать от root (дамп `root:600`), а Sentry через `manage.py shell` (у голого `python` нет клиента: событие уходит в никуда при коде выхода 0).

**Правила React Compiler — детектор багов, а не стиль.** `set-state-in-effect`: 45 мест (план обещал 26 — точный список даёт только ВКЛЮЧЁННОЕ правило). 31 переписан: формы из `useQuery.data` и сброс диалогов → `useDraftState`; «подставить единственное значение», «сбросить выбор при смене выборки», «показать ошибку кривой ссылки» оказались ВЫЧИСЛЕНИЯМИ. Оставшиеся 14 — настоящие эффекты, у каждого точечный `eslint-disable-next-line … -- причина` **в самом файле**.

**Прогон глазами снова окупился дважды.** Нашлись два ЖИВЫХ дефекта, невидимых тестам и API:
- экран «Нумерация документов» встречал красным `ERR_BAD_REQUEST` (превью просилось с отложенным ключом — пустой маской);
- в билдере КП **«Отменить» не делала ничего видимого**. Виновата не отмена: фокус наполняет буфер ячейки текущим значением, и уход фокуса писал его обратно НЕИЗМЕНЁННЫМ — строка становилась «грязной» без исправлений, а в стек отмены падал фантомный шаг, который и откатывался. Тот же гард уже существовал в соседней ветке той же функции (для нуллируемых ячеек) — просто не был доведён до обычной.

**И одна своя регрессия, пойманная тем же прогоном:** предвыбор продавцов стал вычислением, а переключатель считал от пустого «своего» списка — снятие галочки с подсказанного продавца оставило бы выбранным только его. Урок: заменил состояние вычислением — проверь ВСЕ сеттеры.

## 3. Грабли инструментов (сэкономят час)

- **Прод-сборка вырезает `console.*`** (`esbuild.drop` в `vite.config.ts`), а фронт в Docker — прод-сборка. Отладочный вывод в браузере класть в `window.__dbg`. Я потратил на это заход, успев заподозрить кеш Docker и перезапустить Docker Desktop.
- **Жёсткий `pkill` Docker Desktop повредил AOF локального `redis-celery`** (`Bad file format reading the append only file`). Лечение: `docker compose rm -f redis-celery && docker volume rm railtech_saas_b2b_redis_celery_data && docker compose up -d`. Данные брокера одноразовые.
- **Тест «первого кадра» мерит ЗАКОММИЧЕННЫЕ кадры**, а не вызовы функции-компонента: при корректировке состояния в рендере тело один раз выполняется со старым значением, но React его не коммитит. Иначе тест падает на честном коде.
- `Array.prototype.at` недоступен в целевой библиотеке сборки — `tsc -b` падает, хотя vitest проходит.
