## 3. graphify — граф знаний репозитория

Установлен на второй машине. **Пакет на PyPI называется `graphifyy` (две «y»), CLI — `graphify`.**
Версия 0.9.29.

```bash
uv tool install graphifyy
graphify install      # скилл /graphify в ~/.claude/skills/graphify/
graphify update .     # сборка/обновление → graphify-out/
```

Ставит `graphify` и `graphify-mcp` в `~/.local/bin`; попутно создаёт короткий `~/.claude/CLAUDE.md`
(3 строки про триггер `/graphify`).

### Почему платный кэш переносится между машинами

Семантический (LLM) проход по документам стоит денег; результат лежит в
`graphify-out/cache/semantic/p{fingerprint}/` и **закоммичен** (сейчас 226 файлов, 1.5 МБ).
Остальное в `graphify-out/` игнорируется — AST-проход пересобирается бесплатно.

`p{fingerprint}` — это sha256 **текста промпта экстракции**
(`~/.claude/skills/graphify/references/extraction-spec.md`), а НЕ путь и НЕ машина; переводы строк
нормализуются, чтобы CRLF-чекаут не выставлял счёт заново. Имя файла внутри — хеш содержимого
исходника. Отсюда переносимость.

**Проверка ДО того, как платить заново:**

```bash
python -c "
from pathlib import Path
from graphify.cache import prompt_fingerprint
print(prompt_fingerprint(Path.home()/'.claude/skills/graphify/references/extraction-spec.md'))"
# должно совпасть с именем каталога в graphify-out/cache/semantic/ (сейчас d5fd89c46bb5)
```

Проверено 2026-07-29: отпечаток совпал, **150 из 166 файлов первой волны попали в кэш** без
повторной оплаты. Догоняющая экстракция 27 новых файлов (хендофф R3, спеки #422/#427, PDF-шаблоны,
письма) стоила **208 017 токенов** и закоммичена в #440 — иначе на следующей машине пришлось бы
платить снова.

Если отпечаток НЕ совпал — версия graphify изменила промпт: кэш будет промахнут, корпус
переэкстрагируется за деньги. Тогда не запускать семантический проход, а сначала поставить ту же
версию.

Граф на 2026-07-29: **11 361 узел, 21 675 связей, 883 сообщества**, 30 МБ в `graphify-out/`.

## 4. Рефактор: «кто такой продавец» — одно определение (#439)

**Родился из трассировки графа** (`Surprising Connections` → вьюхи `crm`/`catalog` завязаны на
`accounts/constants.py`). Связей оказалось три, здоровье разное:

| Связь | Мест | Диагноз |
|---|---|---|
| `FeatureKey` | 9 | Здорова — задуманный контракт ADR-0006 (константа=словарь, логика в `entitlements`). Не трогал. |
| `Permission` / роли | 7 | В основном здорова. Один дубль предиката — см. ниже. |
| **«это продавец»** | **23** | Проблема: сервиса нет, каждый инлайнит ORM-фильтр. |

23 места, 13 файлов, 6 приложений. У `Company` не было кастомного менеджера — понятию негде было
жить. **Это не стилистика:** ровно этот класс дефекта чинился в #436 и был на проде (пикер считал
приглашаемым «SUPPLIER + KYC», подсказка R1 — просто «SUPPLIER»; расхождение → непроверенная
компания в предвыборе без видимой строки).

Паттерн — **published language / anti-corruption boundary** (DDD), в терминах Django его родная
идиома: **кастомный manager + queryset как публичный API приложения**.

### Новый API (единственный дом — `accounts/models/company.py`)

```python
Company.objects.sellers()                  # компании-продавцы
Company.objects.verified_sellers()         # продавец + пройденный KYC = «кого можно пригласить»
CompanyMember.objects.in_seller_company()  # работает и через user.memberships.…
seller_company_q(prefix)                   # фильтр по связи: owner_company__, company__
verified_seller_company_q(prefix)
```

`KYC_VERIFIED_CODES` переехал из `accounts/services/kyc.py` в `accounts/constants.py` — модель не
может импортировать сервис без цикла. Историчный путь импорта сохранён ре-экспортом.

**Побочно:** `crm/services/quotes/lifecycle.py` больше не пересобирает предикат платформенного
админа руками. Замена на `is_platform_admin` **СТРОЖЕ на одну деталь** — дополнительно требует
отсутствия активных членств. Это инвариант ADR-0003, который миграция `accounts/0010` обеспечивает
на данных: на реальных пользователях результат тот же, а расхождение теперь закрывается отказом,
а не тихим допуском. Если это нежелательно — откат в одну строку.

Миграции НЕ нужны: менеджеры не сериализуются в состояние (`use_in_migrations` по умолчанию False).

### Guard-тесты (`accounts/tests/test_seller_predicate_single_source.py`, 5 шт.)

- **Сканер исходников** падает, если предикат снова продублировали инлайном, и говорит, чем
  пользоваться вместо. Проверен зондом — падает по делу.
- **AST-проверка**, что `verified_seller_company_q` СОБРАН из `seller_company_q` — нельзя поменять
  половину и забыть вторую.
- Поведенческие: непроверенный продавец не приглашаем, L3-контрактный — приглашаем; Q-фабрика с
  префиксом и queryset отбирают одно множество.

### Грабли этого рефактора (переиспользуемые)

- **Тесты мокали ФОРМУ ORM-цепочки.** `user.memberships.filter.return_value.exists.return_value`:
  вставка вызова между `filter()` и `exists()` ломала мок, и `is_seller` начинал возвращать истину.
  Правильный фикс — `MagicMock(spec=[...])`, как уже сделано в соседнем тесте, а не доращивание
  мока новой формой.
- **`SELLER_COMPANY_TYPES` ре-экспортировался из `accounts.services.permissions`** — grep по
  `from accounts.constants import` этого НЕ ловит. Всегда проверять ре-экспорты, иначе ImportError
  вылезет только в рантайме (поймали тесты).
- **Сравнивать «грязное до меня» по линтерам надо С КОНФИГОМ репо.** Во временном каталоге без
  `pyproject.toml` black берёт длину строки 88 вместо 120 и краснеет почти везде — легко принять
  чужой долг за свой.

**CI репозитория мёртв, это не связано с этими PR.** Workflow **CI** падает и на `main`; джобы
завершаются за 2–12 с с нулём шагов и нулём логов, включая тривиальную `i18n-symmetry`. Workflow
**Deploy** при этом зелёный — он на self-hosted раннере, а CI на `ubuntu-latest` (GitHub-hosted).
То есть GitHub-hosted раннеры не выдаются: квота/биллинг. **Чинится только владельцем в настройках
биллинга GitHub.** До починки — гонять гейты локально и писать результат в PR.

Линтеров нет ни в образе backend, ни на хосте, и у контейнера нет сети → ставить в отдельный venv
на хосте. Версии под CI: `black==24.10.0`, `isort==5.13.2`, flake8 7.x. Запускать **из корня репо**
(`flake8 backend/`) — там лежат `.flake8` и `pyproject.toml`.

Замечание: `black --check backend/` красный на ~40 файлах и без наших правок (предсуществующий
долг, в т.ч. `crm/views/deals.py:547` и `crm/services/quotes/lifecycle.py:226`). Намеренно не
трогали, чтобы не тащить в PR посторонний шум.
