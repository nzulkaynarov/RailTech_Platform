## 5. Грабли, которые стоили времени

- **Проверять КОД ВОЗВРАТА, а не хвост вывода.** `isort --check-only | tail -1` показал
  «Skipped 194 files» — информационную строку ПОСЛЕ `ERROR:`. Гейт на main был красным,
  и нашёл это чужой агент, а не я.
- **Типы проверяет только `npm run build`.** `tsc --noEmit` вернул 0 там, где сборка нашла
  11 ошибок: разные tsconfig.
- **vitest изредка даёт exit=1 при 779/779 passed** — шумовые `AggregateError` от jsdom-XHR.
  Перезапустить, прежде чем чинить несуществующее.
- **Celery не перечитывает код** — импорт исполняет воркер, `docker compose restart
  celery-worker` обязателен, иначе видно старое поведение.
- **Два параллельных pytest дерутся за тестовую БД** и дают сотни ложных ошибок.
- **Squash базовой ветки закрывает дочерний PR**, а не ретаргетит: `gh pr edit --base main`
  падает, переоткрыть нельзя. Порядок: смержить базовый → `git rebase --onto origin/main
  <старый-tip> <ветка>` → force-push → создать новый PR.
- **Ключи `notification.*` в локалях плоские с точкой** (`'act.issued'`), а `activity.*` —
  вложенные. Перепутать легко, ловит guard-тест покрытия событий.

## 6. Главный вывод про параллельных агентов

Схема, которая работает: общие слои (клиент API, хуки, `lib/`, локали) держать **за собой**,
агенту давать один файл или модуль, ключи i18n он возвращает таблицей, а не правит словари.

**Но баги живут на СТЫКЕ агентов, а не внутри.** У каждого свои гейты зелёные, и каждый прав
про себя, — а контракт между ними разъезжается. Поймано трижды: поле `base_price_currency`
не отдавалось детальным сериализатором (цена на карточке не отрисовалась бы никогда);
код с параметром против кода без; бейдж, который считает одно и подписан другим.
**После фан-аута ручное ревью стыков обязательно.**
