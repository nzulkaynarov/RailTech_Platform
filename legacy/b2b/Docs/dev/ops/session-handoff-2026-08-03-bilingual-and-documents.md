## 2. Две ловушки gettext (обе поймались ГЛАЗАМИ, не тестами)

1. **msgid обязан быть на исходном языке проекта (`ru`).** `locale/ru` не существует, поэтому
   Django печатает msgid как есть — английские msgid напечатались по-английски в РУССКОМ
   документе («Act No. … / dated … / Page 1 of 1»).
2. **gettext пишет флаги списком: `#, fuzzy, python-format`.** Проверка на точное совпадение
   строки `#, fuzzy` их не видит — восемь номеров и дат документов молча остались
   непереведёнными при внешне полном каталоге. Честная проверка — `msgfmt --check
   --statistics`, она прямо печатает «N fuzzy translations».

**Рецепт сборки каталога** (после любой правки шаблонов):
```bash
docker compose exec -T backend sh -c "cd /app && python manage.py makemessages -l en --no-obsolete --no-wrap"
docker compose cp backend:/app/locale/en/LC_MESSAGES/django.po backend/locale/en/LC_MESSAGES/django.po
# перевести новые записи ПОСТРОЧНЫМ парсером (регексп на .po разъезжается на многострочных),
# снять fuzzy-флаги СПИСКОМ, а не сравнением строки целиком
docker compose exec -T backend sh -c "cd /app && msgfmt --check --statistics -o locale/en/LC_MESSAGES/django.mo locale/en/LC_MESSAGES/django.po"
```

## 3. CI ожил — и вскрыл три накопленных долга (починены в #521)

CI молчал с 07-31, поэтому долги копились незамеченными. Первый живой прогон показал:

| Что | Почему | Как починено |
|---|---|---|
| Все python-джобы падали на `pip install` | матрица пинила Python 3.11, а Django 6.0 требует ≥3.12 (образ давно 3.12) | матрица → 3.12; в CLAUDE.md поправлен «target Python» |
| `flake8` F403/F405 в `core/settings/` | расщеплённые настройки собираются звёздочными импортами — идиома Django | `per-file-ignores` точечно на пакет настроек |
| Дрейф `black`/`isort` в трёх файлах | правки прилетали, пока гейт молчал | переформатировано |

**Урок:** локальные гейты надо гонять В ТОМ ЖЕ виде и ТОЙ ЖЕ версией, что и CI — из корня по
всему `backend/`, а не по изменённым файлам. Отдельная грабля: CI ставит `isort>=5,<6`, а
`uvx isort` тянет 6.x, и версии расходятся (пятая при `profile=black`/`line_length=120`
схлопывает импорт в одну строку, шестая оставляет скобочную форму). Рабочая тройка:

```bash
uvx flake8 backend/
uvx black --check backend/
uvx --from "isort>=5,<6" isort --check-only backend/
```

## 4. DoD глазами (PRODUCT RULE 4)

Все пять закрывающих документов отрендерены в обоих языках и просмотрены: акт, счёт,
договор, квитанция, накладная. RU — чистый; EN — каркас английский, пропись английская,
позиции/статьи/названия компаний русские.

**Три дефекта нашёл только глазами, тесты молчали:**
1. английские msgid в русском акте (ловушка 1);
2. восемь fuzzy-записей (ловушка 2);
3. `act_pdf.html` остался неразмеченным целиком — он не рендерился в проверке, потому что
   `company_template_for` уходит в платформенный образец (templated-ветка).

**Артефакт границы, о котором стоит знать:** в английском договоре §10 «Details and
signatures of the Parties» переведён (реквизиты сторон = каркас), а §1–§9 нет (юридический
текст). Это линия Stripe/DocuSign, а не недоделка; хочет ли владелец иначе — отдельное решение.
