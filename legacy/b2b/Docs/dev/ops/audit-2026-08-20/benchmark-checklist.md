# Чек-лист прогона операторской поверхности на боевом стенде

**Продукт:** RailTech B2B SaaS — плоскость Platform Operator (React `PlatformAdminShell`) + инженерная админка (Django Unfold).
**Назначение:** пройти глазами всю операторскую поверхность на проде, сверяя её с именованными паттернами эталонов (Odoo 18, Salesforce Setup, Stripe/QuickBooks), и зафиксировать расхождения — без разрушения данных реальных арендаторов.
**Формат:** исполняется одним человеком, последовательно, со скриншотом на каждую находку. Ожидаемое время полного прогона — 6–8 часов; разбивается по блокам R0 / R1 / R2.

## 0. Как пользоваться документом

### 0.1 Флаги безопасности

| Флаг | Значение | Правило |
|---|---|---|
| 🟢 | Только чтение / локальное состояние / GET | Выполнять на любых данных |
| 🟠 | Пишет в БД, но обратимо и по объекту-стенду | Выполнять **только** на объектах песочницы из §0.3 |
| 🔴 | **ЗАПРЕЩЕНО НА ПРОДЕ** — необратимо меняет чужого арендатора или всю платформу | Заменить протоколом **[Д-О-О]** (§0.2) |

### 0.2 Протокол [Д-О-О] — «Диалог → Осмотр → Отмена»

Безопасная замена для любого 🔴-пункта. Проверяет ровно то, ради чего пункт написан: что действие **предупреждает о последствии и не срабатывает до подтверждения**.

1. Открыть DevTools → вкладка **Network**, фильтр `Fetch/XHR`, нажать 🚫 (Clear). Записать: запросов = 0.
2. Нажать целевое действие (кнопка/пункт меню).
3. **Осмотр диалога — 5 признаков:**
   - a) текст называет **конкретный объект** (имя компании / e-mail / номер документа), а не «эту запись»;
   - b) текст называет **последствие** («потеряет доступ к платным функциям», «карточка станет видна всем»), а не «вы уверены?»;
   - c) кнопка подтверждения **повторяет глагол действия** («Приостановить», «Отозвать»), а не «ОК»/«Да»;
   - d) если действие необратимо — это **написано** в диалоге, и назван обратимый путь для соседней задачи (если он есть);
   - e) если требуется причина — поле обязательное, есть шаблоны причин.
4. Проверить Network: **запросов по-прежнему 0**. Если запрос ушёл до подтверждения — это дефект уровня BLOCKER, прогон по этому экрану остановить и зафиксировать.
5. Нажать **Отмена/Esc**. Проверить Network: запросов 0. Скриншот диалога приложить к отчёту.

Эталон, который проверяет [Д-О-О]: **O-CONFIRM-VERB**, **ST-CANCEL-TWO-DECISIONS**, **ST-CHANGE-STATUS**.

### 0.3 Подготовка стенда (обязательно, до начала)

**Аккаунты** (без всех пяти половина проверок невыполнима):

| Код | Кто | Зачем |
|---|---|---|
| **A-SU** | Django-суперпользователь | Инженерная админка целиком |
| **A-ENG** | Пользователь в группе `system_engineers`, **`is_superuser=False`** | Проверка `ReadOnlyInspectionMixin` и гейтов import/export. Без него дыры R0 не видны |
| **A-OP-FULL** | Оператор `SystemRole=ADMIN` + `OperatorRole` со всеми правами | Полная операторская плоскость |
| **A-OP-THIN** | Оператор `SystemRole=ADMIN` + `OperatorRole` **без** `billing.view`, `moderation.role_applications`, `moderation.force_override`, `platform.settings`, `operators.manage` | Проверка U10 (скрытие, а не блокировка) |
| **A-TENANT** | Обычный пользователь компании-песочницы | Проверка отзыва доступа и «второй стороны» |

**Песочница** (создать заранее, до прогона):
- компания `__СТЕНД-QA` (ИНН из явно нерабочего диапазона, в названии префикс `__СТЕНД`), тип CLIENT+SUPPLIER;
- второй арендатор `__СТЕНД-QA-2` — для проверки слияния дублей;
- в `__СТЕНД-QA`: 2 пользователя, 1 подписка, 1 сделка с КП, 1 договор, 1 счёт, 1 товар с оффером, 1 KYC-документ;
- заявка на роль в статусе «в работе».

**Baseline-замер** (записать ДО прогона — понадобится для U6 и для отката):
общее число строк в `#admin-users`, `#admin-companies`, `#admin-kyc` по каждой вкладке, `#admin-subscriptions`, `#admin-entitlements`, `#admin-deals`.

**Правила гигиены прода:**
- никаких записей по объектам **реальных** арендаторов — только [Д-О-О];
- выгруженные файлы экспорта с реальными данными **не сохранять на личную машину**; если файл скачался — удалить и зафиксировать факт в отчёте (это банковские реквизиты и прайс-листы третьих лиц);
- каждое выполненное 🟠-действие записывать в лог прогона (объект, время) — это ваш след для сверки с `#admin-access-log` в §25.

# БЛОК R0 — платформенный масштаб
> Ошибка здесь ломает **всех арендаторов сразу** или раздаёт права платформы. Проходить первым, максимально осторожно, только под наблюдением.

## §1. Дверь инженерной админки — `/admin/login/` 🟢

**Открыть:** `https://b2b.railtech.uz/admin/login/`
**Эталон:** `O-DEVMODE`, `O-SUPERUSER`, `O-HIDE-NOT-DISABLE`

| # | Действие | Ожидаемо | Флаг |
|---|---|---|---|
| 1.1 | Войти под **A-TENANT** (обычный пользователь арендатора) | Вход **отклонён**. Не «пустая админка», а отказ. Проверить, что не помогает `is_staff` | 🟢 |
| 1.2 | Войти под **A-OP-FULL** (оператор платформы, не инженер) | Вход отклонён — операторская плоскость ≠ инженерная (ADR-0001) | 🟢 |
| 1.3 | Войти под **A-ENG** | Вход разрешён; в сайдбаре видны 9 секций | 🟢 |

| 1.6 | **Гэп-проверка `SF-LOGIN-HISTORY`:** найти в админке экран истории входов (время, IP, исход) | Зафиксировать наличие/отсутствие. При отсутствии — это gap, не дефект | 🟢 |

## §2. Пользователи в Unfold — `/admin/accounts/customuser/` 🔴

**Почему первым:** это единственный экран, где **не-суперпользователь может выдать себе суперправа** мимо сервисов и аудита; плюс импорт XLSX способен массово деактивировать аккаунты.
**Эталон:** `SF-NO-DELETE`, `O-STEPUP`, `O-PERM-LEVEL`, `O-EXPORT`, `ST-INVITE`

| # | Действие | Ожидаемо | Флаг |
|---|---|---|---|
| 2.1 | Под **A-ENG** открыть форму любого пользователя → вкладка **«Доступ»** | **Ключевая проверка.** Видны ли и **редактируемы** ли `is_active / is_staff / is_superuser / role / groups / user_permissions`? Если редактируемы под не-суперпользователем — дефект уровня BLOCKER (эскалация прав без аудита) | 🟢 (только осмотр, **НЕ сохранять**) |

```
Серьёзность:  BLOCKER / MAJOR / MINOR / GAP (расхождение с эталоном, не дефект)
Воспроизводимость: 3/3
Происхождение: регрессия (работало до PR #NNN) / НИКОГДА НЕ РАБОТАЛО / новая функция
               → как проверял: git log по файлу, наличие теста, поведение на предыдущем релизе
Тестами не ловится, потому что: <например «тест проверяет, что шлёт сервер, а не что видит человек»>
Скриншот:     runs/2026-08-XX/F-NN-*.png
Данные задеты: нет / да (объект: __СТЕНД-QA, откачено в HH:MM)
```

**Приоритизация для владельца:**
1. BLOCKER — необратимая запись без подтверждения; утечка чужих данных; действие без следа в аудите; сокрытие без серверной проверки.
2. MAJOR — обход обязательной причины вторым путём; мёртвый функционал (кнопка недостижима); несогласованность двух экранов над одним объектом.
3. MINOR — сырые ключи, вылет таблицы, счётчик не сходится, пустое состояние во время загрузки.
4. GAP — эталонного паттерна нет вовсе (строки таблицы §3): не дефект, вход в продуктовое планирование.
