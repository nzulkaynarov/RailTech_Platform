# Спека: флоу ТН ВЭД — поиск, ввод, хранение, редактирование. Экосистема без тупиков

Основание: запрос владельца 04-08 — «не должно быть тупиков и сложного пути; всё синхронно с
номенклатурой; при необходимости справочник отдельно для обычного поиска и для поиска с ИИ;
в приоритете рекомендации бенчмарка». Статус: **НА УТВЕРЖДЕНИЕ**, код не начат.

---

## 1. Фактическое состояние (проверено в коде)

### 1.1 Найден действующий ТУПИК

Очередь номенклатуры честно говорит «не хватает: Код ТН ВЭД» и ведёт кнопкой «Дополнить» на
карточку товара. **В форме карточки поля «Код ТН ВЭД» нет вовсе** (поля формы: name, brand,
category, description, domain_type, gost_drawing, MPN, status, uom — всё). В `ProductDetail`
кода тоже нет. То есть система требует то, что негде ввести.

### 1.2 Где код живёт и откуда берётся

| Точка | Состояние |
|---|---|
| `Product.hs_code` | хранится, участвует в полноте, но НЕ редактируется из UI |
| Строка КП (`GridRow`) | единственное место ввода — свободный текст с тултипом «хранится в карточке товара» |
| Строка КП → карточка | работает (волна A): код с отправкой КП уезжает в кандидата |
| Карточка → строка КП | работает: при привязке товара код наследуется и замораживается |
| AI-обогащение | модель выбирает код из retrieval-кандидатов, выбор сверяется со списком |
| `hs-suggest` endpoint | есть (пословный поиск + точный по цифрам), UI-потребителя нет |
| `is_known_code` | написана, к сохранению НЕ подключена — опечатка сохранится молча |
| Справочник (13 148 кодов) | загружен локально, автосинк недельный; на проде пуст до первого синка |
| Просмотр справочника | НЕТ ни у одной роли; Unfold-админки для HSCode тоже нет |

### 1.3 Синхронность, которой не хватает

Автосинк умеет ЗАКРЫВАТЬ коды, выведенные из редакции (`valid_until`). Но карточка с закрытым
кодом сегодня об этом не узнает никогда — она продолжит наследовать мёртвый код в новые КП.

## 2. Бенчмарк

### 2.1 Ввод кода в карточке товара

| Эталон | Механика |
|---|---|
| **Shopify** (Markets / duties) | Поле «HS code» в карточке товара — **автокомплит по справочнику**: печатаешь слово или цифры → выпадают коды с названиями; выбор фиксирует код. Не отдельная страница — поле прямо в форме. |
| **Odoo** (delivery/customs) | `hs_code` на product.template — поле с подсказкой из справочника; заполняется один раз, документы наследуют. |
| **Zonos, Easyship** | Комбинированный ввод: текст ИЛИ префикс кода, живые кандидаты с иерархией. |

**Вывод:** мировой стандарт — НЕ «перейди в справочник и найди», а **поле-автокомплит в месте
работы**. Справочник отдельно — вторичный инструмент.

### 2.2 AI-классификация

| Эталон | Механика |
|---|---|
| **Avalara Item Classification** | Описание товара → код с **confidence**; низкая уверенность → очередь ревью человеком. Массовая классификация каталога пакетом. |
| **Zonos Classify** | То же: AI предлагает, показывает уверенность, человек подтверждает. Код никогда не применяется молча. |
| **Amazon** | Классифицирует сам, но по жалобам пересматривает — модерация постфактум. |

**Вывод:** наш паттерн «retrieval → выбор → сверка» соответствует эталону. Не хватает
**подтверждения человеком в UI** (сейчас код из ИИ применяется в форме без отдельного акцента)
и **пакетной классификации** (у нас уже запланирована как «пакетное обогащение»).

### 2.3 Хранение и редакции номенклатуры

| Эталон | Механика |
|---|---|
| **SAP GTS** | Код — мастер-данные товара; при смене редакции номенклатуры (ежегодной) запускается **переклассификация**: товары с устаревшими кодами попадают в worklist. Хранится источник присвоения (кто/что). |
| **Avalara** | Классификации версионируются; при изменении tariff schedule клиента уведомляют. |

**Вывод:** закрытие кода автосинком должно **порождать работу**, а не тихо устаревать карточку.
У нас уже есть готовое место — очередь «Требуют внимания» в Номенклатуре.

### 2.4 Справочник как самостоятельный инструмент

| Эталон | Механика |
|---|---|
| **WCO Trade Tools, tarif.customs.uz, ЕЭК** | Дерево 2→4→6→10 с текстовым поиском; браузинг для случаев «не знаю, как это называется у таможни». |

**Вывод:** отдельная страница справочника нужна, но как **вторичный** инструмент (первичный —
автокомплит в поле). Владелец просил «обычный поиск и поиск с ИИ» — обе модальности уместны
именно здесь.

## 3. Целевой флоу (экосистема)

### 3.1 Карта: один источник правды, четыре точки касания

```
                    ┌──────────────────────────────┐
                    │  Справочник ТН ВЭД (13 148)  │  ← автосинк с ГТК (недельный)
                    │  master_data.HSCode          │
                    └──────┬───────────┬───────────┘
              retrieval    │           │   браузинг/поиск/ИИ
         ┌─────────────────┤           └───────────────────┐
         ▼                 ▼                               ▼
  ┌────────────┐    ┌─────────────┐              ┌──────────────────┐
  │ Поле-авто- │    │ AI-обогаще- │              │ Страница «Спра-  │
  │ комплит в  │    │ ние карточки│              │ вочник ТН ВЭД»   │
  │ карточке И │    │ (выбор из   │              │ (дерево + поиск  │
  │ строке КП  │    │ кандидатов) │              │ + вопрос ИИ)     │
  └─────┬──────┘    └──────┬──────┘              └────────┬─────────┘
        │                  │                              │ «применить к товару»
        ▼                  ▼                              ▼
  ┌─────────────────────────────────────────────────────────────────┐
  │                Product.hs_code — ДОМ кода                       │
  │   строка КП наследует и замораживает; отправка КП пополняет     │
  │   кандидата; закрытие кода автосинком → задача в очереди        │
  └─────────────────────────────────────────────────────────────────┘
```

### 3.2 T1 — поле-автокомплит (закрывает тупик; паттерн Shopify)

Один переиспользуемый компонент `HSCodeField` в ДВУХ местах: форма карточки товара (поля
сейчас нет вовсе!) и строка КП (сейчас свободный текст).

* печатаешь ТЕКСТ («подшип…») → живые кандидаты из `hs-suggest`: код + собственное имя
  позиции + серым полный путь;
* печатаешь ЦИФРЫ («8482…») → ветка кодов с иерархией;
* выбор фиксирует код; свободный ввод ОСТАЁТСЯ возможным (PRODUCT RULE 2 — не блокируем:
  справочник на проде может быть пуст, а код — известен продавцу заранее);
* мягкая валидация на месте: неизвестный код → жёлтая пометка «нет в справочнике», закрытый →
  «выведен из редакции». Предупреждение, не блок.

### 3.3 T2 — синхронность с номенклатурой (паттерн SAP-переклассификации)

* Автосинк закрыл код → карточки с этим кодом получают запись в очереди «Требуют внимания»:
  «Код 8607 19 100 0 выведен из редакции — подберите актуальный». Это ЕДИНСТВЕННОЕ новое
  «требование», и оно рождено внешним событием, а не нами.
* Замороженные `QuoteItem.hs_code` в отправленных КП НЕ трогаются (правило E3 — выпущенный
  документ неизменен).
* Правка кода в карточке действует на НОВЫЕ КП; история присвоения — в ActivityLog
  (`product.hs_code_changed`: кто, откуда — вручную / ИИ / из строки КП / из справочника).

### 3.4 T3 — страница «Справочник ТН ВЭД» (обе модальности поиска)

Пункт в разделе «Номенклатура» (продавец) и в плоскости оператора:

* **Обычный поиск**: строка поиска (текст/цифры) + дерево 2→4→6→10, разворачиваемое по
  уровням; у листа виден путь, единицы учёта, статус редакции;
* **Поиск с ИИ**: поле «опишите товар своими словами» → тот же retrieval → модель выбирает и
  ОБЪЯСНЯЕТ выбор одной фразой; уверенность показывается; «применить к товару…» открывает
  выбор своей карточки (или создание);
* read-only для данных: править классификатор нельзя никому — он приходит из ГТК;
* Unfold-админка HSCode для инженера — read-only инспекция (ADR-0001).

### 3.5 T4 — пакетная классификация (Avalara bulk; закрывает и остаток волны D)

В очереди номенклатуры: выделить карточки без кода → «Подобрать коды с ИИ» → фоновая задача
(очередь `ai`, ARCH-01) → результат в карточках с пометкой «предложено ИИ, подтвердите»;
подтверждение — одним кликом по строке или пакетно. Код НИКОГДА не применяется молча
(Avalara/Zonos: человек подтверждает).

## 4. Что сознательно НЕ делаем

* **Не блокируем сохранение по валидации кода** — предупреждение, не гейт (PRODUCT RULE 2).
* **Не храним и не показываем ставки пошлин** — уже решено в волне D: читалось бы как
  таможенная консультация.
* **Не даём ИИ применять код без человека** — только предложение с подтверждением (Avalara).
* **Не редактируем классификатор из UI** — источник один, ГТК; локальные правки разошлись бы
  с редакцией при первом же синке.
* **Не делаем страну-зависимую классификацию** — платформа РУз-центрична, номенклатура одна.

| Волна | Что | Закрывает |
|---|---|---|
| **T1** | `HSCodeField` (автокомплит + мягкая валидация) в карточке и строке КП | действующий ТУПИК |
| **T2** | переклассификация: закрытые коды → очередь внимания; ActivityLog присвоений | синхронность |
| **T3** | страница «Справочник ТН ВЭД» (дерево + обычный поиск + ИИ-поиск) + Unfold read-only | обе модальности |
| **T4** | пакетная классификация с подтверждением | остаток волны D |

Зависимости: T1 самодостаточна; T2 требует T1 (куда вести из очереди); T3/T4 независимы.
