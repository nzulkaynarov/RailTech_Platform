# Спека: живые таможенные платежи по коду ТН ВЭД (интегрированный тариф ГТК)

_Статус: НА УТВЕРЖДЕНИИ. 2026-08-04. Продолжение трека номенклатуры
(`spec-nomenclature-lifecycle-2026-08-03.md`, PR #529/#530)._

## 1. Задача и решение одним абзацем

Менеджер, готовя КП с растаможкой, сегодня уходит на сайт ГТК, руками вбивает код ТН ВЭД,
смотрит пошлину/акциз/НДС и возвращается переносить цифры. Предложение: показывать платежи
**там, где код уже выбран** — в карточке товара, в строке КП и в справочнике ТН ВЭД — живым
запросом к официальному калькулятору ГТК (`tarif.customs.uz`), с суточным кэшем и честной
деградацией в ссылку. **Ставки НЕ храним и в расчёт КП НЕ подставляем** — мы витрина
официального источника, не таможенный консультант.

## 2. Ресерч источников (сделан, 2026-08-04)

| Источник | Что там | Вердикт |
|---|---|---|
| lex.uz/docs/-7533457 (ПП-181 от 14.05.2025) | Юр. первоисточник номенклатуры. 1-илова: PDF 874 стр., только уз-кириллица, ставок НЕТ; рус. версии приложения НЕТ | Для наименований uz — когда возьмём uz-локаль; не сейчас |
| ПП-3818 (2018, ред. 2-иловы ПП-181) | Ставки пошлин/акцизов как юридический ТЕКСТ | Не структурные данные; не источник для интеграции |
| tarif.customs.uz `/hscode-list` | Операционный классификатор (13 138 кодов, RU) | УЖЕ интегрирован — PR #530, недельный автосинк |
| tarif.customs.uz `POST /calc/view_calc.jsp` | **Интегрированный тариф по коду**: сбор/пошлина/акциз/НДС со ставкой и правовым основанием + разрешительные документы, по режиму и странам | **Источник этой спеки.** Отвечает ~0.8 сек (замерено), HTML |

Замеры и грабли источника: ответ 0.8 сек / ~38 КБ (в отличие от медленного `/hscode-list`);
TLS-цепочка без промежуточного сертификата — **лечится уже добавленным**
`master_data/certs/sectigo-dv-r36.pem` (PR #530); API неофициальный (внутренний endpoint их
страницы) — отсюда обязательная деградация, см. §6.

## 3. Бенчмарк (PRODUCT RULE 1)

- **Odoo / Bitrix24**: на товаре хранится только HS-код; ставок в системе нет вообще.
- **SAP GTS, Avalara, Thomson Reuters ONESOURCE**: тарифный контент — платная подписка у
  специализированных провайдеров: ставки меняются постановлениями, зависят от страны
  происхождения и преференций, их перепечатка = ответственность.
- **Именованный паттерн**: «live-витрина официального калькулятора» — как наш FX-блок
  (курсы ЦБ РУз тянем сами, но КП замораживает снимок, а не мы «назначаем курс»). Здесь
  ещё осторожнее: показываем справочно, ничего не замораживаем и не подставляем.

Решение по паттерну: **не хранить** (позиция уже закреплена в докстринге `HSCode` — сознательно
без ставок), **не блокировать** (ГТК лёг — работаем как раньше), **не консультировать**
(подпись «по данным ГТК, справочно» + прямая ссылка на первоисточник).

## 4. Что уже есть в системе (фундамент)

- `master_data.HSCode` — 13 138 кодов, недельный автосинк (PR #530).
- `HSCodeField` (Shared) — автокомплит кода на месте (паттерн Shopify), стоит в **карточке
  товара** (`ProductFormSheet`) и **гриде КП** (`GridRow`, dense-режим); мягкая валидация.
- Страница справочника `#hs-directory` (секция «Номенклатура», продавец, KYC + `catalog.*`).
- `QuoteItem.hs_code` — замороженный снимок кода в КП.
- Вид расхода `CUSTOMS` в каскадных строках расходов КП — куда менеджер вносит пошлину руками.
- Паттерн внешнего госисточника: `master_data/fx.py` (ЦБ) и `master_data/tnved.py` (ГТК).

## 5. Backend (волна D1)

**Сервис** `master_data/customs_duties.py` (Rule 8 — вся логика здесь):

- `fetch_duties(hs_code, origin_country_numeric)` — `POST /calc/view_calc.jsp`
  (`rejim=1` импорт, `receiving_country=860`, TLS-контекст из `tnved.py`), httpx timeout 10с.
- Парсер их HTML → структура:
  `{fetched_at, payments: [{type_code: "10"|"20"|"27"|"29", rate_text, legal_basis}], permits: [{org, document}]}`.
  Типы платежей — по стабильным кодам ГТК (10 сбор, 20 пошлина, 27 акциз, 29 НДС), подписи —
  наши i18n-ключи, их локализованные заголовки не используем.
- Парсер ТЕРПИМЫЙ: неузнанные строки пропускает с `logger.warning`; полное неузнавание
  структуры → `DutiesUnavailable` (никаких падений на смене их вёрстки).
- **Кэш**: Django cache (Redis) по ключу `(hs_code, origin)`, TTL 24 ч; негативный кэш ошибок
  5 мин (не долбить лежащий сервер). Никаких записей в БД, никаких Celery — по требованию.

**Endpoint** `GET /api/v1/master-data/hs-codes/{code}/duties/?origin=RU` — тонкий view:
код валидируется по справочнику (404 `HS_CODE_UNKNOWN`), сбой источника → 503
`HS_DUTIES_UNAVAILABLE` (shape `{"detail": CODE}`), троттлинг стандартный. Синхронный вызов
допустим: 0.8 сек + жёсткий таймаут + кэш (это НЕ тяжёлый PDF/AI-путь из ARCH-01/03).

**Страны**: калькулятору нужны числовые ISO-коды (643, 860...). Миграция master_data:
`Country.iso_numeric` + данные для сидированных стран (Rule 1 — данные миграцией).

## 6. Frontend (волна D2) — путь пользователя

Один компонент **`DutiesSheet`** (Shared, shadcn `Sheet`), три точки входа — везде, где уже
живёт код:

1. **Карточка товара** (`ProductFormSheet`): под `HSCodeField` при валидном коде появляется
   тихая ссылка-кнопка «Таможенные платежи» (иконка `Landmark`/`Scale`).
2. **Грид КП** (`GridRow`): пункт контекстного меню строки при заполненном `hs_code` — тот же
   Sheet. Рядом со ставкой пошлины — подсказка «внести в расходы» НЕ автоматом: закрываем Sheet,
   менеджер сам добавляет строку CUSTOMS (§3 — не подставляем).
3. **Справочник `#hs-directory`**: действие в строке кода.

Содержимое Sheet (сверху вниз):

- Заголовок: код + наименование позиции из нашего справочника.
- Селектор «Страна отправления/происхождения» (наши `Country`, по умолчанию — пусто с
  подсказкой выбрать; выбор запоминается на сессию). Пока страна не выбрана — данные не тянем.
- Таблица платежей: Вид платежа | Ставка | Правовое основание (обычная маленькая `Table`,
  не `ResponsiveDataTable` — 4 строки).
- Блок «Разрешительные документы» (если есть): орган + документ.
- Футер: «По данным ГТК РУз на {дата}, справочно — не является консультацией» + внешняя
  ссылка «Открыть калькулятор ГТК» (`target=_blank`).
- Состояния: skeleton при загрузке; **деградация** — карточка «Не удалось получить данные ГТК»
  с той же внешней ссылкой (тупика нет никогда); кэш-попадание — мгновенно.

i18n: все подписи в `ru.json` + `en.json`; семантические токены; тексты ставок ГТК показываем
как есть (первоисточник — русский).

**Гейты**: новых НЕТ (PRODUCT RULE 2). Endpoint — любой авторизованный; UI появляется на
поверхностях, уже закрытых своими гейтами (карточка — `catalog.manage`, грид — `quote.build`).

## 7. Что сознательно НЕ делаем

- НЕ храним ставки в БД (ни модели, ни снапшотов) — витрина, не копия.
- НЕ подставляем пошлину в расчёт КП автоматически (происхождение/преференции/СТ-1 — зона
  ответственности менеджера).
- НЕ показываем блок в публичном КП клиента — внутренний инструмент продавца.
- НЕ делаем режим экспорта (`rejim=2`) в MVP — путь клина импортный; добавится параметром.
- НЕ парсим uz-PDF из ПП-181 — отложено до волны uz-локали (см. §2).

- **D2 frontend** (~1 PR): `DutiesSheet` + три точки входа + i18n + vitest.
- **DoD (глазами, GIF владельцу)**: карточка товара → выбрал код автокомплитом → «Таможенные

  деградации со ссылкой работает; та же панель из строки КП и из справочника.
