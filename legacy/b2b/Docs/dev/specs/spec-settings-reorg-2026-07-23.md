# Спека: «Настройки 2.0» — навести логический порядок и работоспособность

_Статус: **DRAFT — ожидает утверждения владельцем.** Наблюдение владельца 2026-07-23: «в настройках полная свалка, работает частично или заводит в тупик, есть расхождения с основным функционалом». По PRODUCT RULES — сначала целевая картина + gap-анализ, потом код._

_Основано на: адверсариальном аудите Settings Hub (карта 10 секций + проблемы) + benchmark-ресерч (Bitrix24 Settings, Slack role-specific settings, Odoo Settings→Billing, SaaS account-settings UX)._

## 0. Benchmark-вердикт (как у эталонов)

| Принцип эталона | Источник | Как применяем |
|---|---|---|
| **Личное отделено от компании отделено от платформы** | Bitrix24: «My Profile» (сам правит) ↔ «Settings» (только админ) ↔ «CRM → My company details» | Сгруппировать 10 плоских секций в блоки: Аккаунт · Компания · Продажи · Команда и доступ · Платформа |
| **Progressive disclosure / role-specific** | Slack прячет advanced workspace-настройки от рядовых | Показывать секцию ТОЛЬКО если право пользователя её реально СОХРАНЯЕТ (убирает мёртвые заглушки) |
| **План/биллинг живут в Settings** | Odoo/Bitrix24: Settings → Billing | Перенести «Подписку» в Настройки как витрину плана компании |
| **Одна запись — один источник** | все | Убрать дубль реквизитов между «Компания» и «Документы и бренд» |
| **Никаких тупиков, реальные статусы** | все | Team: добавить удаление/деактивацию, заменить фейковый «Активен» |

**Ключевой инсайт:** это НЕ добавление функций, а **устранение трения** (PRODUCT RULE 2) — свести показ-гейт к правде сохранения, сгруппировать, убрать дубли/тупики.

## 1. Текущее состояние (что за свалка)

10 плоских секций одним столбцом, все реально пишут в БД (заглушек нет), но:

**Покупатель (5 секций):** Личные данные · Безопасность · Компания · Шаблоны документов · Команда. Промахи: сотрудник без прав приземляется в пустую read-only «Команду»; покупателю зачем-то показывают «Шаблоны документов» (письма/акты).

**Продавец (9 секций):** + Документы и бренд · Дефолты КП · Нумерация · Шаблоны расходов. Настоящая свалка: три «документ*»-вкладки + две «Шаблоны», дубль реквизитов, а «Подписка» — отдельным пунктом меню вне настроек.

## 2. Корневые проблемы (severity)

| № | Проблема | Severity | Корень |
|---|---|---|---|
| P1 | **Показ-гейт ≠ гейт сохранения** — делегат с `charge_templates.manage` видит 6 секций, работает 1; остальные рисуют read-only/«обратитесь к админу» | 🔴 тупик | `canEditCompanySettings` слишком широкий; внутри компоненты требуют `settings.edit` (бэк 403) |
| P2 | **Нет удаления/деактивации члена команды** — «добавил не того — убрать нельзя» | 🔴 незавершённость | В team/* только инвайт+роли; нет remove/deactivate (бэкенд `update-member-capabilities`/toggle есть) |
| P3 | **Рядовой член приземляется на read-only «Команду»** — стена без действий | 🟡 тупик | `defaultSettingsSection` для беспермишенного = `team` |
| P4 | **Дубль реквизитов** legal_name/inn/address/bank в «Компания» И «Документы и бренд» | 🟡 свалка | Задумано наследование (`use_company_defaults`), по факту двойной ввод |
| P5 | **Две «Шаблоны» рядом** (расходов vs документов) + три «документ*»-вкладки | 🟡 путаница | Терминологическая перегрузка |
| P6 | **Превью нумерации только «КП»**, хотя префикс брендирует ВСЕ документы (CT/INV/акты) | 🟡 расхождение | Хардкод `PREVIEW_LABEL='КП'` |
| P7 | **Подписка вне «Настроек»** (отдельный top-level пункт) | 🟡 разрыв модели | Нет секции план/лимиты в настройках компании |
| P8 | **Фейковый статус «Активен»** у члена команды (всегда зелёный) | 🟡 расхождение | Колонка не читает реальное состояние |
| P9 | `SystemSetting.standard_margin` **вероятно инертна** (движок цен читает `CompanySettings.default_margin_percent`) | 🟡 расхождение | Настройка в «Платформа» без эффекта |
| P10 | Дефолт-секция = company/team, а не profile; плоский список без группировки | ⚪ косметика | — |
| P11 | Лого/KYC: UI строже бэка (бэк пускает любого члена, UI прячет за `settings.edit`) | ⚪ гейтинг | Рассинхрон UI↔бэк |

## 3. Целевая картина

### 3.1 Группировка (сайдбар настроек с заголовками)
```
АККАУНТ
  · Личные данные        (все)
  · Безопасность         (все)
КОМПАНИЯ
  · Реквизиты и бренд    (settings.edit)  ← слияние «Компания» + «Документы и бренд»
  · Нумерация документов (settings.edit)
ПРОДАЖИ                  (только продавец: can_sell && companySells)
  · Параметры КП по умолчанию   (settings.edit)   ← ex-«Дефолты КП»
  · Статьи расхода КП           (charge_templates.manage)  ← ex-«Шаблоны расходов»
  · Шаблоны писем и актов       (settings.edit)   ← ex-«Шаблоны документов»
КОМАНДА И ДОСТУП
  · Команда и роли       (team.manage; рядовой — read-only свой профиль в команде)
БИЛЛИНГ
  · План и подписка      (витрина; продавец)   ← перенос «Подписки» в настройки
ПЛАТФОРМА                (только оператор)
  · Системные настройки
```

### 3.2 Показ-гейт = правда сохранения (P1 — главный фикс)
Секция видна ТОЛЬКО если у пользователя есть право, которое её РЕАЛЬНО сохраняет:
- Реквизиты/бренд/нумерация/параметры-КП/шаблоны-писем → `settings.edit`
- Статьи расхода → `charge_templates.manage`
- Команда → `team.manage` (иначе — read-only «мой профиль в команде», без стены CRUD-ролей)
Это УБИРАЕТ 5 мёртвых секций у charge-делегата. Никаких новых блокировок — только перестаём показывать несохраняемое.

### 3.3 Дефолт-секция = `profile` для всех (P3/P10)
Вход в «Настройки» всегда открывает «Личные данные» (или последнюю посещённую) — не бросает в read-only.

### 3.4 Терминология (P5, i18n)
«Шаблоны расходов»→«Статьи расхода КП»; «Шаблоны документов»→«Шаблоны писем и актов»; «Дефолты КП»→«Параметры КП по умолчанию». Единая пара маржа/наценка по владельческой семантике.

## 4. Волны исполнения (мультиагенты; guardrails PRODUCT+IRON RULES; DoD глазами покупатель+продавец)

| Волна | Задача |
|---|---|
| **S1 — гейтинг + дефолт (P1/P3/P11)** | `settingsSections.tsx`: visible() каждой секции = точное право сохранения; дефолт=profile; синхронизировать UI-гейт лого/KYC с бэком. Тесты `settingsSections.test.ts` (матрица ролей: OWNER/settings.edit/charge-делегат/рядовой/покупатель/продавец/admin). БЕЗ бэкенда. |
| **S2 — группировка + терминология (P5/P10/i18n)** | `SettingsLayout` заголовки групп; переименования табов (i18n оба json); порядок секций. Чистый фронт. |
| **S3 — команда: удаление/деактивация + реальный статус (P2/P8)** | Бэкенд: endpoint remove/deactivate члена (never-orphan: ≥1 OWNER — `CANNOT_REMOVE_LAST_COMPANY_ADMIN`); фронт: кнопки в TeamMembersTable + AlertDialog + реальный статус. Тесты. |
| **S4 — слияние Реквизиты+бренд (P4)** | Объединить «Компания»+«Документы и бренд» в одну секцию: реквизиты (источник) + подраздел PDF-бренд с тумблером «наследовать». Убрать двойной ввод. Осторожно — не сломать document-profile/КП-рендер. |
| **S5 — подписка в настройки + нумерация-превью (P6/P7)** | Секция «План и подписка» (витрина `GET /accounts/subscriptions/mine/`); превью нумерации для КП/CT/INV. |
| **S6 — аудит standard_margin (P9)** | Разобраться: подключить как fallback движка цен ИЛИ убрать из «Платформы». |

_Порядок: S1 (тупики) → S2 (порядок) → S3 (команда) → S4 (дубли) → S5 (биллинг/нумерация) → S6 (маржа). S1+S2 — быстрые фронт-волны, дают львиную долю «порядка»._

## 5. Решения владельца (утверждено 2026-07-23)

**Спека УТВЕРЖДЕНА, рекомендации приняты целиком:**
1. **Покупателю ПОКАЗЫВАТЬ** «Шаблоны писем» (переименовать понятно) — он выпускает претензии/запросы.
2. **СЛИТЬ** «Компания»+«Документы и бренд» в одну секцию (реквизиты-источник + подраздел бренда).
3. **ПЕРЕНЕСТИ** «Подписку» в Настройки → Биллинг, top-level nav-пункт убрать.
4. **standard_margin — УДАЛИТЬ** из «Платформы» (движок цен читает CompanySettings.default_margin_percent).
