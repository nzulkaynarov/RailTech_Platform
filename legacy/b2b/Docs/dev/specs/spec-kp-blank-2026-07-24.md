# Спека: «Фирменный бланк 2.0» — единая анатомия КП + документов по мировой практике

_Статус: **УТВЕРЖДЕНА концептуально владельцем 2026-07-24** («в целом я утверждаю твои предложения и рекомендации»; таблица позиций утверждена отдельно после ресерча EN 16931). Ожидаются материалы владельца (файлы бланка/печати/подписи + ответы на уточнения §6) — волны K1–K3 могут стартовать без них, пиксель-доводка K2b требует файлы._

_Контекст: владелец прислал 2 эталона — свой ручной КП (Word, СНГ-практика) и Quotation ADZ Nagano GmbH (EU-практика), попросил вывести паттерны и предложить вариант по мировому опыту. Акцент — «расстановка данных». Владелец также спрашивал про загрузку .docx-бланка напрямую — отклонено как костыль (автоконвертация docx→HTML даёт мусорную разметку и ломает тему D2); принят путь «бланк = дизайн-эталон, воспроизводимый чистым шаблоном» (как Odoo/PandaDoc)._

---

## 1. Анализ эталонов (что вычитано из двух образцов)

| Блок | КП RailTech (СНГ) | ADZ Nagano (EU) |
|---|---|---|
| Шапка | Лого + полные реквизиты **с банком** (МФО/ИНН/p/c) | Лого + «Quotation»; реквизиты компактно |
| Мета | №, Дата, Кому (3 строки) | **Мета-бокс справа**: №, дата, expiration, customer ref, **sales responsible**, тел/email |
| Вступление | **Куртуазный абзац** («выражает почтение… в ответ на заявку») = КП+письмо в одном PDF | Юр. строка (non-binding, without VAT) + инструкции по заказу |
| Таблица | № / Наименование / Ед / Кол-во / Цена **с НДС** / Сумма | Pos / item#+external+многострочная спека / Qty / unit price (/1 pcs) / Amount (**нетто**) |
| Итоги | «Общая стоимость» (с НДС) | Net amount |
| Условия | Блок «Условия поставки» label:value (отгрузка/сроки/оплата/гарантия/срок КП/прочие) | Payment 50/50, Incoterms FCA, **прайс-бреки по объёму**, lead-time плашка, упаковка/сборы, compliance (no re-export RU/BY) |
| Подпись | **Подпись директора + круглая печать М.П.** | «valid without a signature» (автоген) |
| Футер | Примечание про НДС/логистику | **Многоколоночный рег-футер** на каждой стр. + Page X of Y |

**Вывод:** два акцента одной анатомии. Мировая практика (Odoo Document Layout, PandaDoc Themes, DocuSign underlay+fields) не клонирует бланк-файл, а даёт **структуру + тему + настройки**: СНГ-режим и EU-режим — пресеты одного движка.

## 2. Сравнение с мировой практикой (по каждому решению)

| Решение спеки | Эталон | Обоснование |
|---|---|---|
| Бланк как чистый шаблон, не docx-импорт | Odoo (макеты в коде + Document Layout), PandaDoc (docx лишь отправная точка) | Автоконвертация = мусорная разметка, ломает тему/динамику |
| Транзакционные: фиксированная анатомия + динамические строки | Odoo QWeb, все ERP | Строки растут/переносятся по A4 — фикс-координаты Word невозможны |
| Письма/доверенности: подложка + поля | DocuSign (underlay + placed fields) | Фиксированный лист — «расстановка данных» буквально |
| Нетто-цены построчно, НДС один раз в итогах | **EN 16931** (стандарт э-инвойса ЕС): разделение нетто/налог/брутто | Утверждено владельцем; движок УЖЕ так считает — «с НДС» был только в ручном Word |
| Идентификатор товара подстрокой (не колонкой) | ADZ (item#+external+description стопкой) | Вмещает арт/ГОСТ/чертёж/part# без разбухания таблицы |
| Срок/наличие колонкой с fallback | ADZ (lead-time выделен плашкой) | Промышленный B2B; данные уже есть (`lead_time_days`) |
| Одна тема на все PDF | Odoo Document Layout, PandaDoc Themes | Реализовано в D2 (#406) — бланк едет на ней |
| Подпись+печать изображениями, тумблер «автоген» | СНГ-обязательность М.П. vs ADZ «valid without signature» | Оба режима одной галкой |
| Настройки по владельцу данных | Трёхуровневый сплит (утв. 2026-07-24) | Идентичность продавца→UI; платформенное→env; юр.→шаблон |

## 3. Целевая анатомия КП 2.0 (7 блоков)

Артефакт-макет (утверждён визуально): https://claude.ai/code/artifact/887fd648-9140-4570-a13c-71bf4aa88df7

1. **Шапка-letterhead с банком** [НОВОЕ]: лого + юр.название + адрес + **банковский блок** (банк/филиал, МФО, ИНН, р/с) + web/email. Источник — «Реквизиты и бренд» (`CompanyDocumentProfile`+Company). Тумблер `show_bank_in_header`.
2. **Мета-бокс справа** [РАСШИРИТЬ]: № КП · Дата · **Действителен до** · Кому · **Менеджер** (prepared_by). Сейчас есть №/дата/valid_until разрозненно — собрать в бокс.
3. **Сопроводительный абзац** [НОВОЕ]: куртуазное вступление («КП+письмо в одном»), текст с плейсхолдерами (`{{company.name}}` контрагента и т.п.), настраиваемый; тумблер показа.
4. **Таблица позиций** [УТВЕРЖДЕНА]: № · Наименование+идентификатор (арт/ГОСТ/чертёж/part# подстрокой) · Кол-во (ед. inline) · **Срок/наличие** (per-line → fallback общий срок КП → «В наличии») · **Цена за ед. без НДС** · Сумма без НДС. Динамика по страницам (thead повторяется — уже есть). Конфиденциальность цел: показанная нетто-цена = all-in delivered (charges размазаны, НЕ отдельной строкой).
5. **Итоги**: Итого без НДС → НДС N% → **К оплате с НДС** + «Сумма прописью» (есть). 
6. **Условия поставки структурно** [РАСШИРИТЬ]: label:value — Место отгрузки · Сроки · Оплата · Базис (Incoterms) · Гарантия · Срок действия КП · Прочие (free-text). Источники: дефолты КП (`CompanySettings.default_*`) + per-КП поля.
7. **Подпись + печать** [НОВОЕ]: изображения подписи и печати (М.П.) из профиля; `sign_mode`: `manual` (СНГ: подпись+печать) / `auto` (EU: строка «Сформировано автоматически, действительно без подписи»). Футер + «Стр. X из Y» — есть.

**Опционально, по умолчанию ВЫКЛ** (не плодим настройки без спроса): колонка скидки % (Odoo), базис цены «/1 шт» (ADZ), прайс-бреки по объёму (ADZ) — отложены до явного запроса.

## 4. Модель данных (дельта)

`CompanyDocumentProfile` (+ миграция accounts):
- `cover_letter_text` TextField blank — текст сопроводительного (плейсхолдеры разрешены; рендер через существующий letter-резолвер, HTML-escape значений);
- `show_cover_letter` Bool default False;
- `signature_image` ImageField null (валидация как логотип: validate_image_upload + magic-bytes);
- `seal_image` ImageField null (аналогично);
- `sign_mode` CharField choices `manual`/`auto`, default `manual`;
- `show_bank_in_header` Bool default True.

Данные срока: `QuoteItem.lead_time_days` (есть) + `Quote.effective_delivery_lead_time_days` (есть) → рендер-логика fallback + «В наличии» (без миграции). Брендовый снапшот: новые поля входят в `brand_snapshot`/frozen-семантику как существующие (frozen КП не перерисовывается; смена профиля инвалидирует незамороженные — уже сделано в D1a).

## 5. Волны реализации (пилот → раскат; DoD глазами по каждой)

| Волна | Содержимое | Зависимости |
|---|---|---|
| **K1 — backend-поля** | Миграция полей §4; сервис document_profile (upload signature/seal — тот же путь что logo, magic-bytes; whitelist полей; инвалидация PDF уже срабатывает); brand-context прокидывает новые поля; тесты | — |
| **K2a — шаблон КП (структура)** | quote_pdf/_document_base: мета-бокс, банк-шапка (тумблер), сопроводительный абзац (резолвер плейсхолдеров), колонка Срок/наличие с fallback, условия label:value, подпись+печать/автоген-строка; регенерация схемы; тесты рендера | K1 |
| **K2b — пиксель-доводка** | Сверка с .docx/PDF бланка владельца до совпадения глазами (отступы/шрифт/расстановка) | файлы владельца |
| **K3 — настройки UI** | «Реквизиты и бренд»: загрузка подписи/печати, текст сопроводительного, тумблеры, sign_mode; live-превью (WYSIWYG POST draft — механизм D1b готов); i18n | K1 |
| **K4 — раскат** | Те же блоки (шапка-банк/подпись-печать/мета-бокс) на договор/инвойс/акт — через _document_base, дельта мала | K2 утверждён глазами |
| **K5 — письма-подложка** | Опция «бланк-подложка» для писем/доверенностей (фикс-лист): фон-изображение A4 + поля поверх (DocuSign-модель) | отдельное решение владельца — есть ли реальные подложки |
| **K6 — адверс-ревью** | Сопроводительный текст через санитайзер/эскейп (SSTI/XSS), изображения печати (magic-bytes, публичная страница), конфиденциальность цен, frozen-инварианты | K2–K4 |

_Порядок: K1→K2a→K3 стартуют сразу (материалы владельца не нужны); K2b — по получении файлов; K4 — после «глазами ок» на пилоте КП; K5 — по отдельному решению. DoD каждой волны: сценарий глазами (настройки → предпросмотр → отправка → публичная страница/PDF у клиента) + скриншот владельцу._

## 6. Открытые пункты (ждём владельца — блокируют ТОЛЬКО K2b/K5)

1. Файлы бланка: .docx + PDF-экспорт (пиксель-доводка).
2. Сопроводительный текст: фикс-дефолт компании или редактируемый per-КП? (в K1 закладываем дефолт компании + возможность override per-КП позже).
3. PNG печати и подписи (прозрачный фон) — есть ли файлы.
4. Фирменный шрифт — критичен ли конкретный (иначе DejaVu, кириллица есть).
5. Банк в шапке vs в блоке «Поставщик» (по бланку владельца — в шапке; default `show_bank_in_header=True`).
6. Полный ли список строк «Условий поставки» (§3.6); «Прочие» — free-text per-КП.

## 7. Явно НЕ делаем (и почему)

- **Импорт .docx как рабочего шаблона** — костыль, ломает тему/динамику (эталоны так не делают).
- **Редактируемый HTML-макет транзакционных PDF** — эталон решает темами поверх фиксированных макетов (решение D2, подтверждено владельцем).
- **Прайс-бреки/скидки/базис цены** — отложено до явного спроса (не плодим настройки).
- **Неустойка договора в настройки** — юр-уровень, по трёхуровневому сплиту остаётся в шаблоне.
