# Волна 2.3b: `set-state-in-effect` — ВЫПОЛНЕНА 18-08

_Правило включено. Нарушений было 45, а не 26: точный список даёт только прогон с ВКЛЮЧЁННЫМ правилом. Переписан 31, у оставшихся 14 стоит точечное исключение с причиной. Итог и уроки — в конце файла._

_Решение владельца 18-08: «переписать волной и включить правило». Волна ЧИСТО техническая: поведение остаётся прежним везде, кроме мест, где нынешний эффект даёт лишний кадр — там кадр исчезает._

## Почему это не «стиль»

`useEffect`, который синхронизирует состояние с пропсами, показывает пользователю **старое
состояние на один кадр**, потом перерисовывает. На быстрых машинах незаметно, на медленных —
мигает; при этом каждый такой эффект тянет за собой ручную защиту от рефетча (ref-гарды, списки
примитивов в зависимостях), а забытая защита стирает то, что человек печатает. Четыре настоящих
дефекта волны 2.3a (18-08) — ровно этого класса.

Канон React (react.dev, «You Might Not Need an Effect»): **derived value** → **`key` для сброса**
→ **корректировка состояния в рендере**. Последнее уже завёрнуто в наш `useDraftState`.

### B. Сброс при закрытии диалога → сессия открытия

`CommandPalette:94`, `DocumentSearchDialog:59`, `ConfirmActionDialog:88`, `ExcelPasteDialog:55,64`,
`RequestItemsEditor:76` (сброс AI-подсказок), `AICatalogMatchDialog:45`.

Канон — **размонтировать** содержимое: Radix и так снимает `DialogContent` при закрытии, поэтому
состояние, живущее ВНУТРИ содержимого, сбрасывается само. Где выносить тело в подкомпонент дорого —
`useDraftState(open ? sessionId : null, …)`: тот же сброс без эффекта и без лишнего кадра.

## Итог 18-08

**45 → 14**, правило `react-hooks/set-state-in-effect` включено. Файлов в диффе — 37, тестов +4.

Что оказалось важнее плана:

- **Настоящий список даёт только включённое правило.** По плану мест было «26» (оценка из
  прошлого триажа), по факту 45: разметка «категория B» не совпадала с тем, что ловит линтер.
- **Часть мест не нуждалась в состоянии вовсе.** «Кривая ссылка восстановления пароля»,
  «единственная дорожка чата», «предвыбор подсказанных продавцов», «роли колонок при вставке
  из Excel», «выбор строк в реестре» — это ВЫЧИСЛЕНИЯ: состояние хранило то, что и так
  выводится из пропсов.
- **Три ref-гарда в карточке товара заменились одним источником** «форма открыта + id карточки».
  Ровно эти гарды дали дефект 18-08: у соседнего эффекта гард забыли, и рефетч стирал результат
  ПЛАТНОГО вызова ИИ.
- **Тонкость, пойманная собственным тестом:** при корректировке состояния в рендере тело
  компонента ОДИН РАЗ выполняется со старым значением — React отбрасывает этот результат и сразу
  перерисовывает. На экран старое не попадает, поэтому мерить надо ЗАКОММИЧЕННЫЕ кадры (эффект
  после коммита), а не вызовы функции-компонента. С `useEffect` старое значение как раз
  коммитится — отсюда и мигание, ради которого волна затевалась.
- **Исключения живут в файлах, а не в конфиге.** 14 оставшихся мест (подписки, таймеры,
  websocket, разбор URL, императивная загрузка) получили `eslint-disable-next-line` с текстом
  причины рядом с кодом — так исключение видит тот, кто правит этот код, а не тот, кто однажды
  откроет `eslint.config.js`.
