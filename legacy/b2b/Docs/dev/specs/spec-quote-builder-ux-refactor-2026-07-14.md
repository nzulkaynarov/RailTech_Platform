# ТЗ: Стресс-аудит и рефакторинг UX/UI конструктора КП

**Дата:** 2026-07-14 · **База:** main `8a5ea3c` · **Статус:** предложение на решение владельца
**Метод:** мультиагентный аудит (3 независимых Opus-агента: эргономика грида по коду · сквозной workflow продавца · бенчмарк 11 CPQ-продуктов и grid-эталонов) + ручная верификация критических находок по коду.

---

## 1. Вердикт

КП-конструктор — основное рабочее место команды продавцов, но в текущем виде это «демо, а не рабочее место». **Оценка Excel-паритета: 3/10.** Сильные стороны (живой rail экономики, cost-redaction по правам, чат без потери контекста, 202-паттерн AI) обнулены критическими дефектами ввода, потери данных и масштаба. При реальной нагрузке (КП на 30–300 позиций, 8-часовой рабочий день) инструмент вызовет отторжение — риск, прямо угрожающий wedge-циклу ADR-0006.

Главный конкурентный вывод бенчмарка: «гигиенический минимум» рынка (inline-грид с клавиатурой, typeahead-подбор, sticky-итоги, автосейв+undo, guardrails по марже) мы не выполняем, но **две ниши рынок обслуживает плохо и мы можем в них выиграть**: (а) массовая вставка позиций из Excel в грид (PandaDoc/Airtable не осилили, а наши заявки живут в Excel), (б) прозрачный каскад charges с промежуточными суммами (у всех «чёрный ящик», у нас уже есть SAP-style движок).

## 2. Верифицированные P0-дефекты (проверены по коду вручную)

| # | Дефект | Код | Эффект |
|---|--------|-----|--------|
| P0-1 | **Пагинация молча режет КП на 20 позициях.** `QuoteItemViewSet` (crm/views/quotes.py:726) не имеет `pagination_class = None` (у QuoteStatus/ChargeType/ChargeTemplate — имеет), глобальный `PAGE_SIZE=20`; `crmApi.getQuoteItems` возвращает только `data.results`. | quotes.py:726, settings.py:590, crmApi.ts:602 | КП >20 строк: продавец видит и редактирует только 20, остальные существуют и входят в `economics`-итог. Расхождение «строки ≠ итог», отправка непроверенного КП. Потеря доверия + фактическая неработоспособность на больших КП |
| P0-2 | **Правка цены не двигает сумму/маржу/итоги до Save.** «Сумма» и маржа-чип читают server-поля `final_price_excl_vat`/`landed_cost`; локальная правка `frozen_base_price` их не меняет (а qty — меняет: поведение непоследовательное). | QuoteBuilderGrid.tsx:741-744, 338-349 | Сломанная петля обратной связи: инструмент ощущается «мёртвым», продавец сохраняет вслепую |
| P0-3 | **Тихая потеря введённого.** `useEffect` безусловно перетирает `localItems` при ЛЮБОМ рефетче `['quote-items']`; а его инвалидируют мутации settings/charges/basis. Плюс: нет guard'а навигации (`beforeunload`/back), нет optimistic locking на QuoteItem (last-write-wins между двумя менеджерами). | QuoteBuilderGrid.tsx:132-137; useCRM.ts (инвалидации); quotes.py:726 | Штатный сценарий «вбил цены → открыл Настройки задать наценку → цены исчезли». Час работы теряется от одного промаха по «Назад» |
| P0-4 | **Пакетный Save с частичным провалом.** Последовательный `for…await` по строкам; падение строки N: 1…N−1 сохранены, N+1… — нет; в catch один генерик-тост `errors.operationFailed`; успешные мутации уже рефетчнули и перетёрли грид, включая упавшую правку. | QuoteBuilderGrid.tsx:166-191 | «Операция не удалась» — а что сохранилось, неизвестно; именно проблемная правка потеряна |
| P0-5 | **Числовой ввод враждебен RU-локали.** `type=number`: запятая «1234,50» → пустое значение → форс `"0"` (нельзя даже стереть и перенабрать); колесо мыши над сфокусированным инпутом меняет цену; 9-значные UZS-суммы без разрядов в `w-32`-инпуте (ошибку на порядок не видно). | QuoteBuilderGrid.tsx:143-157, 692-714 | Обнуление цены десятки раз в день; случайные изменения сумм скроллом; невидимые ошибки на порядок |

## 3. Major-находки (сгруппированы)

**Эргономика ввода (агент 1):**
- Нет стрелочной навигации по ячейкам, Enter/Escape в ячейках не делают ничего; автофокуса на новой строке нет; add-row закрывается после каждого добавления, qty=1/price=0 зашиты → добавить 30 позиций = сотни кликов с прокруткой.
- Нет bulk-операций (мультиселект, массовое удаление/цена), нет дублирования строки, нет Undo, нет Excel-paste. Удалить 5 позиций = 10 кликов и 5 модалок.
- Sticky-итоги отсутствуют: на ноутбуке ≤1279px панель экономики — за кнопкой (Sheet), итог «уезжает»; на <1200px cost-колонки исчезают из таблицы (маржа — только через раскрытие каждой строки).
- Валидация только на Save (кроме cap-тостов); инлайн-подсветки невалидной ячейки нет.
- Hit-targets 12–32px (корзина `size-3`, chevron ~20px) — на таче минное поле; фокус ячейки — только `ring-1`.

**Workflow (агент 3):**
- Happy-path «заявка → отправленный КП» = 3 экрана, ≥3 модала, ~14–16 кликов + построчный ввод. Полноправный соло-продавец обязан: submit на согласование → согласовать собственный шаг → send (3 действия вместо одного).
- **Тупик после REJECTED:** `canBuildQuote` требует `!deal.active_quote` → после отклонения кнопки «Создать версию 2» нет нигде, хотя backend умеет автоинкремент версий. Переговорная итерация (ядро wedge) обрывается в UI.
- **Поздний сюрприз монетизации:** `SELLER_KYC_REQUIRED`/`QUOTE_SEND_NOT_ENTITLED` всплывают только в `send_to_client` — после всей набивки и согласования. На билдере/дашборде упреждающего баннера нет.
- Очередь согласований ведёт в общий список сделок (`onNavigate('crm-deals')`), а не в конкретный КП; стадийный «лифт» DRAFT→SOURCING→CALCULATING прокликивается вручную, в RFQ_OPEN у продавца пустой action-bar (тупик).
- Конфигурация КП размазана: Incoterm — в rail, маржа/НДС/валюта/сроки — в QuoteSettingsDialog, cover-note — в GenerateQuoteDialog, charges — секция под таблицей; `valid_until` вводится в двух местах.
- Асимметрия RequestItemsEditor (покупатель) и QuoteBuilderGrid (продавец) — два разных UI одной ментальной модели «список позиций».

**Что сделано хорошо (НЕ ломать):** живой rail экономики с below_cost/below_floor; cost-redaction (`econ === null`) и на сервере, и в UI; Deal-workspace с чатом slide-over; 202+polling для AI; backend re-check всех прав в approvals; идемпотентный claim через `select_for_update`; empty-states с primary action.

## 4. Бенчмарк: где мы против рынка

Полная матрица 11 продуктов — в отчёте агента (Salesforce CPQ/QLE, HubSpot, PandaDoc, Proposify, Qwilr, DealHub, Zoho, Odoo, Bitrix24, МойСклад + AG Grid/Airtable как grid-эталоны). Выжимка:

| Паттерн | Best-in-class | У нас |
|---|---|---|
| Inline-грид + drawer для редких полей | Salesforce QLE, Airtable | Частично (expandable-строка есть, грид не inline-first) |
| Клавиатура: Tab/Enter/стрелки, Excel-paste, fill-handle | AG Grid (эталон); CPQ-рынок отстаёт | **Нет** |
| Bulk: мультиселект, массовая цена, дублирование, drag-reorder | DealHub, PandaDoc, МойСклад, Odoo | **Нет** |
| Автосейв + индикатор + undo | Airtable/PandaDoc/Qwilr | **Нет** (явный Save с потерей при уходе) |
| Подбор товара: typeahead в ячейке + picker с мультивыбором + create-on-the-fly | Odoo + HubSpot | Частично (AI-match есть, ручного typeahead нет) |
| Live-маржа по строке + guardrail «ниже floor → авто-approval» | DealHub, PandaDoc, Zoho | Маржа есть (сильно!), но не live при правке цены (P0-2); guardrail не подсвечивает строку |
| Прозрачный каскад скидка→charges→налог с промежуточными суммами | Ни у кого хорошо | **Наш шанс** (движок готов) |
| Секции/заметки/optional items для 50+ позиций; виртуализация | Odoo, Qwilr; AG Grid | **Нет** (и обрыв на 20 строках) |

Антипаттерны рынка, которых избегать: тормоза Salesforce на сотнях строк (→ виртуализация), отсутствие bulk-edit у HubSpot (главная жалоба), сломанный Excel-paste у PandaDoc (открытый uservoice — **ниша**), тяжёлый явный Calculate/Save (→ автосейв черновика + undo).

## 5. Предложение: целевая модель и рефакторинг

### Целевая модель билдера
«**Excel, который знает ваши правила**»: inline-first грид с полной клавиатурной моторикой и локальным мгновенным пересчётом; сервер — источник истины по каскаду, фронт — детерминированное зеркало (decimal.js уже есть); автосейв черновика с undo; строки-guardrails, сами уходящие в согласование; Excel-paste как фирменная фича заявочного рынка.

### Архитектурный рефакторинг фронта
`QuoteBuilderGrid.tsx` (904 строки — уже нарушает лимит 500) разбить на пакет `components/QuoteBuilder/`:
- `QuoteBuilderGrid.tsx` (фасад) · `GridRow.tsx` / ячейки · `EconomicsRail.tsx` · `StickyTotalsBar.tsx` · `AddRowInline.tsx`
- `hooks/useQuoteDraft.ts` — **машина состояния черновика**: dirty-tracking по строкам, merge server-рефетча только в чистые строки, undo-стек, autosave-дебаунс, navigation-guard. Это лечит P0-3/P0-4 системно, а не заплатками.
- `hooks/usePricingMirror.ts` — локальный пересчёт строки/итогов (decimal.js), зеркалирующий `crm/services/pricing` (паритет закрепить контрактным тестом фронт-vs-бэк на фикстурах). Лечит P0-2.
- `hooks/useGridKeyboard.ts` — roving tabindex, стрелки/Enter/Escape, Excel-paste (tab-separated → строки).
- Грид на **TanStack Table + TanStack Virtual** (headless, совместимо с shadcn, без лицензии AG Grid); RequestItemsEditor позже мигрирует на те же примитивы (снимает асимметрию редакторов).

### Backend
- `pagination_class = None` на QuoteItemViewSet (P0-1, однострочный hotfix) → затем виртуализация.
- **Bulk-PATCH** `POST /crm/quote-items/bulk/` — транзакция, пер-строчные ошибки `{index, field, code}`; один пересчёт каскада и один рефетч вместо N (лечит P0-4 и мигание грида).
- `version` + `OptimisticLockingMixin` на QuoteItem (409 → диалог «обновить данные»).
- `capabilities`-срез для билдера уже есть в `/me` — довести до UI (ранний баннер KYC/подписки).

### Нарезка на волны (каждый пункт = отдельный PR, конвенция «один PR — одно изменение»)

**Волна 0 — hotfix (дни, до любого редизайна):**
1. P0-1 пагинация (`pagination_class = None` + тест «КП 25 строк виден целиком»).
2. Navigation-guard + не перетирать dirty-строки при рефетче (минимальная версия: skip setLocalItems при hasUnsavedChanges + beforeunload).
3. Числовой ввод: запятая→точка, пустое ≠ "0", `onWheel` blur, `inputMode="decimal"`, разряды на blur.
4. Deep-link из QuoteApprovalQueue на `deal-quote/{id}`.

**Волна 1 — «живой грид» (1–2 недели):**
5. `useQuoteDraft` + bulk-PATCH endpoint (транзакция, пер-строчные ошибки, подсветка ячейки).
6. `usePricingMirror`: сумма/маржа/итоги пересчитываются на вводе; sticky-полоса итогов (и на ≤1279px).
7. Add-row: остаётся открытой (Enter = добавить и продолжить), поля qty/цена сразу, автофокус новой строки.
8. Ранние гейты: баннер KYC/подписки на билдере с первого экрана; disabled-«Отправить» с объясняющим tooltip.
9. Кнопка «Создать версию 2» после REJECTED (UI поверх готового backend-автоинкремента).

**Волна 2 — Excel-моторика (1–2 недели):**
10. Клавиатурная навигация (стрелки/Enter/Escape, roving tabindex) + видимый фокус ячейки/строки.
11. Мультиселект строк + bulk-действия (удалить, наценка/скидка на выбранные) + дублирование строки; undo-стек.
12. **Excel-paste**: вставка tab-separated таблицы → создание/заполнение строк (наш дифференциатор №1).
13. Typeahead-подбор товара в ячейке имени (каталог + create-on-the-fly), рядом с существующим AI-match.

**Волна 3 — масштаб и структура (по мере спроса):**
14. TanStack Virtual (цель: 300 строк без лага) + разбиение файла на пакет.
15. Optimistic locking на QuoteItem.
16. «Согласовать и отправить» одним действием для держателя `quote.approve_final` (backend уже позволяет самосогласование — схлопнуть UI-шаги); авто-лифт стадий до CALCULATING одной кнопкой «Приступить к КП».
17. Консолидация настроек КП (базис поставки → в QuoteSettingsDialog; `valid_until` — одно место).
18. Каскад-визуализация charges с промежуточными суммами (дифференциатор №2); guardrail-подсветка строки ниже floor → бейдж «уйдёт на согласование».
19. Секции/заметки/optional items; общие grid-примитивы для RequestItemsEditor.

### Метрики приёмки (мерить до/после, есть TTFK-телеметрия)
- «Заявка 30 позиций → КП готов к отправке»: ≤ 10 мин (сейчас — не измеримо, ввод мышевозный).
- Клики на одну позицию (добавить+оценить): ≤ 3 (сейчас 6–8 с прокруткой).
- Потери введённого: 0 сценариев (сейчас ≥3 штатных).
- КП на 300 позиций: полный, без лага ввода (сейчас обрыв на 20).
- Excel-паритет: с 3/10 до ≥7/10 по чек-листу осей аудита.
