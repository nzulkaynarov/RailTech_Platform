# RailTech B2B Platform — Критический аудит и мировые практики

## Готовность к демо для инвестора: 4 из 10

Визуально платформа выглядит профессионально, архитектура заложена правильно. Но для инвестора, который будет кликать по интерфейсу — слишком много пустых заглушек и несостыковок с данными.

---

## Часть 1. Что делает мир (и что мы упускаем)

### 1.1 Онбординг — Alibaba, SAP Ariba, IndiaMart

**Мировой стандарт:**

- Alibaba: регистрация → Business Verification (загрузка документов + проверка 2-14 дней) → Gold Supplier / Verified Supplier уровни
- SAP Ariba: приглашение от покупателя → заполнение профиля → квалификация через анкету → допуск к тендерам
- IndiaMart: регистрация → TrustSEAL (выезд инспектора) → верифицированный значок

**Что у нас:**
Онбординг из 3 шагов (email → статус → имя). Нет загрузки документов (лицензия, ИНН, сертификаты). Нет уровней верификации.

**Рекомендация:** Добавить шаг загрузки документов (хотя бы UI). Показать уровни доверия: «Базовый» → «Проверенный» → «Премиум партнёр». Это то, что инвестор ожидает от B2B платформы.

---

### 1.2 RFQ-процесс — Salesforce, Coupa, Yo!Kart

**Мировой стандарт:**
Salesforce 2025 сократил 7-шаговый RFQ до 4 шагов внутри платформы. Ключевое: покупатель НЕ выходит из системы — исследование, запрос, котировка, согласование — всё в одном месте. Coupa добавляет автоматические напоминания поставщикам и SLA по времени ответа.

**Что у нас:**
Поток работает (заявка → RFQ → ответ завода → расчёт → КП → сделка), но нет Excel-импорта (ключевая фича!), нет переговорного цикла (только принять/отклонить), нет SLA-таймеров.

**Рекомендация:** Симулятор импорта Excel — критически важен для демо. Добавить возможность «Запросить скидку» при просмотре КП. Показать таймеры ответа на RFQ.

---

### 1.3 Landed Cost и ценообразование — Zonos, Avalara, DHL

**Мировой стандарт:**
Zonos и Avalara предлагают real-time калькуляторы таможенных пошлин. DHL показывает полную разбивку: товар + фрахт + страховка + пошлина + НДС = итого. Прозрачность — ключевой фактор доверия.

**Что у нас:**
Формула правильная (FCA + логистика 8% + таможня 5% = Landed Cost × маржа × 1.12 НДС). Но маржа только общая, нет per-item настройки. Нет визуальной разбивки для клиента (waterfall-диаграмма).

**Рекомендация:** Добавить waterfall/breakdown карточку в КП для клиента. Даже если данные демо — визуализация ценообразования впечатляет инвесторов.

---

### 1.4 Дашборд — роле-зависимый

**Мировой стандарт:**
Каждая роль видит СВОИ метрики. Покупатель: «Мои заявки», «Ожидают КП», «Экономия». Продавец: «Входящие запросы», «Конверсия», «Выручка». Производитель: «Заказы в работе», «Загрузка», «RFQ на ответ».

**Что у нас:**
Один дашборд для всех ролей. Одни и те же цифры (280K, 88 заявок) вне зависимости от статуса компании.

**Рекомендация:** Три разных набора KPI-карточек и графиков в зависимости от `activeStatus`.

---

### 1.5 Каталог и продукция

**Мировой стандарт:**
B2B каталоги: иерархия категорий (дерево), фильтры по спецификациям, изображения товаров, сравнение, PDF-карточка товара.

**Что у нас:**
20 товаров. Без изображений. Плоские категории (нет дерева). Для ЖД-платформы слишком мало специализированного оборудования — в основном сырьё (баббит, круг стальной).

**Рекомендация:** Довести до 50+ товаров. Добавить 2-3 единицы тяжёлого ЖД-оборудования (тележки, колёсные пары, тяговые двигатели). Добавить placeholder-изображения.

## Часть 2. Критические баги для демо

### 2.1 Производитель видит пустой список продукции

В `ProductManagement.tsx` фильтр: `ownerCompanyId === 'C_SELF'`. Но в `products.ts` большинство товаров принадлежит `'C_OTHER'`. Когда инвестор переключится на роль производителя — пустая страница.

**Приоритет: КРИТИЧЕСКИЙ**

### 2.2 Бейджи в сайдбаре захардкожены

`badge="2"`, `badge="5"`, `badge="3"` — статичные числа. Не меняются при переходе по потоку. Инвестор заметит.

**Приоритет: ВЫСОКИЙ**

### 2.3 11 из ~20 страниц — заглушки «В разработке»

Если инвестор кликнет по «Сделки», «Котировки», «Клиенты», «Аналитика», «Категории», «Импорт» — увидит заглушку. Это 40% навигации.

**Приоритет: ВЫСОКИЙ**

### 2.4 Нет скачивания КП / документов

Кнопка «Скачать» есть, но не работает. B2B-продажи = документооборот. Без PDF-выгрузки демо неполноценно.

**Приоритет: ВЫСОКИЙ**

### 2.5 Dashboard не реагирует на роль

Переключение BUYER → SELLER → MANUFACTURER не меняет дашборд. Инвестор спросит: «А что видит покупатель?» — и увидит то же самое.

**Приоритет: СРЕДНИЙ**

## Часть 3. Что правильно (и это ценно)

1. **Мультиролевая архитектура** — CompanyStatus × UserRole — это правильный подход, так работают SAP, Coupa
2. **FSM для сделок** — конечный автомат переходов стадий. Профессиональный подход
3. **Финансовый конвейер** — формула Landed Cost корректна для Узбекистана (12% НДС)
4. **Мультиперспективный поток** — одна заявка видна по-разному для покупателя/продавца/завода. Это killer-feature
5. **shadcn/ui** — чистый, современный UI без кастомных компонентов
6. **i18n-готовность** — ru/en тексты, правильная структура
