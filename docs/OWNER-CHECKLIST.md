# OWNER-CHECKLIST — действия владельца вне кода
Статус: действует · Владелец: владелец · Обновлено: 2026-11-22

Только то, что может сделать владелец руками: настройки в интерфейсе, внешние аккаунты, GitHub, тексты. Отмечать здесь;
агенты читают статус перед задачами, которые от этого зависят. Вопросы, на которые нужно **ответить** (выбрать вариант),
живут в [`QUESTIONS.md`](QUESTIONS.md), раздел «Ждут владельца»; принятые решения — в [`DECISIONS.md`](DECISIONS.md).

## Сейчас — до пилота (≈ 6–7 ноября 2026)

- [x] **Почта** (подключена, письма уходят; журнал CRM 2026-11-09). Платформа → Настройки → Подключения → «Почта»: SMTP (позже IMAP `info@`) с паролем приложения Яндекс 360.
  У домена отправки проверить SPF, DKIM и DMARC. На сервер ничего класть не нужно.
  Проверено 2026-11-22: MX — Яндекс, SPF `redirect=_spf.yandex.net`, DKIM (селектор `mail`) и DMARC есть.
- [ ] **DMARC — от «наблюдать» к «в спам»** (через 2–4 недели после 2026-11-22, если в отчётах на `dmarc@railtech.uz`
  нет чужих отправителей от имени домена). DNS домена обслуживает Яндекс 360 (NS `dns1/dns2.yandex.net`): Администрирование
  Яндекс 360 → Домены → `railtech.uz` → DNS-записи → `TXT _dmarc` — заменить `p=none` на `p=quarantine`; остальное оставить. Подделка писем от `@railtech.uz` уйдёт в спам, наши письма доходят лучше.
- [ ] **CAA для сертификатов.** Там же (Яндекс 360 → Домены → DNS-записи) добавить запись `CAA` для `railtech.uz`: `0 issue "letsencrypt.org"` —
  сертификаты для домена и поддоменов сможет выпускать только наш центр сертификации (Caddy получает их у Let's Encrypt).
  Новых технических поддоменов не нужно (разбор 2026-11-22): рабочие `platform`, `cabinet`, `crm`, `erp`; служебные
  интерфейсы наружу не публикуются намеренно.
- [ ] **Внешняя копия бэкапов на Яндекс Диске** (решение 2026-10-31; Google Drive на личном Google не работает —
  `storageQuotaExceeded`). В Яндекс ID аккаунта Яндекс 360, на Диске которого будут копии (лучше отдельный ящик вроде
  `backup@<домен>`): Безопасность → Пароли приложений → создать пароль типа **«Файлы»**. Затем Платформа → Настройки →
  Подключения → «Хранилище» → «Внешняя копия бэкапов» → «Изменить подключение» → «Яндекс Диск (рекомендуется)» → адрес почты,
  папка (по умолчанию `RailTech-backups/prod`), пароль приложения → «Сохранить и проверить» → «Доступ есть»
  ([`runbooks/offsite-gdrive.md`](runbooks/offsite-gdrive.md) §1, ≈ 3 минуты). На сервер ничего класть не нужно.
- [ ] **Юристу — одной фразой подтвердить** хранение зашифрованных копий базы на Яндекс Диске компании (Яндекс 360) вместо
  Google Drive (одобрение 2026-10-28 было про Google Drive).
