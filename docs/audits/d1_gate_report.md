## 1. Итог

**Гейт D1-7 пройден с оговорками.** Весь путь «клиент пишет в бота → менеджер видит и отвечает → «Создать заявку» → резолюция
директора → задание в расчёт → КП → одобрение с автоотправкой и ИСХ; служебка с возвратом и бухгалтер» проходит на живом стенде под
ролями пилота (делопроизводитель, директор, менеджер-универсал, бухгалтер, снабженец, гл. инженер), созданными из шаблонов через
интерфейс администратора, **без единого захода в старые фронты**. Сообщение клиента появляется в Платформе за **0,8 с** (цель ≤ 2 с),
двойной клик «Создать заявку» даёт **одну** ЗВ, 70 проверок axe по ключевым экранам и двум ширинам — 0 нарушений.

Оговорки — их три и они про пилот, а не про ядро пути: **(1) граница по лидам из решения владельца 2026-11-01 в интерфейсе не
выдержана** — делопроизводитель «Забирает» лида и отвечает клиенту так же, как менеджер, а передать лид менеджеру-универсалу нельзя
(D17-G-1); **(2) недоступный канал отправки КП в Платформе не виден ни до, ни после одобрения** — причина лежит только в ERP, менеджер
получает в колокольчике «отправьте вручную» без причины и без кнопки «Отправить» (D17-G-2); **(3) приглашение в кабинет клиенту не
уходит, пока не задан адрес кабинета** (D17-G-3, на стенде не задан; для P7 нужен чек-лист).

## 3. Замеры и честные ошибки отправки

**≤ 2 с, 6 замеров** (менеджер-универсал открыл диалог L-0001; сообщение клиента `inject` в заглушку Bot API → появление пузыря в ленте
без перезагрузки), мс: **799, 787, 783, 784, 782, 784**. Новая передача от бота в «Ждут ответа» на двух открытых страницах (ДП и МУ): **792 / 792 мс**
(включая работу бота: без ИИ-ключей бот отвечает «Извините, сейчас не получается ответить…» и передаёт человеку). Значения ровные (разброс 17 мс); запас до цели ≈ 2,5×. Машина не была перегружена (load average на старте ≈ 4).

**«Доставка не подтверждена».** Заглушка Telegram поставлена на паузу (`docker pause` своего контейнера), менеджер отправляет ответ:
через **20 с** — «Доставка не подтверждена: Telegram не ответил вовремя. «Повторить» не отправит второе сообщение» (текст в поле сохранён);
«Повторить» сразу — «Сообщение ещё отправляется — подождите немного»; «Повторить» после 2 минут — «Доставка не подтверждена — проверьте у клиента,
получил ли он ответ». Дубля нет, ложного «отправлено» нет. Снимки `m2-*`.

**CRM остановлена** (`stop crm-api`): «Ждут ответа» и «Лиды» — «Не удалось загрузить. Проверьте связь и обновите» + «Обновить»; «Мои задачи» —
«Не загрузились лиды и ответы клиентам… Остальное показано» + «Очередь загружена не полностью». После запуска — всё поднялось само (D17-G-10 — мелочь).

## 8. Не проверено и почему

- **Доставка письма клиенту (e-mail)** и **входящая почта**: на стенде нет SMTP/IMAP, реальные письма запрещены; цепочка ERP → шина → почтовый сервис CRM → `skipped_no_smtp` проверена по журналу. Закрывает P7 на проде.
- **Telegram, кнопка «Открыть кабинет», Mini App**: заглушка Bot API видит только текст и `chat_id`; кнопки и deep-link `/start` не проверялись (D17-G-3).
- **Ответ ИИ-агента бота**: ключей моделей нет (платные вызовы запрещены), бот честно отвечает «Извините, сейчас не получается ответить…» и передаёт человеку; квалификатор лида падает в журнале (`qualifier_failed`) — ожидаемо.
- **Резолюция «на исполнение» любому сотруднику** и поручения — P8b не влит.
- **Письмо на бланке (P4), «Исходящие» ИСХ-письма** — P4 не влит.
- **Версии файлов EDS, экспорт реестра, ошибка обработки inbox шины, архивный контакт** — §5.
- **Договор, счёт, акт, оплата, «Я оплатил»** — гейт D2-6.
- **КП без выбранных каналов**: по умолчанию включены все три, ветку «ни одного канала → отправит менеджер» не проходил; в Платформе действия «отправить» нет (D17-G-2).

## 9. Стенд и воспроизведение

Проект `rt-gate-d17`, порт 8097, поднято: `postgres`, `db-init`, `redis-broker`, `redis-cache`, `rustfs`, `s3-init`, `litellm`, `litellm-seed`,
`crm-migrate`, `crm-api`, `crm-bot`, `crm-worker`, `erp-backend`, `erp-worker`, `erp-beat`, `eds-migrate`, `eds-api`, `eds-worker`, `platform-bff`,
`platform-web`, `caddy` и контейнер заглушки Bot API; **без** `docling`, `crm-mcp-*`, `erp-mcp`, `erp-worker-ai`, `erp-ai-gateway`, `crm-web`, `erp-web`,
`cabinet-web`, Langfuse. Пик памяти стенда ≈ 4,6 ГиБ. `PLATFORM_SSO_ENABLED=true`, `TELEGRAM_BOT_TOKEN` — вымышленный, `TELEGRAM_API_BASE_URL=http://fake-bot-api:8081`.
Файл переменных создан вне репозитория (скриптом по `.env.example` со случайными секретами; `make env` и правка `.env` в этой сессии были
недоступны — запрет прав на файл `.env`), override compose — вне репозитория: снял зависимость `caddy` от `crm-web`/`erp-web`/`cabinet-web` и `crm-worker` от `docling`.
Ошибки в журналах стенда за время гейта: только вызванные намеренно (502 при зависшем Telegram, 503 при остановленной CRM) и `qualifier_failed` без моделей.
Стенд снят: `docker compose -p rt-gate-d17 down -v`, контейнер заглушки и образы проекта удалены; общих очисток Docker не было.
