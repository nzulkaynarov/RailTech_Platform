# Админка без терминала: подключения, модели ИИ, расходы, первый запуск — скоуп и план (2026-10-12)

Запрос владельца: отдать админу максимум управления — бот, канал, модели ИИ и ключи, лимиты, расходы,
статус системы; при старте CRM первым делом настроить все подключения. Документ — ресерч, рекомендация и
план работ. Реализация начинается после утверждения ADR (отклонение от SPEC и CLAUDE.md §2.3).

## 1. Что сейчас настраивается вне интерфейса

| Что | Где сейчас | Кто может поменять |
|---|---|---|
| Первый админ | `make create-admin` | только с сервера |
| Токен Telegram-бота, режим polling/webhook | `.env` (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_MODE`) | сервер + перезапуск |
| Канал команды | `make settings key=notifications` или «Настройки» (ввести `-100…` вручную) | админ, но id надо где-то узнать |
| Провайдеры и модели ИИ | `infra/litellm.config.yaml` | сервер + перезапуск |
| Ключи провайдеров (Anthropic, Gemini) | `.env` | сервер + перезапуск |
| Жёсткие лимиты расходов | `infra/litellm.config.yaml` | сервер + перезапуск |
| Мягкий бюджет, тексты бота, правила передачи, часы | «Настройки» | админ ✅ |
| Демо-база знаний, загрузка файлов | `make kb-demo` / «База знаний» | частично админ |
| Бэкап, его статус | `make backup`, cron | сервер |
| Статус моделей, бота, канала, очереди | алерт в канал команды раз в час | никто не видит постоянно |
| Реальный расход | дашборд: только диалог и квалификатор | неполно |

## 2. Бенчмарк

- **Chatwoot, Intercom, Zoho TeamInbox** — Telegram подключается в интерфейсе: «Добавить канал → Telegram →
  токен от BotFather», продукт сам проверяет токен, регистрирует webhook и показывает имя бота.
- **n8n, Zapier, Make** — «Credentials»: секрет вводится один раз, хранится зашифрованным, в интерфейсе виден
  только хвост, у каждого подключения кнопка «Test» и статус.
- **Metabase, Grafana, GitLab, Jenkins** — мастер первого запуска: пока нет админа, открывается страница
  настройки, защищённая одноразовым кодом из логов сервера (чтобы чужой не успел создать админа первым).
- **Intercom, HubSpot** — чек-лист «Getting started» на главной у админа: шаги с галочками до первой ценности.
- **OpenAI, Anthropic, Vercel** — страница usage: расход по дням, по назначению, против лимитов.
- **Statuspage-подход внутри продукта (Front, Intercom «System status»)** — один экран «Работает / Сбой» по
  каждому компоненту с временем последней проверки.

Чего в бенчмарках **нет** в интерфейсе: пароли баз данных, ключи подписи сессий, мастер-ключ шифрования,
домен и TLS. Это инфраструктура: без неё приложение не стартует, и её утечка через веб-интерфейс опаснее,
чем польза от правки мышкой.

## 3. Рекомендация: граница «интерфейс / сервер»

**В интерфейс (админ):**
1. Telegram-бот: токен, проверка, имя бота, описание и меню на трёх языках, режим (polling на dev, webhook
   на prod — выбирается автоматически по наличию домена), перезапуск бота без перезапуска сервера.
2. Канал команды: «Добавьте бота админом в канал» → бот получает событие `my_chat_member` → CRM показывает
   «Найден канал „…“ — подключить?»; кнопка «Отправить тестовое сообщение». Без ручного `-100…`.
3. Модели ИИ: для каждой роли (диалог, квалификатор, резерв, поиск, проверка качества) — провайдер, модель,
   ключ, «Проверить подключение», статус. Хранение — штатно в БД LiteLLM (`store_model_in_db`, ключи
   шифруются `LITELLM_SALT_KEY`), CRM — обёртка над его API управления моделями.
4. Лимиты: дневной лимит по каждому провайдеру и мягкий бюджет — в «Настройках», проверяет наш код перед
   вызовом. Потолок в конфиге LiteLLM остаётся аварийным, выше настроек.
5. Расходы: единый учёт каждого вызова (назначение, провайдер, модель, токены, стоимость, лид, работа/тест),
   экран «Расходы».
6. Статус системы: экран «Состояние» — бот, канал, каждая модель, база знаний, очередь, последний бэкап,
   место в хранилище; время проверки и понятная причина сбоя.
7. Бэкапы: статус последнего, «Сделать бэкап сейчас». Восстановление — только с сервера (разрушительно).
8. Системные уведомления: личные сообщения от бота админам (подписка в профиле), канал — запасной путь.
9. Мастер первого запуска и чек-лист «Настройка» на главной админа.
10. Песочница бота в CRM: «Проверить бота» — диалог с ботом прямо в CRM без Telegram, с пометкой «тест»
    в расходах. Админ проверяет базу знаний и тексты до запуска клиентов (Intercom «Test Fin»).

**Остаётся на сервере (`.env`):** пароли Postgres и S3, `JWT_SECRET`, `AGENT_CONTEXT_KEY`, мастер-ключи
LiteLLM и шифрования секретов, домен, TLS, порты, Langfuse. В «Состоянии» показывается только «задано / нет».

**Безопасность, обязательная для всех пунктов 1–3:**
- поле секрета только на запись, после сохранения видны последние 4 символа, в браузер и логи не уходит;
- смена секрета или модели — повторный ввод пароля админа, запись в аудит без значения;
- секреты в нашей БД шифруются ключом из `.env` (AES-GCM / Fernet), в бэкап ключ не попадает;
- мастер первого запуска закрыт одноразовым кодом из логов api и выключается навсегда после создания админа.

## 4. Мастер первого запуска

Пока нет ни одного админа, CRM открывает `/setup` вместо входа.

| Шаг | Что делает админ | Что проверяет CRM |
|---|---|---|
| 0 | Вводит одноразовый код из логов сервера | код совпал, не истёк |
| 1 | Создаёт себя админом | пароль, email |
| 2 | Компания: название, часовой пояс, рабочие часы, языки | — |
| 3 | Модели ИИ: ключ Anthropic и Gemini (или другой провайдер) | «Проверить подключение» по каждой роли |
| 4 | Telegram-бот: токен от BotFather | `getMe`, имя бота, меню опубликовано |
| 5 | Канал команды: добавить бота админом | событие от Telegram, тестовое сообщение дошло |
| 6 | База знаний: загрузить первые документы | документ проиндексирован |
| 7 | Проверить бота в песочнице | ответ по базе знаний |
| 8 | Пригласить команду | пользователи созданы, Telegram ID привязаны |

После мастера на главной админа — чек-лист с теми же шагами и статусами, пока всё не зелёное.
Любой шаг можно пропустить и вернуться позже; без шагов 3–5 бот не запускается, CRM честно это показывает.

## 5. Ещё продуктовые советы

- **Песочница бота** (п. 3.10) — самый быстрый способ админу проверить базу знаний; дешевле и безопаснее,
  чем тест на живом Telegram.
- **Шаблоны быстрых ответов менеджера** («Пришлю КП сегодня», «Уточните ИНН») — стандарт Intercom/Front
  macros; бесплатны, в отличие от ИИ-черновика. Хорошо сочетаются с Q-019.
- **Экспорт** лидов и клиентов в CSV для админа — ожидаемо в любой CRM, снимает страх «данные заперты».
- **Журнал доставки бота**: на сообщении в CRM видно «доставлено / ошибка Telegram (клиент заблокировал бота)»
  — менеджер не ждёт ответа от того, кто бота заблокировал.
- **Не делать сейчас:** мультитенантность, свой маркетплейс интеграций, мини-приложение Telegram.

## 6. План работ

Каждый шаг — отдельный PR с «Проверить на dev». Платных вызовов моделей в разработке нет; кнопка
«Проверить подключение» в интерфейсе — один минимальный запрос (доли цента) по нажатию админа.

| # | Что | Зависит от | Объём |
|---|---|---|---|
| 0 | ADR: секреты интеграций в БД (шифрование, граница интерфейс/сервер); ADR: модели и ключи через БД LiteLLM; правка SPEC §2, §3, §11 и CLAUDE.md §2.3 | ваше утверждение | 1 PR, документы |
| 1 | Фундамент: зашифрованное хранилище секретов, раздел «Подключения» со статусами, экран «Состояние системы» | 0 | 1–2 PR |
| 2 | Telegram из интерфейса: токен, перезапуск бота на лету, профиль и меню, авто-обнаружение канала, тестовое сообщение | 1 | 1–2 PR |
| 3 | Модели ИИ из интерфейса: БД LiteLLM, роли, ключи, проверка, переключение резерва, предупреждения о качестве и переиндексации | 1 | 2 PR |
| 4 | Учёт расхода и «Расходы»; лимиты по провайдерам в «Настройках» с проверкой кодом | 3 | 1–2 PR |
| 5 | Личные уведомления: админу системные (вместо канала), менеджеру по его лидам (Q-010), звук и уведомление браузера | 2 | 1–2 PR |
| 6 | Мастер первого запуска и чек-лист «Настройка»; бэкап «сейчас» и его статус | 1–4 | 1–2 PR |
| 7 | Песочница бота в CRM | 3, 4 | 1 PR |
| 8 | Бот по статусу: меню лида и клиента, «Мои документы» кнопками, «Поделиться номером» (Q-020) | 2 | 2 PR |
| 9 | Бэклог решений: контакты клиента (Q-011), сделки (Q-013, ADR), ИИ-помощь менеджеру (Q-019), шаблоны ответов, экспорт CSV | по очереди | — |

Порядок: сначала безопасность и подключения (0–3), потому что от них зависят деньги и запуск; затем
прозрачность (4–6); затем удобство клиента (7–8). Приёмка Фазы 9 на стенде может идти параллельно с шагом 0.
