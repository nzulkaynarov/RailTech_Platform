# Эргономика CRM и дашборд — предложение (2026-10-12)

Запрос владельца: компактность и логика расположения информации на всех экранах, без потерь; отдельное
решение по дашборду с графиками; только готовые компоненты, без кастома и костылей.

Метод: снят каждый экран под админом (1440×900), замерена высота страницы, просмотрен глазами. Данных на
стенде мало, поэтому для списков учитывалось поведение на реальном объёме.

## Принципы (одни для всех экранов)

1. **Один экран — одна задача.** Всё, что нужно для решения, видно без прокрутки на 1440×900; детали —
   по клику, а не простынёй.
2. **Таблица, а не карточки, для однотипных записей.** antd `Table` с `size="small"`, фиксированной шапкой
   (`sticky`), раскрывающейся строкой (`expandable`) для деталей и пагинацией 20/50.
3. **Детали — в боковой панели, а не на новой странице или внизу.** antd `Drawer` справа (как в Linear,
   HubSpot): список остаётся на месте, контекст не теряется.
4. **Пары «поле — значение» — `Descriptions`** (`size="small"`, 2–3 колонки), а не столбик подписей.
5. **Длинные формы — по группам**: `Collapse` или `Tabs`; «Сохранить» — в шапке страницы, всегда видно
   (`PageHeader extra`), плюс тег «Есть несохранённые изменения». Плавающую панель посреди формы убрать.
6. **Пустые разделы — одной строкой** (уже сделано в карточке клиента) — распространить на все.
7. **Ничего не удаляется**: каждое перемещение в таблице ниже указывает, куда переехал блок.

## Дашборд — с графиками

Библиотека — `@ant-design/plots` 2.6 (официальные графики экосистемы Ant Design на AntV G2; совместима с
React 18 и antd 5; тема берётся из токенов). Свои графики не рисуем.

Экран по смыслу сверху вниз, всё на 1–1,5 экрана:

1. **Ряд KPI** (`Statistic` + стрелка тренда к прошлому периоду): новые лиды · забрали менеджеры ·
   выиграно (шт. и сумма) · среднее время до «Забрать» · стоимость моделей.
2. **Поток лидов** — `Line` (или `Area`) по дням: новые лиды, передачи, забрали, выиграно — из `daily`.
3. **Воронка** — `Funnel` по стадиям (сейчас список с цифрами) — из `funnel`.
4. **Почему передаём** — горизонтальный `Bar` по причинам — из `escalation_reasons`.
5. **Сделки** — `Column` выиграно/проиграно по дням + кольцевой `Pie` «Отказы по причинам» — из
   `deals/summary`.
6. **Работа бота** — `Gauge` «Доля вопросов без ответа» (`fallback_share`) и `Column` «Ответы бота /
   передачи» по дням.
7. **Расходы** — `Column` по дням (работа/тест стеком) и `Bullet` «сегодня против дневного бюджета» — из
   `spend`.

Чего не хватает в API (добавить при реализации): разбивка по менеджерам (забрал, время реакции, выиграно)
и доля передач, отвеченных в срок SLA. Остальное уже отдаёт `/dashboard`, `/deals/summary`, `/spend`.

## Дефекты, найденные по ходу

- Лиды: тег приоритета вылезает из «Кто ведёт» в «Язык».
- Настройки → Правила передачи: плавающая «Сохранить» закрывает поле «Отключённые причины передачи».
- Аудит: сырые коды новых действий (ИИ-помощь, сделки, контакты, модели, экспорт, шаблоны) и их полей.
