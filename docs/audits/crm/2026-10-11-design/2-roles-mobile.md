# Ревью: пути ролей и мобильная версия RailTech CRM — 2026-10-11

Методика: design-critique (юзабилити, иерархия, консистентность, доступность). Серьёзность: 🔴 блокирует сценарий или ведёт к ошибке, 🟡 мешает или сбивает, 🟢 полировка.
Источники: скриншоты `shots/*.png` (desktop-manager-*, desktop-viewer-*, mobile-admin-*, mobile-anon-login); код `frontend/src`, `infra/casbin/policy.seed.csv`, `backend/app/services/leads.py`.
Закрытое в аудите 2026-10-09 (U-02 экран 403, U-03 причины, U-05 фильтры в URL, U-06 быстрое «Забрать», U-10 «Назад», U-12 вкладки, P-20 имя владельца, P-21 передача, P-30 RBAC наблюдателя) не повторяю. Упоминаю только там, где исправление сработало не полностью.

**Итог:** с ролями всё в порядке: навигация совпадает с политикой Casbin, прямой URL к чужому разделу даёт понятный 403, наблюдатель не видит ни одной кнопки записи. Остались три вида проблем: (1) ссылки дашборда, ведущие на 403; (2) сервисный запрос, у которого нет «входа» в работу менеджера; (3) мобильная версия: кнопка меню Refine перекрывает заголовок на каждой странице, таблица лидов разваливается, цели касания 24–32 px.

## 2. Путь менеджера по задачам дня

| # | Шаг | Клики | Узкое место |
|---|---|---|---|
| 1 | Вход → сразу «Входящие» | 0 | ✓ `HomeRedirect` |
| 2 | Эскалация → «Забрать» прямо в очереди | 1 | 🟡 После «Забрать» лид уходит в «Мои лиды», а менеджер остаётся в очереди. Чтобы ответить, нужен ещё клик по лиду. Intercom/Front после «Assign to me» сразу открывают диалог. Рекомендация: «Забрать и открыть» как действие по умолчанию или переход после успеха (`InboxPage.tsx:37-40`) |
| 3 | Открыть лида | 2 | ✓ «Назад» возвращает в очередь (`PageHeader.tsx:18`) |
| 4 | Ответ клиенту (Enter) | 3 | 🟡 На телефоне Enter отправляет сообщение (`ChatThread.tsx:66-71`), на мобильной клавиатуре нет Shift, поэтому многострочный ответ невозможен |
| 5 | Смена стадии | — | Явной смены стадии нет, есть только «Сделка заключена / Закрыть отказом». Это соответствует SPEC (стадии решает код) |
| 6 | «Сделка заключена» → диалог → подтвердить | 5 | — |
| 7 | «Сделать клиентом» → модалка: выбрать или создать клиента → ОК | 7–8 | 🟡 После создания клиента идёт переход в карточку клиента (`MakeCustomer.tsx:31`). Лид и переписка теряются из вида. Лучше: остаться в лиде с уведомлением «Клиент создан — открыть» |
| 8 | Сервисный запрос от клиента | 9–13 | 🔴 У запроса нет «входа»: в навигации и во «Входящих» его нет. Если бот создал `info`-эскалацию, менеджер видит лида, но не сам запрос. Путь: Клиенты (9) → поиск (10) → карточка (11) → прокрутить вниз → «Закрыть» (12) → ответ → «Отправить и закрыть» (13). Из лида нет ссылки на открытый запрос: обратная ссылка «из лида» есть только в карточке клиента (`ServiceRequests.tsx:64-68`). HubSpot/Front: тикеты — отдельная очередь со статусами |

**Итого:** около 13 кликов и 3 смены контекста (очередь → лид → карточка клиента → поиск клиента). Контекст теряется на шагах 2 (возврат в очередь), 7 (уход в клиента) и 8 (поиск запроса вручную).

## 4. Прочее (замечено попутно)

- 🟡 В «Почему система так решила» сырые коды триггеров: «(триггер): price_or_contract_asked, qualifier_recommend» (`desktop-manager-leads_11`). `transitionReason` возвращает строку как есть, если она не распознана (`domain/labels.ts:103`). Список кодов через запятую нужно прогнать через `reasonLabel`.
- 🟡 Плитка «Сделок 3» ведёт на `/leads?stage=won`, но все 3 сделки уже в стадии «Клиент» (воронка: `won` нет). Ссылка откроет пустой список (`DashboardPage.tsx:62`). Метрика — события, фильтр — текущая стадия.
- 🟢 «Отложить» доступно любому менеджеру на чужом лиде: ни фронт (`leadActionRules.ts:49`), ни бэк (`services/leads.py:165-178`, нет `_require_owner`) не проверяют владельца. Это открытый P-25, отмечаю как ещё не закрытый.

## 5. Топ-10 рекомендаций

1. 🔴 **Убрать перекрытие заголовка кнопкой меню на мобильном**: гамбургер в шапку (`App.tsx:83`, свой Header). Затрагивает все экраны.
2. 🔴 **Ссылки дашборда — по правам**: плитку без доступа к цели делать некликабельной (`DashboardPage.tsx:70-71` + `allowed()`). Сейчас менеджер и наблюдатель попадают на 403.
3. 🔴 **Мобильный список лидов карточками** вместо таблицы на `xs` (`LeadsPage.tsx`). Это главный экран менеджера с телефона.
4. 🔴 **Вход в сервисные запросы**: колонка или фильтр во «Входящих» и ссылка «Открытый запрос» в карточке лида-клиента. В перспективе — список запросов со статусом «в работе» (`ServiceRequests.tsx`, бэк `clients.py`).
5. 🟡 **Мобильная карточка лида**: одно главное действие + «⋯», стадия и владелец в шапке, поле ответа закреплено внизу, Enter = перенос строки (`LeadDetailPage.tsx`, `LeadActions.tsx`, `ChatThread.tsx/.css`).
6. 🟡 **Цели касания ≥ 44 px на `xs`**: «Забрать» в очереди, «Отправить», «Закрыть» запроса, «Отвязать» (`InboxPage.tsx:33`, `ServiceRequests.tsx:46`).
7. 🟡 **Чужой лид — один баннер вместо четырёх серых кнопок**: «Лида ведёт Admin», без неактивных кнопок. «Передать коллеге» — по тому же правилу, что и остальные (`LeadActions.tsx:110`, `leadActionRules.ts`).
8. 🟡 **«Забрать» → сразу в карточку лида** из «Входящих». Перехват админом — не primary, а «Перехватить» (`InboxPage.tsx:37`, `LeadActions.tsx:91`).
9. 🟡 **Не уводить из лида после «Сделать клиентом»** (`MakeCustomer.tsx:31`): уведомление со ссылкой на клиента.
10. 🟡 **Профиль**: ссылка «Сменить пароль», подсказку про Telegram — только при `leads.take`, убрать дубль переключателя режима (`ProfilePage.tsx:25-26`). Отдельный текст 404 для неверного адреса (`RouteGuard.tsx:25`).
