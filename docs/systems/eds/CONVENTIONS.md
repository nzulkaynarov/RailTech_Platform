# Конвенции кода EDS, `apps/eds`
Статус: действует · Владелец: лид · Обновлено: 2026-10-26

Ты работаешь над **EDS** — сервисом электронного документооборота ансамбля RailTech (ADR-0015): письма и резолюции, служебные записки, заявления, отчёты,
общий движок маршрутов согласования, реестр и нумерация документов. Главный пользователь — **сотрудник** (директор, менеджер, бухгалтер, снабженец,
гл. инженер); приходит он через BFF Платформы (этап D). Клиентов и внешнего маршрута у сервиса нет. Это правила кода EDS; код ссылается на них как
`CONVENTIONS.md §N`. Состояние на 2026-10-26: каркас (E2) — вход, проекция сотрудников, шина, база, Docker, CI; домен (E3) — реестр, письма, документы, маршруты,
файлы ([`wave12-eds-c1.md`](../../runbooks/wave12-eds-c1.md), устройство — [`README.md`](README.md), «Домен»). Запуск и команды — [`README.md`](README.md).

## 2. Правила (нарушение = PR не принимается)

1. **Контракт раньше кода.** Эндпоинт — сначала в `eds.yaml`, событие — сначала схема и пример в `packages/contracts/events/` (в том же PR с обеих сторон). Расхождение с
   контрактом — вопрос архитектору, а не «своя версия».
2. **Интеграции только через шину** (`rt_bus`). Чужих баз и чужих REST-вызовов «в обход» нет; чужие данные — проекции, обновляемые событиями (ADR-0002, ADR-0015 п. 5).
   Единственная таблица-проекция сейчас — `employees`; пишет её только обработчик шины.
3. **Событие наружу — только из сервисного слоя, в той же транзакции**, что и изменение (`bus.publish(session, …)`): не из роутера, не после коммита. Откат — события нет.
   На каждую публикацию тест «откат → события нет».
   После коммита шина сама будит ретранслятор (`Container.bus`, `wakeup=tasks.wakeup`, B5a): доставка идёт за доли секунды, а не на тике `pump` (5 с). Новый процесс, который публикует события, вызывает `container.drain_bus()`, пока очередь открыта (тесты — `tests/test_bus_wakeup.py`).
4. **Права — данные.** Роли у EDS нет: права сотрудника — проекция `employees.permissions_eds` из `identity.user.*`; проверка на каждый запрос зависимостью
   `require_permission(*коды)` (любое из кодов, как `x-rt-permissions` в `eds.yaml`). Без неё в защищённых маршрутах нельзя; тест сверки с контрактом — `tests/test_contract_permissions.py`.
5. **Код решает, модель предлагает.** Нумерация, переходы, права, маршруты — детерминированная логика с тестами.
6. **Нумерация реестра — только EDS** (runbook §2.1): счётчик под `SELECT … FOR UPDATE` в транзакции создания, без пропусков; отменённый документ номер не возвращает.
7. **Секретов нет** в коде, тестах, фикстурах, документах, логах. Токены, подписи, пароли в записи журнала не попадают. Репозиторий временно публичный: демо-данные вымышленные.
8. **Внешнего маршрута нет.** Не добавляй EDS в Caddyfile и не публикуй порт в compose; тест `infra/deploy/tests/eds-prod-test.sh` это ломает намеренно.
9. **Тесты — часть задачи.** Поведение сначала воспроизводится тестом. База в тестах — настоящий PostgreSQL (маркер `pg`), не SQLite и не моки сессии.
10. **Документация — только в `docs/`** (ORCHESTRATOR §3 п. 17): `apps/eds` несёт указатели `CLAUDE.md` (≤ 25 строк) и `README.md` (≤ 15). Статус — в описании PR (`docs/PROGRESS.md` ведёт лид).

## 3. Стек и команды

Python 3.12 · uv · FastAPI · SQLAlchemy 2 (async, psycopg 3) · Alembic · Procrastinate · pydantic v2 / pydantic-settings · PyJWT · structlog · rt-bus, rt-contracts (по пути) ·
ruff, mypy `--strict`, pytest (+ pytest-asyncio). Команды — [`README.md`](README.md): `make check-eds` перед коммитом, один тест — `./scripts/with_pg.sh uv run pytest tests/<файл>.py -x -q`.

## 4. Соглашения кода

- **Слои:** `api` (роутеры, зависимости, схемы запросов/ответов) → `services` (операции в транзакции, события) → модели `models/`; `security/` — токены и права; `bus/` — обработчики
  входящих событий и сборка шины; `tasks/` — задачи Procrastinate. `api` не ходит в модели напрямую для записи.
- **Типы везде**, `mypy --strict` на весь `app/`, `tests/`, `alembic/`. Строка ≤ 120 символов (русские docstring не переносим).
- **Ошибки API** — один формат `Error` (`code`, `message`, `source="eds"`, `details`): `EdsError` из `app/errors.py`, коды из `eds.yaml` (`UNAUTHORIZED`, `INVALID_SSO_TOKEN`, `USER_NOT_PROVISIONED`,
  `USER_INACTIVE`, `FORBIDDEN`, `NOT_FOUND`, `VALIDATION_FAILED`, `CONFLICT`, `PAYLOAD_TOO_LARGE`, `UNSUPPORTED_MEDIA_TYPE`, `BAD_REQUEST`, `INTERNAL_ERROR`). Текст — сотруднику, не стек.
- **Логи** — `structlog`, только kwargs, без f-строк, без `print`; `request_id` (= `X-Request-ID`, = `correlationid` событий) добавляется автоматически.
- **Сессии:** `current_employee` читает проекцию своей короткой сессией; маршруты, которые пишут, берут `get_session` и открывают `async with session.begin()` сами.
  Один запрос — одна транзакция записи; событие шины — в ней же.
- **Входящие события:** обработчик регистрируется в `app/bus/handlers.py` (`build_registry`), выполняется в транзакции со статусом inbox, идемпотентен (повтор `event id` гасит inbox;
  «не применять более старое» — по `updated_at` снимка), читает `data` терпимо (лишние поля не ошибка). Тип подписки — строка `eds` в `subscriptions.yaml`.
- **Миграции Alembic:** одна голова (тест `test_single_head`), обратимые (`downgrade`), имена файлов `YYYYMMDD_HHMM_slug`, `revision` — выданный `alembic revision` (случайный id, не `00NN_…`; старые не переименовываются; две головы — `alembic merge heads`, ORCHESTRATOR §4.1), без дрейфа от моделей (тест `test_models_match_migrations`);
  таблицы `rt_bus_*` — только библиотечные (`bus_tables`), не править. Новая модель — в `app/models/__init__.py`.
- **Файлы:** ≤ 400 строк, функции ≤ 50; нет закомментированного кода и `TODO` без ссылки на задачу.

## 5. ADR

Формат MADR, `docs/adr/NNNN-slug.md`. Пишется для выбора библиотеки/сервиса, схемы данных, влияющей на несколько систем, протокола или политики безопасности и любого отклонения от
стратегии, ADR и контрактов — только через ADR и решение владельца.

## 6. Тесты и проверка

1. `unit` — без внешних сервисов (токены, снимки, формат ошибок); `pg` — на PostgreSQL: миграции, приёмник шины, проекция, вход, права. `make -C apps/eds test-unit` — секунды.
2. База в тестах — одноразовая (`scripts/with_pg.sh`, `postgres:17` в Docker, `tmpfs`); перед каждым `pg`-тестом таблицы очищаются. Стенд ансамбля не используется.
3. Мокай границы, не середину: HTTP наружу — `httpx.MockTransport`; шина — настоящий `AsyncBus` с подписанной доставкой (`tests/helpers.py`).
4. Перед коммитом — `make check-eds`; перед PR — `scripts/ci_local.sh eds` (и `infra`, `contracts`, если менялись compose/контракт). **CI не запускать и не опрашивать** (`CLAUDE.md` корня).
5. Проверка на стенде — только отдельный проект `-p rt-c1` со своим `.env` (не общий стенд владельца); после — `down -v`.
