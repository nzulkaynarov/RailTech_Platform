# Cabinet (кабинет клиента) — `apps/cabinet`
Статус: действует · Владелец: лид · Обновлено: 2026-10-31

SPA клиента RailTech Platform без собственного бэкенда (ADR-0004): все данные — ERP `/api/portal/v1/*`
(`docs/architecture/CONTRACTS.md` §4, схема `packages/contracts/openapi/erp-portal.yaml`). Один и тот же SPA открывается
как сайт `cabinet.railtech.uz` и как Telegram Mini App клиентского бота CRM. Правила кода — [`CONVENTIONS.md`](CONVENTIONS.md);
каналы клиента — `docs/product/SPEC-v3.md` §8.

Стек: React 18 · TypeScript · Vite 7 · Tailwind CSS 4 · shadcn/ui (примитивы из `apps/erp/frontend`) ·
React Query · react-router 7 · i18next (ru / uz — латиница / en) · openapi-typescript · MSW · Vitest + Testing Library + axe.

## Команды

```
make -C apps/cabinet install        # npm ci
make -C apps/cabinet dev            # http://localhost:5175 с моком портального API (VITE_PORTAL_MOCK=1)
make -C apps/cabinet dev-stand      # без мока: /api/portal → стенд (VITE_PORTAL_PROXY_TARGET, по умолчанию erp.localhost)
make -C apps/cabinet check          # eslint, tsc, i18n, токены, типы API, vitest + axe  (= make check-cabinet из корня)
make -C apps/cabinet build          # статика в dist/
make -C apps/cabinet gen-api-types  # src/api/portal.d.ts из erp-portal.yaml; src/api/crm-form.d.ts из OpenAPI CRM
```

## Оболочка и вид (редизайн 2026-10-31, работа над ошибками CAB-FIX-1…3)

Как устроено по коду; находки аудита и что из редизайна убрано — [`audits/2026-10-31-cabinet-ui.md`](../../audits/2026-10-31-cabinet-ui.md).

1. **Оболочка (`AppShell`).**
   - Рамка `bg-muted` (в Mini App — `secondary_bg_color` Telegram, если пары проходят AA), на ней холст `bg-background`
     со скруглением `rounded-2xl` и рамкой `border-border` от `md`; на телефоне холст — во всю ширину.
   - Слева от `md` — сайдбар `SideNav`: марка «RT · RailTech Cabinet», компания и право действовать из `GET /me`, разделы.
     Сворачивается кнопкой и сочетанием ⌘\ / Ctrl+\ (по `event.code === 'Backslash'` — и в RU-раскладке; в полях
     ввода не срабатывает; подсказка — ⌘ на Mac, Ctrl на Windows). Ширина 256 ↔ 64 px меняется одним шагом, без анимации
     (анимация ширины пересчитывала холст на каждом кадре). Состояние — `localStorage` `rt-cab-sidebar-collapsed-v1`.
   - На телефоне и в Mini App — нижняя навигация `BottomNav` (четыре раздела и «Ещё»), в шапке — плитка «RT».
   - Шапка (только веб): крошки — разделы ссылками, документ — номером из данных экрана (`PageHeader crumb`, `shell/crumbs.ts`:
     KP-…, Z-…, D-…), «Проект» — текстом (списка проектов у клиента нет); справа — профиль.
   - Наблюдатель (`can_act=false`) видит плашку «Только просмотр» и «Копировать ссылку» (только веб): копируется
     `origin + pathname` и обычные параметры, без `#…` (magic-токен, `tgWebAppData`) и без `tgWebApp*`, `token`, `startapp`,
     `utm_*`; ошибка буфера — сообщение словами. В Mini App кнопки нет.
   - Переходов между экранами с анимацией нет. Анимируются только цвет и тень, подъём `.portal-card` при наведении, спиннер
     и пульс скелетона; при «Уменьшить движение» в системе всё это мгновенно (`index.css`, `motion-safe:`).

2. **Палитра — тема `cabinet` в `packages/ui-tokens`** (CAB-FIX-2; `tokens.json` → `shadcnThemes.cabinet`):
   - Цвета — только значения семантических переменных shadcn: navy `--primary` (`#1f2e4a`), графит `--foreground`,
     рамка `--muted`, холст `--background`, активный пункт `--accent`, статусы `--success` / `--warning` / `--destructive` /
     `--info`. Компоненты пишут `bg-primary`, `text-muted-foreground`, `bg-success/10 text-success`…; своих имён и hex в коде нет.
   - Каждая пара «текст на фоне» светлой и тёмной (`.dark`) темы ≥ 4.5:1, значки и точки статуса ≥ 3:1 —
     `packages/ui-tokens/contrast.test.mjs`. `StatusBadge` — `border-X/30 bg-X/10 text-X`; neutral — `bg-muted text-muted-foreground`.
   - **Mini App** (`telegram/theme.ts`, CAB-FIX-3): цвет `themeParams` Telegram ложится на переменную, только если с ним все
     те же пары проходят AA (`lib/contrast.ts`); иначе остаётся наш токен. В стандартных темах Telegram ложатся фоны и текст,
     а `button_color` с белым текстом (4,1:1 и 3,6:1) и `hint_color` (≈ 4,2–4,4:1) не берутся — кнопки и подписи наши.
   - Все экраны (actor и viewer, 1440 и 390, таблицы и на 1280, uz и en, Mini App со стандартными светлой и тёмной темами
     Telegram) с axe — `npm run test:e2e:screens` (сводка, снимки и замеры скачков — `docs/screens/cab-fix-3`).

3. **Экраны и общие части.**
   - Клиенту сделка — **«Проект»** (SPEC-v3 §2: «Запрос» — заявка, «Проект» — после КП): «Проект D-48», «Этапы проекта»,
     колонка «Проект» (uz — «Loyiha», en — «Project»). Маршрут `/deals/:id` и код не переименовывались.
   - Этапы проекта «Запрос — КП — Договор — Оплата — Поставка и акт» считаются по **статусам** документов, не по их наличию
     (`lib/dealStage.ts`, правила — в его комментарии). Выделен один **текущий этап** — первый невыполненный (`aria-current`);
     остальные начатые — спокойно, с подписью «начато». Закрытый запрос — «Запрос закрыт», только выполненные этапы,
     без текущего: портал не говорит, выигран проект или отменён (BACKLOG B-CABFIX-2).
   - «Запросы» — один вид (таблица от `lg`, карточки ниже) и «Требует вашего решения» (`ActionRequiredWidget`: КП в сроке,
     договоры на согласовании, просроченные счета, акты к приёмке). Пока списки грузятся, на месте виджета — скелетон, а
     список показывается в одном кадре с виджетом: экран не прыгает (CLS 0). Наблюдателю виджет не призывает к действию:
     «Ждут решения компании», «Решает контакт с правом подтверждать». Канбана и переключателя видов нет; `?view=…` ведёт на список.
   - Статус КП в любом списке (КП, запрос, проект) — `QuoteStatusBadge`: «ждёт решения» с прошедшим сроком — «Срок истёк».
   - Деньги — одна функция `formatMoney` (`lib/format.ts`, правило Платформы): `48 600 000 сум`, `18 750 000,50 сум`,
     `12 500 USD`; uz — «so‘m», en — `48,600,000 UZS`. Разряды — неразрывным пробелом, цифры `tabular-nums` обычным
     шрифтом, в таблицах — по правому краю.
   - Полоса «Договоры · Счета · Акты» (`BillingNavTabs`) — навигация ссылками (`nav`, `aria-current="page"`) только на этих
     трёх экранах; на телефоне прокручивается вбок целиком. У «Документов» — свой фильтр по виду (`?kind=`), без полосы.
     Таблица счетов на 1280 помещается без прокрутки вбок.
   - «Компания» → «Изменить»: кнопка сохранения одна — в баре `UnsavedChangesBar`. Бар — последний элемент формы, подвал
     на всю её ширину, прилипает к низу окна (на телефоне — над нижней навигацией); место под него зарезервировано и без
     правок, поэтому форма не прыгает ни при первом символе, ни при сохранении или сбросе. Поле в фокусе не уходит под бар.
     «Сбросить» — с подтверждением, ⌘S / Ctrl+S — только при правках (подсказка не видна на телефоне); уход по ссылке меню,
     крошке или «Назад» — вопрос «Выйти без сохранения?» (`useBlocker`), закрытие вкладки — предупреждение браузера;
     «Закрыть» с правками спрашивает так же. На форме «Нового запроса» бара нет: отправка — необратимое действие с «Что произойдёт».
   - `PageHeader` — заголовок экрана с иконкой в плитке `bg-primary`, подзаголовком и действиями.
   - **«Я оплатил»** (B-CABFIX-1, SPEC-v3 §3.1 шаг 8, §8): у неоплаченного и неотменённого счёта (`lib/invoice.ts`
     `invoiceOpen`) — кнопка (только `can_act`) → диалог «Приложите платёжное поручение»: файл обязателен (PDF или
     изображение до 10 МБ, проверка до отправки; `FileField`), дата платежа (`DateField`, не позже сегодня), сумма (`parseAmount`: пробелы разрядов,
     запятая; больше нуля, два знака) и комментарий до 500 знаков — по желанию; «Что произойдёт» — «Менеджер проверит
     поступление и подтвердит оплату — статус счёта изменится». Отправка — `POST /uploads`, затем
     `POST /invoices/{id}/proofs {upload_id, paid_on, amount, comment}`. Под номером счёта — платёжки `Invoice.proofs` со
     статусом (`StatusBadge` сущности `proof`: «На проверке», «Оплата подтверждена», «Отклонена» с причиной) и тем, что указал
     клиент. В ERP платёжка — та же, что прикладывает менеджер (источник «Кабинет клиента»): вкладка «Платёжки на
     подтверждение» Платформы. Отклонять платёжки ERP пока не умеет (BACKLOG B-D24-7) — статус «Отклонена» не приходит.
   - **Комментарии к КП** (B-CABFIX-1): на карточке КП — лента `Quote.comments` (клиент: «Вы» или имя коллеги, менеджер —
     «Менеджер · имя») и поле с «Что произойдёт», пока КП ждёт решения (`POST /quotes/{id}/comments`, до 2000 знаков; 409 у
     решённого или истёкшего КП). Комментарий получает ответственный менеджер (карточка КП в Платформе и колокольчик); КП он
     не меняет. Наблюдателю — только лента.

## Проверка в браузере (мок)

1. `make -C apps/cabinet dev` → http://localhost:5175 — страница входа (DevTools → режим устройства 390 px).
2. «Войти»: любой e-mail → «Письмо отправлено» → «Открыть ссылку из письма (мок)» (`/auth/magic#token=demo`) → «Запросы».
   Только в dev-режиме с моком (`import.meta.env.DEV` и `VITE_PORTAL_MOCK=1`) под входом есть блок «Быстрый демо-вход»:
   «Войти как Заказчик» / «Войти как Наблюдатель». В прод-сборке, на стенде и в `make up` его нет.
3. Ссылки мока: `/auth/magic#token=viewer` — контакт без права действовать (`can_act=false`: нет «Новый запрос», плашка
   «Только просмотр», язык контакта uz); `#token=expired` — «Ссылка не действует» (410); `#token=forbidden` — «Доступ
   закрыт» (403); `#token=throttled` — «Слишком много запросов, попробуйте через час» (429).
4. «Профиль» — язык ru / uz / en, «Выйти». Сессия мока живёт в `sessionStorage` вкладки, **данные мока — в памяти
   вкладки**: перезагрузка страницы возвращает фикстуры (принятое КП снова «ждёт решения»).
5. `/auth/magic#token=empty` — компания без единого объекта: пустые состояния всех разделов.

## Проверка как Mini App

**Без Telegram (эмуляция).** SDK `telegram-web-app.js` читает параметры запуска из `#tgWebAppData=…`. В консоли
открытой вкладки dev-сервера:

```js
const data = new URLSearchParams({ user: JSON.stringify({ id: 42, language_code: 'ru' }), auth_date: '1760400000', start_param: 'deal_42', hash: 'demo' });
const theme = JSON.stringify({ bg_color: '#17212b', text_color: '#f5f5f5', hint_color: '#708499', button_color: '#5288c1', button_text_color: '#ffffff', secondary_bg_color: '#232e3c' });
location.href = '/#tgWebAppData=' + encodeURIComponent(data) + '&tgWebAppVersion=8.0&tgWebAppPlatform=tdesktop&tgWebAppThemeParams=' + encodeURIComponent(theme);
```

Ожидаемо: страницы входа и шапки сайта нет, тёмная тема Telegram (фоны и текст; кнопки и подписи — наши, если цвета
Telegram не держат AA), открыт «Проект D-42» (`start_param=deal_42`).
«Написать менеджеру» в Mini App вызывает `Telegram.WebApp.openTelegramLink` (в эмуляции вне Telegram SDK ничего не открывает — это ожидаемо).
Мок принимает любой `init_data`; содержащий `bad` → 401 («Не удалось войти»), `viewer` → контакт без права действовать.
SDK запоминает параметры в `sessionStorage` — для возврата в веб-режим откройте новую вкладку.

**В Telegram (тестовый бот).** Mini App требует HTTPS:

1. Туннель к dev-серверу: `cloudflared tunnel --url http://localhost:5175` или `ngrok http 5175`
   (домены `*.trycloudflare.com`, `*.ngrok-free.app` разрешены в `vite.config.ts`). К стенду —
   `cloudflared tunnel --url http://localhost:80 --http-host-header cabinet.localhost`.
2. В @BotFather у **тестового** бота: `/newapp` (или Bot Settings → Menu Button) → URL туннеля.
3. Откройте Mini App из бота (Telegram Desktop: Settings → Advanced → Experimental → Enable webview inspecting
   — DevTools). С моком вход проходит сразу; против стенда — после M2-ERP-01 (подпись `initData` проверяет ERP).
   Deep-link: `https://t.me/<бот>/<app>?startapp=deal_42`.

## Ансамбль

`make up` из корня: сервис `cabinet-web` (этот Dockerfile: Vite → nginx, `/health`), Caddy
`http://cabinet.localhost` — `/api/portal/*` → `erp-backend:8000` (до M2-ERP-01 — 404), остальное → `cabinet-web`.
Имя бота для сборки — `TELEGRAM_BOT_USERNAME` из корневого `.env`. Форма «Я новый клиент» ходит в CRM напрямую:
адрес — build-arg `VITE_CRM_URL` = `CABINET_CRM_URL` корневого `.env` (по умолчанию `http://crm.localhost:${HTTP_PORT}`),
CRM разрешает CORS на `/api/v1/leads/web*` только origin из `CABINET_ORIGIN` (`crm-api` в `infra/compose/base.yml`;
по умолчанию `http://cabinet.localhost`, `http://cabinet.localhost:${HTTP_PORT}`, `https://${CABINET_DOMAIN}`).
Прод: `CABINET_CRM_URL=https://crm.railtech.uz`, `CABINET_ORIGIN=https://cabinet.railtech.uz`.
`make dev-stand` без `VITE_CRM_URL` ведёт форму через прокси Vite на CRM стенда (`VITE_CRM_PROXY_TARGET`, по умолчанию `http://crm.localhost`).
