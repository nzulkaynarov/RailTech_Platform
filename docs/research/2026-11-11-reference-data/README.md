# Справочники: загрузка из файла, обновление из источника, один механизм на все домены
Статус: исследование; на решении владельца · Владелец: архитектор · 2026-11-11

Поручение владельца 2026-11-11: любой справочник загружается из файла (списком или по одной строке) или обновляется
через интеграцию; коды валют, стран, курсы и подобное публикуются открыто — руками их не выдумываем. Правила: сначала
исследование, потом план, потом работа; одна задача — один механизм; готовые поддерживаемые библиотеки; ничего не
зашито в код; ru и en — первыми, uz (латиница) — вторым; ИИ помогает, человек подтверждает; подписей на экране минимум.

Продолжает: [справочник как данные, §4.3](../2026-11-02-flexibility/4-settings-ia.md), [внешние системы Узбекистана,
§4.2 и §5](../2026-10-23-architecture/arch-research-uz-integrations.md), [ИИ по запросу](../2026-11-02-flexibility/5-ai-assist.md),
[документы и счета компании](../2026-11-11-documents-templates/README.md), строку B-EDSREG-1 [BACKLOG](../../BACKLOG.md),
[DECISIONS](../../DECISIONS.md) 2026-11-11 («ничего не хардкодить», «файл в модель — только извлечённый текст»).
Пометки: **[Ф]** — факт из кода или из самого источника (ссылка; «живой запрос» — проверено с этой машины 2026-11-11),
**[Ф-п]** — блог, форум, сторонний пересказ, **[П]** — наш вывод. Что проверить не удалось, сказано прямо.

## Коротко

1. **Сейчас три разных устройства справочников.** EDS и CRM отдают общий ресурс `/dictionaries/{kind}` с названиями на
   трёх языках. ERP хранит свои списки отдельно, с одним названием. Причины отказа в CRM лежат строками в настройках.
   Загрузки из файла нет ни у одного списка на экране «Настройки · Справочники». [Ф]
2. **Готовый образец уже есть в продукте** — «Каталог · Загрузка прайса»: шаблон → файл → «Проверить» (ничего не
   пишет) → отчёт → «Применить», второй путь — любой файл через ИИ. Его шаги берём для всех справочников. [Ф]
3. **ЦБ отдаёт больше, чем мы берём.** В том же JSON, откуда мы читаем курсы трёх валют, есть 74 валюты с цифровым
   кодом, номиналом и названиями ru, uz (латиница и кириллица), en. Номинал мы не читаем: у рупии он 10. [Ф]
4. **Список банков с кодами открыт, но только файлом.** ЦБ публикует xlsx «Филиалы коммерческих банков»: 324 кода
   (пять цифр), название банка и филиала, адрес, ИНН; листы на узбекском, русском и английском. API нет, адрес файла
   меняется при каждой публикации. [Ф]
5. **Страны и валюты ISO** — библиотека Babel (данные CLDR, лицензия BSD): названия на ru, uz (латиница) и en полные.
   pycountry (LGPL-2.1) даёт коды, но узбекских названий стран в нём 148 из 249, валют — нет. [Ф]
6. **МХИК/ИКПУ**: у tasnif.soliq.uz есть открытый JSON без ключа (код, названия ru и uz, единица, упаковки), но без
   документации и условий. В коде у нас МХИК не хранится нигде. [Ф]
7. **Проверка компании по ИНН** открытого описанного API не имеет: государственная услуга № 708 заявлена как
   бесплатная, технические условия не опубликованы. [Ф]
8. **Механизм [П]:** один ресурс справочника в каждом домене, шесть действий (список, выгрузка, проверка файла,
   применение, «Обновить из источника», состояние обновления); ключ строки — код; у строки видно происхождение;
   обновление из источника не трогает то, что владелец изменил руками.
9. **План — 10 PR** (§D). Первый — выгрузка и загрузка с проверкой для девяти списков экрана, только Платформа.

1. Экран один (`web/src/modules/admin/settings/DictionariesPage.tsx:33`), а данных три вида: ресурс `/dictionaries`

## B. Внешние источники

### B1. Центральный банк: курсы, валюты, банки

- **Курсы.** `GET https://cbu.uz/ru/arkhiv-kursov-valyut/json/` — без ключа. Живой запрос: 74 строки, поля `id`, `Code`
  (цифровой код ISO, «840»), `Ccy` («USD»), `CcyNm_RU`, `CcyNm_UZ` (латиница), `CcyNm_UZC` (кириллица), `CcyNm_EN`,
  `Nominal`, `Rate`, `Diff`, `Date` («11.11.2026»). У IDR `Nominal` = 10, то есть `Rate` дан за десять единиц. UZS в
  списке нет. [Ф]
- **Архив.** `…/json/all/2018-12-11/` — все валюты на дату, `…/json/USD/2025-01-10/` — одна валюта (живой запрос вернул
  курс на 10.01.2025). То же с `/xml/`. [Ф] [страница для веб-мастеров](https://cbu.uz/ru/arkhiv-kursov-valyut/veb-masteram/)
- **Условия.** Лимитов и условий использования на странице нет. Сказано: «Данная возможность создана для синхронного
  (автоматического) получения информации из сайта другими системами» и «При обращении без параметров, выдаются курсы
  прошлой недели» — при этом живой запрос без параметров вернул дату сегодняшнего дня. Расписания публикации нет. [Ф]
- **Банки.** Страница [«Филиалы коммерческих банков»](https://cbu.uz/ru/credit-organizations/banks/branches/) даёт
  файл `Filiallar_haqida_malumot.xlsx` (подпись ссылки — 03.09.2026). В нём четыре листа: узбекский латиницей и
  кириллицей, русский, английский. Столбцы русского листа: код филиала (5 цифр), признак (0 — подразделение ЦБ, 1 —
  головной офис, 2 — платёжный центр, 3 — филиал), наименование банка, наименование филиала, адрес, даты открытия и
  изменения, область, район, город, ИНН, сайт. Кодов 324: 18, 35, 14 и 257 по признакам. Названия банков — на узбекском
  во всех листах, адреса переведены. Шапка таблицы — в седьмой строке, даты — числами Excel. [Ф]
- [«Головные офисы»](https://cbu.uz/ru/credit-organizations/banks/head-offices/) — второй файл: краткое и полное
  название, номер и дата лицензии, адрес, ИНН, сайт; кода банка в нём нет. [Ф]
- Что «код филиала» — это МФО из нашей формы, в файле не написано; на самой странице у филиала стоят подписи «Код
  банка» и «МФО». [Ф] Сверить на счёте компании перед PR 7. [П] API списка банков и набора на портале открытых данных
  поиск не нашёл; адрес файла содержит случайную часть и меняется. SWIFT в файле нет. [Ф]

### B3. МХИК/ИКПУ и единицы для счетов-фактур

- Живой запрос без ключа: `GET https://tasnif.soliq.uz/api/cls-api/mxik/search/by-params?searchText=…&size=…&page=…&lang=ru`
  и `…/mxik/get/by-mxik?mxikCode=<17 цифр>&lang=ru`. В ответе: `mxikCode`, названия группы, класса, позиции,
  подпозиции, `mxikName`, `unitCode`, `unitName`, `internationalCode`, признаки `label`, `lgotaId`, и `packages[]` —
  упаковки с кодом, названием тары и единицей. С `lang=ru` названия русские, с `lang=uz_latn` ответ пришёл на
  узбекском латиницей; допустимые значения `lang` нигде не описаны. [Ф]
- Документации, условий и лимитов нет. Открытые клиенты ([mxik-js](https://azabroflovski.github.io/mxik-js), MIT) называют
  себя неофициальными. Прежнее исследование: адрес может не отвечать из-за рубежа; с сервера в Узбекистане отвечает. [Ф]
- Каталог ведёт центр при Налоговом комитете; полный каталог скачивается в Excel с сайта (прежнее исследование, §5.2). [Ф]
- Отдельного открытого перечня «коды единиц для ЭСФ» найти не удалось. Единица и упаковка приходят вместе с кодом
  МХИК, поэтому их правильно брать оттуда же, а не вести своим списком. [П]

- Вывод [П]: это не справочник, а заполнение карточки. Без письма в Налоговый комитет не делается. Вне этой волны.

### B5. Incoterms 2020 и единицы UN/ECE

## C. Что брать нам

### C1. Один ресурс справочника

Расширяем то, что уже работает у EDS и CRM, и подключаем к нему ERP. BFF по-прежнему держит каталог «вид → домен →
кто читает» и проксирует; решения принимает домен.

| Действие | Путь BFF | Кто исполняет |
|---|---|---|
| Список видов с описанием полей, источником и состоянием обновления | `GET /dictionaries` | домены, BFF склеивает (как сейчас) |
| Строки | `GET /dictionaries/{kind}` | домен |
| Выгрузка — она же шаблон (xlsx или csv; пустой список — шапка и строка-пример) | `GET /dictionaries/{kind}/export` | BFF из строк и описания полей |
| Проверка файла: что добавится, изменится, не изменится, где ошибка | `POST /dictionaries/{kind}/import?dry_run=true` | BFF читает файл, домен проверяет строки без записи |
| Применение ровно проверенных строк | `POST /dictionaries/{kind}/import` | домен, одна транзакция |
| «Обновить из источника» и состояние (когда, итог, сколько строк) | `POST`, `GET /dictionaries/{kind}/sync` | домен; есть только у видов с источником |

Столбцы файла одинаковы у всех видов: `code`, `name_ru`, `name_uz`, `name_en`, `active`, `position`, затем поля вида из
описания. Граница: справочник — до нескольких тысяч строк, правится руками. Классификаторы на десятки тысяч строк (ТН
ВЭД, МХИК, каталог товаров) через этот экран не идут: у них поиск, источник и фоновая загрузка, как у прайса.

### C2. Строка: ключ, происхождение, что перезаписывается

- **Ключ — код.** Код в файле есть и найден — строка обновляется. Кода нет — строка создаётся: у стран, валют,
  банков, единиц код задаёт файл, у списков EDS и CRM код создаёт домен из названия, как сейчас. Код не меняется.
- **Происхождение** (`origin`): `system` — строка, от которой зависит поведение кода; `integration` — пришла из
  источника; `file` — из загруженного файла; `manual` — введена на экране. Рядом `synced_at` и имя источника.
- **Источник обновляет:** названия на трёх языках и поля источника (цифровой код, номинал, alpha-3, адрес банка).
- **Источник не трогает:** «действует», порядок, поля владельца (ставка НДС, символ, флаги базиса) и любое поле,
  которое изменили руками. Изменённые поля строка помнит списком; кнопка «Вернуть из источника» его очищает.
- **Новая строка из источника приходит выключенной** (как валюты Odoo): владелец включает нужные.
- **Строка исчезла из источника** — не удаляется, получает метку «нет в источнике». Так уже сделано для ТН ВЭД.
- **Предохранитель:** если источник вернул заметно меньше строк, чем было, обновление отклоняется целиком (уже есть у
  ТН ВЭД — `MIN_EXPECTED_CODES`).
- **Ручная строка в списке с источником разрешена** — например, зарубежный банк без кода ЦБ.

### C3. Защита и журнал

- Использованную строку нельзя удалить ни с экрана, ни файлом: её выключают. Закрытый вид (поведение кода) файлом
  можно только переименовать и переставить. Оба правила уже есть, файл их не обходит.
- Каждая загрузка и каждое обновление — одна запись в журнале домена: кто, когда, файл или источник, сколько
  добавлено, изменено, пропущено, с ошибкой. Правки строк пишутся в журнал, как сейчас. Экран показывает последние
  записи по виду. Обновление из источника идёт через существующий выключатель и состояние внешних сервисов ERP
  (`external_call`, как у курсов ЦБ и ТН ВЭД в `master_data/tasks.py`).

### C4. Где помогает ИИ

Файл с нашей шапкой читается без модели. Если шапка чужая, человек нажимает «Сопоставить столбцы»: BFF передаёт
домену шапку и первые 20 строк текстом, домен вызывает модель через LiteLLM по алиасу (ERP — `enrich-model`, как у
прайса; трасса в Langfuse пишется шлюзом, метки `system`, `feature=dictionary_import`), модель возвращает только
«столбец файла → поле справочника». Человек видит сопоставление и правит его, строки проверяет код, запись — после
«Применить». В BFF модели нет ([5-ai-assist](../2026-11-02-flexibility/5-ai-assist.md) §4.2). Ещё одно применение —
подсказать недостающее название на втором языке в строке; тоже предложение, а не запись.

### C6. Чего не делаем

- Не пишем свой разбор xlsx и свой движок загрузки: openpyxl и django-import-export.
- Не разбираем файл в браузере: два разборщика и нет серверной проверки.
- Не заводим общую таблицу справочников на все домены: каждый домен хранит свои (инвариант «общих таблиц нет»).
- Не загружаем полные перечни «на всякий случай»: 2000 единиц Rec 20, весь МХИК.
- Не храним и не переводим тексты правил Incoterms.
- Не берём данные о компаниях с orginfo.uz и не разбираем чужие страницы там, где есть файл или API.
- Не даём обновлению из источника перетирать ручные правки и удалять строки.
- Не записываем ничего по ответу модели без подтверждения человека.
- Не делаем конструктор произвольных справочников: виды и их поля остаются закрытым списком в коде домена.
