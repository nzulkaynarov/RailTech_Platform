# Стандарт интерфейса B2B: разбор и заключение
Статус: заключение архитектора; принятое включено в стандарт и план по поручению владельца 2026-11-15 · 2026-11-15

Поручение владельца: изучить документ «B2B Enterprise UI/UX Constitution & Brand Book» (цвет, шрифт, сетка, окна,
таблицы, формы, поведение, чек-лист), провести своё исследование, добавить работы в план и приступить; порядок и
приоритет — за архитектором. Итог — [стандарт интерфейса](../architecture/ui-standard.md) и
[план](../history/runbooks/plan-2026-11-12.md) §3b. Пометки: **[Ф]** — факт из кода или расчёта, **[П]** — вывод.

## Коротко

Документ верен по существу, и большая его часть совпадает с уже принятыми правилами (одна главная кнопка, форма на 4+
полей не в окне, подписи над полями, скелет вместо спиннера). Платформа ближе к нему, чем кажется: общая таблица,
пастельные статусы, пустые состояния и форматтеры уже есть. Главные расхождения — палитра и цвета литералами в CSS,
окна поверх экрана с формами, разнобой ширин панелей, два набора значков, нет моноширинного шрифта для кодов. Три
пункта приняты с изменением (контраст приглушённого текста, шапка таблицы, высота контролов), один не принят (сетка
«8 и 4»).

## 1. Что проверено

- **Аудит кода** обоих фронтендов по одиннадцати правилам документа (ветка `main`, 2026-11-15): токены, тема, общие
  компоненты, счёт нарушений по файлам. [Ф]
- **Контраст** предложенных пар по формуле WCAG 2.1. [Ф]
- **Сверка** с действующими решениями: SPEC-v3 §5.2, [platform-frontend](../architecture/platform-frontend.md) §4–§5 и
  §9, правила Cabinet, решения 2026-10-31 и 2026-11-11. [Ф]

## 2. Контраст предложенной палитры [Ф]

| Пара | Отношение | Норма 4,5:1 |
|---|---|---|
| Основной текст `#0F172A` на белом | 17,85 | да |
| Вторичный `#475569` на белом / на холсте | 7,58 / 7,24 | да |
| Приглушённый `#94A3B8` на белом | 2,56 | **нет** |
| Шапка таблицы `#64748B` на `#F1F5F9` | 4,34 | **нет** |
| Статусы: нейтральный / в работе / ждёт / готово / отказ | 9,45 / 6,16 / 4,84 / 4,79 / 5,75 | да |
| Текст ошибки `#E11D48` на белом | 4,70 | да |
| «—» `#CBD5E1` на белом | 1,48 | знак, не текст |

Вывод [П]: `#94A3B8` годится для значков, отключённых элементов и «—», но не для ИНН второй строкой, кодов и
подсказок, как предлагает документ. Для приглушённого текста берём `#5F6F86`: ступень `#64748B` даёт 4,76:1 на белом,
но 4,34–4,37:1 на вторичной поверхности и фонах статусов (поймал тест контраста при внедрении, UI-2). Шапку таблицы набираем
вторичным цветом `#475569`.

## 3. Где мы сейчас [Ф]

| № | Правило | Платформа | Cabinet | Объём |
|---|---|---|---|---|
| 1 | Палитра slate | нет: серые AntD (`#1f1f1f`, `#595959`, `#d9d9d9`, `#f5f5f5`); около 670 цветов литералами в CSS, переменных нет | частично: цвета только из токенов (линтер), нейтральные свои | Платформа — большой, но механический; Cabinet — малый |
| 2 | Пастельные статусы | почти: `StatusTag` и общая карта, линтер запрещает цветной `Tag`; остались заливки шагов и бейджа меню | частично: фон и рамка через прозрачность, сплошной `Badge` по умолчанию | малый |

| 4 | Шаг 4 px, скругления, тени | частично: 131 из 1041 отступа вне шага; окно 8, не 12 | частично: карточка 12 и 16 с тенями | малый–средний |

Уже проверяет машина: запрет цветного `Tag`, своих карт статусов и литерала валюты; запрет родных `select` и полей
даты; контраст токенов; длина текстов; геометрия таблиц в e2e. Не проверяет: выбор окна или панели, набор значков,
число главных кнопок, `<table>` в модулях, цвета и размеры в CSS Платформы.

## 4. Решения по пунктам документа [П]

| Пункт | Решение | Почему |
|---|---|---|
| Палитра slate, холст, рамки | принято | спокойнее и единообразно для двух приложений; значения — в токенах |
| Приглушённый текст `#94A3B8` | **изменено**: текст — `#5F6F86` | контраст 2,56:1; наше правило и axe требуют 4,5:1 |
| Главный цвет | принято: главная кнопка — графитовая `#0F172A`, акцент — `#1D4ED8`; Cabinet сохраняет фирменный | близко к нынешнему `#1668dc`, контраст 6,7:1; фирменный цвет кабинета — решение 2026-10-31 |
| Пастельные статусы | принято | уже почти так; меняются значения токенов |
| Inter, JetBrains Mono для кодов | принято | коды и номера читаются и сверяются быстрее; один компонент `Code` |
| Шесть размеров шрифта | принято, кроме шапки таблицы | 13 px убирается; число сводки 28 остаётся |
| Шапка таблицы 11 px капсом | принято с цветом `#475569` (уточнено 2026-11-15 после проверки на экране) | жёстким препятствием был только контраст 4,34:1 у `#64748B`; с вторичным цветом — 6,9:1 |
| Шаг 4 px, скругления 6, 8, 12 | принято | совпадает с SPEC-v3, кроме окна (8 → 12) |
| Высота 36 px везде | **изменено**: Платформа 32 и 24, Cabinet 36 и 32 | 32 — «компактная» высота самого документа и высота AntD; плотность реестров; 36 — кабинету с телефоном |
| Lucide, 16 px | принято | сейчас два набора; значки внутри AntD остаются его |
| Одна главная кнопка | принято | уже правило; кнопка модуля в подменю становится обычной |
| Три вида окон | принято | совпадает с §4.1a; порог страницы — 15 полей |
| Ширины панели 480 и 640 | принято, заменяет 440 и 600 | сейчас десять ширин; разница с прежним решением — 40 px |
| Закреплённый подвал панели, защита от потери | принято | сейчас кнопки в конце формы, защита в 7 файлах |
| Таблицы: «…», панель выбора, две строки в ячейке | принято | одно частое действие строки может остаться кнопкой (§4.2) |
| Формы: поиск в длинном списке, единица в поле, ошибка под полем | принято | частично уже так |
| Четыре шаблона страниц | принято три; «8 и 4 колонки» — **нет** | противоречит правилу «панель поверх страницы, не сжимая её»; вопрос уходит в исследование областей экрана (шаг 6 плана) |
| «Только общие компоненты» и чек-лист | принято | добавляются проверки линтера |
| Файл в корне репозитория | **изменено**: документ в `docs/` | правило «документация только в `docs/`»; в `CLAUDE.md` приложений — ссылка |

## 5. Порядок внедрения [П]

Сначала то, что меняет всё разом и дёшево (переменные вместо литералов, затем палитра одной правкой токенов), потом
общие компоненты (окна, таблица, код), потом перенос экранов по модулям с проверками линтера, чтобы новое не
возвращалось. Перечень PR — [план](../history/runbooks/plan-2026-11-12.md) §3b.

Риски: правка CSS всех модулей конфликтует с открытыми экранными PR — идёт между их слияниями; снимки `docs/screens`
устаревают по цвету — переснимаются по мере правки экранов, не одной волной; перенос 25 окон в панели — самый долгий
шаг, идёт по модулю на PR.
