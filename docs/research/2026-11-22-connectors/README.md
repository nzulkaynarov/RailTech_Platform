# Коннекторы и интеграции: что подключить готовым, а что не трогать

> Исходные исследования по направлениям — [areas/](areas/), проверки критиков — [verify/](verify/). Страница для чтения владельцем опубликована отдельно; правда — этот файл.

Дата: 22.11.2026. В основе семь исследований: госсервисы, банки и платежи, учёт и 1С, логистика, связь, рабочие сервисы, закупки и данные о товаре. Их проверили два раза независимо: существуют ли заявленные API, и что с правом, санкциями и хранением данных. Все исправления по итогам проверок внесены. Чего подтвердить не удалось, помечено «не подтверждено».

Как читать оценки: **S** — один PR (один модуль работы), **M** — 2 PR, **L** — 4–6 PR. Системы: CRM (лиды, бот, почта, звонки), ERP (сделки, закупки, склад, деньги), EDS (документы и подписи), Платформа (экраны сотрудников), Кабинет (клиенты и партнёры).

## 0. Коротко

- **Самое крупное, что можно не строить самим, уже есть у бухгалтера.** «1С:Бухгалтерия для Узбекистана» умеет отправлять ЭСФ в Didox ([buxgalter.uz](https://buxgalter.uz/ru/publish/doc/text156636_otpravka_elektronnyh_schetov-faktur_v_didoks_stala_besplatnoy)) и получать выписки из 24 банков через DiBank ([dibank.uz](https://dibank.uz/)). Если у нас это уже работает, ERP не нужно самой выставлять ЭСФ и подключаться к банкам. Хватит передавать в 1С продажи и закупки, а оплаты читать из 1С. Сначала нужен разговор с бухгалтером (вопрос 3).
- **Закон о персональных данных смягчили.** С 27.03.2026 хранить в Узбекистане обязательно только биометрию, генетические данные и данные абонентов операторов связи ([lex.uz](https://lex.uz/ru/docs/4396428)). Остальные данные можно передавать в страны из перечня Кабмина № 415 ([lex.uz](https://lex.uz/ru/docs/8369688)):
  - в перечне есть Россия, страны ЕС и Великобритания;
  - США — только для компаний, которые участвуют в EU-US DPF;
  - Китая, Казахстана, ОАЭ и Турции в перечне нет.

  Правило «все ПДн граждан РУз — только в РУз» устарело. Три вопроса юристу остаются (§5).
- **До запуска — только действия без кода.** Это семь шагов (§3.1), в очередь фронта не добавляется ни одного PR.
- **Госзакупки — новый канал продаж.** Регистрация на xarid.uzex.uz бесплатная, нужна ЭЦП ([saby.ru](https://saby.ru/articles/tenders/zakupki_uzbekistana)). Уведомления приходят письмами в уже работающую «Входящую почту». Рынок скромнее, чем кажется по общим цифрам. 67% закупок железной дороги за квартал — капитальное строительство. Электронный магазин — 550 договоров на 39 млрд сум ([railway.uz](https://railway.uz/upload/iblock/7e2/mt2gmkxlksbgjtn6v3sujkzzweg7laiw.pdf)).
- **Лучший коннектор после запуска — Telegram Business.** Переписка менеджеров с клиентами в личном Telegram сама попадает в карточку клиента. Premium не нужен ([Telegram](https://core.telegram.org/api/bots/connected-business-bots)). Нужны согласие сотрудника и правило.
- **Оплаты перестанут вводить вручную.** Есть два пути: выписка из банка файлом по открытому стандарту 1С ([1С](https://v8.1c.ru/tekhnologii/obmen-dannymi-i-integratsiya/standarty-i-formaty/standart-obmena-s-sistemami-klient-banka/formaty-obmena/)) или чтение оплат из 1С. Публичных API у банков нет. Единый банковский API ЦБ появится не раньше 2027 года ([kun.uz](https://kun.uz/kr/63737784)).
- **Пять небольших доработок по одному PR:**
  - проверка контрагента по госреестрам и списку нарушителей по НДС;
  - номер E-Contract в заказе поставщику;
  - срок сертификата ЭЦП подписанта;
  - источник лида «тендер»;
  - прайс поставщика по ссылке.
- **Проверить уже сейчас.** Запасная модель ИИ (Gemini) должна работать на платном аккаунте Google. В бесплатном уровне Google запрещает присылать персональные данные и может использовать присланное ([условия](https://aistudio.google.com/docs/terms)).
- **Не подключаем:** эквайринг, других операторов ЭДО, OneID, платные карты, 2ГИС (санкционный риск), ЭТРАН, свою АТС, свой BI-сервер, n8n и похожие сервисы. Причины — в §3.4.
- **Закупки и данные о товаре.** Три находки:
  - Прайсы в PDF и фото сейчас уходят в модель файлом целиком. Это расходится с правилом 2026-11-11 «в модель — только текст со скрытыми ПДн» (долг B-CAT1-3). Docling у нас уже стоит и закрывает это за 1–2 PR.
  - Подшипники (ТН ВЭД 8482) и часть электрики входят в список CHP — товары, на которые ЕС, США, Великобритания и Япония обращают особое внимание ([EC](https://finance.ec.europa.eu/document/download/5a2494db-d874-4e2b-bf2a-ec5a191d2dc0_en)). Поставщик из ЕС без пункта «no re-export to Russia» в договоре их не продаст ([FAQ EC](https://finance.ec.europa.eu/system/files/2024-02/faqs-sanctions-russia-no-re-export_en.pdf)). Нужны флаг товара и пункт в шаблоне договора.
  - Всемирный банк публикует закупки открытым API без ключа: по запросу «railway» в Узбекистане нашлось 31 уведомление ([API](https://financesone.worldbank.org/api-explorer?id=DS00979)). Это лиды по ж/д проектам.

## 4. Что купить и подключить, а что держать у себя

**Берём готовое:**

- **Юридически значимое.** Didox (ЭДО), E-IMZO (подпись), Vakolat (доверенности). Без оператора и государственного ключа у документа не будет юридической силы. Если писать своё, получится только копия.
- **Учёт, налоги, зарплата.** Это 1С бухгалтера. Обмен с ней настраивает 1С-партнёр, а не мы.
- **Банки.** Используем открытый стандарт файла 1С и готовые библиотеки для разбора выписок. Позже — DiBank или API банка.
- **Связь.**
  - Telegram (Business, позже Gateway);
  - облачная АТС местного оператора;
  - Eskiz;
  - Яндекс 360: почта, календарь, видеовстречи.
- **Логистика.** DHL, агрегатор трекинга, Shipsgo, BTS. Словарь событий — по открытому стандарту DCSA.
- **Речь.** Распознавание через наш шлюз ИИ, для узбекского языка — Aisha.
- **Готовые библиотеки.**
  - календарь: [caldav](https://pypi.org/project/caldav/), [icalendar](https://pypi.org/project/icalendar/);
  - вход: [Authlib](https://pypi.org/project/Authlib/);
  - этикетки и сканер: bwip-js, barcode-detector;
  - чтение из 1С: python-1c-odata.

  Брать onec-odata нельзя: она требует Python 3.13, а ERP собрана на 3.12 ([PyPI](https://pypi.org/project/onec-odata/)).
- **Аналитика.** Excel у пользователя. Когда появится отдельный сервер — DataLens Open Source или Metabase.

**Держим у себя, и почему:**

- **Весь путь от лида до закрытия сделки, роли, Кабинет.** Это и есть наш продукт. Готовые CRM и ERP уже рассмотрели и отклонили.
- **Тонкие правила поверх готовых данных.**
  - Сопоставление оплаты со счётом. Отдельного готового движка нет: rekon заброшен с 2018 года ([PyPI](https://pypi.python.org/pypi/rekon)), остальные работают только внутри чужих ERP.
  - Отметка о проверке контрагента.
  - Статусы отправок.

  На каждое — один модуль.
- **Адаптеры к внешним сервисам за общими интерфейсами («оператор ЭДО», «трекинг») и экран «Подключения».** Тогда вендора можно сменить без переделки. Бренды остаются только в настройках, а все ключи и ссылки — в настройках, а не в коде.
- **Шина и связи между системами.** n8n, Activepieces и Camunda не берём, решения 2026-11-10 и 2026-11-21: лицензии, и вендор виден пользователю.

## 5. Риски

### 5.1 Закон о персональных данных

Что действует сейчас, по закону ЗРУ-547 в редакции ЗРУ-1125 ([lex.uz](https://lex.uz/ru/docs/4396428)) и ПКМ № 415 ([lex.uz](https://lex.uz/ru/docs/8369688)):

- **Хранить в РУз обязательно** только биометрию, генетические данные и данные абонентов операторов связи (ст. 27¹). Регистрировать в госреестре нужно только такие базы (ст. 20).
- **Передавать за рубеж можно** в страны из перечня. Основание — ст. 27¹ и ст. 15 закона. Формулировка «без разрешений и уведомлений» в постановлении относится только к автоматической передаче по международным соглашениям.
  - В перечне: Россия, ЕС, Великобритания, Корея, Япония, Гонконг.
  - США — только для компаний в EU-US DPF.
  - Нет в перечне: материковый Китай, Казахстан, ОАЭ, Турция.
- **Для стран вне перечня** стандартные договорные условия должны были утвердить, но акт не найден. Пока остаётся одно основание — согласие человека.
- **Утечка при передаче за рубеж.** Уведомить МВД нужно в течение 24 часов, подробности сообщить в течение 72 часов (п. 4 ПКМ 415). Значит, нужен регламент на случай инцидента.

### 5.2 Санкции

Списки OFAC, ЕС и Великобритании проверены по названиям 20–22.11.2026. Цепочку владения проверка не охватывала.

- **Яндекс.** Сам Яндекс в списках не значится. Под заморозкой в Великобритании с 16.06.2026 только «Яндекс Банк» ([UK](https://sanctionslist.fcdo.gov.uk/docs/UK-Sanctions-List.csv)), на Яндекс 360 это не влияет.
- **2ГИС.** Контролирует Сбербанк, а он в списке SDN. По правилу 50% OFAC это риск, поэтому 2ГИС не используем.
- **РЖД.** В США — ограничения только на долг и капитал, без блокировки ([OFAC](https://sanctionssearch.ofac.treas.gov/Details.aspx?id=34736)). В Великобритании — заморозка активов. В сводном списке заморозок ЕС РЖД нет.
- **ПАО «Трансконтейнер».** В списке SDN и под заморозкой ЕС с 28.06.2024. Если экспедитор везёт груз в его контейнерах, могут возникнуть проблемы с платежами через банки с западными корреспондентами. Цепочку экспедитора надо включить в проверку контрагента.
- **Российские сервисы.** Saby, Контур, Альта-Софт, ATI.SU в списках по названиям не найдены.
- **Западные сервисы** для РУз открыты: DHL, Shipsgo, Google. Anthropic поддерживает Узбекистан ([список стран](https://www.anthropic.com/supported-countries)).

### 5.4 Зависимость от вендора

- **Didox.** Оператор у нас один. Контрагенты у других операторов получают документы через роуминг, адаптер работает через общий интерфейс. Запасной оператор Faktura: его сайт с API 22.11.2026 не отвечал ([api.faktura.uz](https://api.faktura.uz/help/)).
- **MCP-серверы 360** — пока предварительная версия, формат может поменяться.
- **Сервисных приложений** у одной организации может быть не больше 20.
- **Расширение 1С.** При обновлениях 1С его поддерживает партнёр. Если что-то сломается, запасной путь — файлы.
- **Сервисы без официального API:** tasnif, калькулятор tarif.customs.uz, реестры налоговой. При каждом сбое — ручной ввод и ссылка, на чужих страницах обмен не строим.
