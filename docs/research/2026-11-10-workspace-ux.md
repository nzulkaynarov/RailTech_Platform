# Рабочее место: центр, панели, уведомления, таблицы, чаты
Статус: исследование; решения владельца приняты 2026-11-10 (раздел в конце) · Владелец: архитектор · 2026-11-10

Поручение владельца: понятно, где что использовать; документы и расчёты в центре, боковое окно вспомогательное; таблицы и секции настраиваются мышью, как в VS Code; определить внутренние чаты и право писать контрагенту.

## Что нашли

## Как сейчас в Платформе

- Боковое окно содержит действия: «Резолюция», «Согласовать», «Оплата», «Задание» расчёта. Это противоречит правилу «работа в центре» и SPEC-v3 §6.1.
- Единого компонента таблицы нет, настройка колонок не сделана. Ширина боковых окон — только два размера.
- Сообщения вызываются напрямую примерно в 94 файлах, общего правила нет.
- Чата внутри компании нет: на расчёте вместо чата подпись-заглушка. Заметка команде есть только в переписке с клиентом.
- Писать контрагенту (`leads.py`): отвечает только ответственный; занятую беседу забрать нельзя; **администратор обходит оба правила**. Свободную беседу забирает любой с правом «Забрать». Кабинет и Telegram — одна очередь.

## Предложение

### Правила зон

| Зона | Что в ней | Чего в ней нет |
|---|---|---|
| Рейл | Модули, «Создать», профиль | |
| Список | Подменю, список объектов | Работа с объектом |
| **Центр** | Документ, письмо, таблица расчёта, форма, все действия: подписать, согласовать, резолюция, оплатить | |
| Вспомогательная панель | Сведения, чат, история, связанные документы, подсказка | Кнопки решений и обязательные поля |

### Сообщения

| Что случилось | Где показываем |
|---|---|
| Ошибка поля или блока | У этого поля или блока |
| Итог моего действия | Всплывающее, 3–5 секунд, без кнопок |
| Проблема всей системы: нет связи, работы на сервере | Баннер вверху, один, до устранения |
| Необратимое действие | Окно подтверждения |
| Что-то произошло, можно посмотреть позже (Платформа и кабинет) | Колокольчик, с пометкой источника |
| От меня нужно действие | Главная · Задачи |

Событие и задача — разные вещи: колокольчик сообщает, задача требует.

### Единые окна

В любом модуле три вида страницы: **список**, **карточка объекта**, **документ**.

- Список: одна панель поиска и фильтров, одна таблица.
- Карточка: номер, статус, кнопки действий на одном месте, шкала шагов, вкладки в одном порядке.
- Документ: один просмотрщик откуда угодно, адрес по номеру документа.
- Документ всегда находится в разделе «Документы», у каждого объекта есть вкладка «Документы» с тем же списком, номер документа — ссылка везде, крошки показывают его дом.

### Настройка мышью

**К запуску.** Все разделители тянутся, панели сворачиваются, раскладка запоминается, есть «Сбросить». Таблица: ширина, порядок перетаскиванием, закрепление, скрытие колонок, плотность. Секции карточки сворачиваются и меняют высоту. Сначала сохраняем в браузере, на сервер у профиля — на бэкенд-этапе.
**После запуска.** Вкладки открытых документов, два документа рядом, перетаскивание панелей между зонами (dockview).

### Чаты

Внешнее общение живёт в карточке клиента или поставщика, ждущие ответа сообщения попадают в задачи ответственного.

| Кто | Что может |
|---|---|
| Ответственный | Пишет контрагенту |
| Сотрудник с доступом к карточке | Читает, оставляет заметку команде |
| Директор | Читает всё, передаёт ответственного |
| Администратор | Не пишет контрагенту: обход убрать |

Внутри компании — одна модель беседы: обсуждение на объекте (документ, проект, заявка) с заметками только для команды и личные сообщения между сотрудниками. Групповых каналов и звонков нет. Это сохраняет рабочие разговоры в корпоративном контуре, чего требует [контроль рисков](../product/BUSINESS-PROCESS.md). Меняет решение 2026-11-09 «внутренний мессенджер не делаем».

## Решения владельца 2026-11-10

Приняты рекомендации: внутри компании — обсуждения на объектах и личные сообщения; настройка мышью — объём «к запуску», вкладки и перетаскивание панелей — после запуска. Остальное в этом документе — по рекомендации.
