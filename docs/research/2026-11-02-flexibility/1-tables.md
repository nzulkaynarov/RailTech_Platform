# Ресёрч 1. Ширина столбцов таблиц: Платформа и Cabinet

Дата: 2026-11-02 · основа: `main` @ 442b7a87e · только чтение кода, сборки и тесты не запускались.
Пути Платформы ниже даны от `apps/platform/web/src/`, пути Cabinet — от `apps/cabinet/src/`.

## 1. Как столбцы задаются сейчас и откуда берётся эффект

**Платформа: ширины фиксированы намеренно.** Так решили в UX-1c (#337) по находке S9 аудита 2026-10-30. Аудит
(`docs/audits/2026-10-30-platform-ui.md:69`) зафиксировал, что «колонки по содержимому» двигаются при смене фильтра и
страницы. Лекарство записали в инвариант 6 (`docs/architecture/platform-frontend.md:157,172-173,213`; ORCHESTRATOR §3,
стр. 81): «колонки рабочих таблиц фиксированы».

Механизм:
- `shared/ui/data-block.css:87-94` — класс `.pf-fixed-table` задаёт `table-layout: fixed; width: 100%`. У **всех** `th` и
  `td` стоит `overflow-wrap: anywhere`: текст переносится в любом месте, даже посреди слова, и в заголовках тоже.
- `data-block.css:96-100` — у тега статуса принудительно `white-space: normal !important`. В узком столбце статус
  переносится на две строки. Сам `StatusTag` задаёт `nowrap` (`shared/ui/StatusTag.tsx:50`), но CSS это перебивает.
- `data-block.css:102-106` — класс `.pf-ell` (одна строка с многоточием) включён вручную только в 14 ячейках. Полный
  текст показывает только атрибут `title`: на сенсорном экране и с клавиатуры его не увидеть.
- `shared/ui/DataBlock.tsx:162-175` — `TableCols` строит `<colgroup>` из массива: px или `null`. `null` — «гибкий» столбец,
  он забирает весь остаток ширины.
- `shared/ui/tableWidth.ts:2-4` — `tableMinWidth` даёт `minWidth = Σpx + flexible`. Если места меньше, таблица
  прокручивается вбок внутри `ScrollRegion` (`shared/ui/FormParts.tsx:43-49`, `form-parts.css:57-60`).
- Ширины подобраны вручную на каждом экране, константой `COLS` (перечень — §2). Типов столбцов нет. Единственный шаг к
  типам — «число = 130 px» в `modules/erp/catalog/common.tsx:30-32`.

**Почему получается то, что видит владелец.** Рабочая область при 1440 px: 1440 − рейл 56 − подменю 208 − отступы 48 ≈
**1128 px**; при 1920 px — ≈ **1608 px** (размеры каркаса — `platform-frontend.md:96-98,110`).
1. *Узкий столбец, текст переносится.* Px-столбец не растёт ни при каком экране. Например, «Корреспондент» во входящих —
   170 px (`modules/eds/inbox/InboxList.tsx:32`). «ООО «…темир йўллари»» в нём разбивается на 2–3 строки, причём из-за
   `anywhere` рвёт и слова. Так же переносятся заголовки и статусы.
2. *Мало текста, а столбец широкий.* Весь излишек экрана уходит в `null`-столбец. При 1920 px «Тема» входящих получает
   1608 − 1070 = **538 px**, хотя короткие темы занимают 150 px. Px-столбцы под короткие значения тоже стоят с запасом:
   «Действие» — 170 px под кнопку «Открыть» (`LeadsPage.tsx:52`), дата — 110 px.
3. *Прокрутка вбок на обычном ноутбуке.* Входящие требуют 1070 + 240 = **1310 px**, это больше 1128, поэтому даже при
   1440 px таблица уезжает вбок (`InboxList.tsx:143`). Если окно закреплено рядом (440 px), остаётся ~688 px: почти все
   списки уходят в прокрутку, а гибкий столбец сжимается до своего минимума.
4. Пользователь ничего не может изменить: ручной смены ширины, подгонки по содержимому и скрытия столбцов нет ни в одной
   таблице.

Вывод: беда не в самом `fixed`, он нужен ради инварианта 6. Беда в том, что ширины подобраны вручную в px, а не по типу
данных. К этому добавляются глобальный `overflow-wrap: anywhere`, отсутствие верхнего предела у гибких столбцов и
отсутствие ручной настройки.

**Cabinet: противоположная модель.** `components/ui/table.tsx` (shadcn) использует `table-layout: auto`, контейнер
`overflow-x-auto` (стр. 9-12), а у **всех** `th` и `td` стоит `whitespace-nowrap` (`table.tsx:73,86`). Ширину диктует содержимое, поэтому столбцы прыгают от страницы к странице. Длинная строка растягивает таблицу, и
появляется прокрутка вбок: так возникла находка K13, «таблица счетов на 1280 прокручивается вбок»
(`docs/audits/2026-10-31-cabinet-ui.md:56`). Переносится только заголовочный столбец: `min-w-48 whitespace-normal`
(`components/ResponsiveList.tsx:98`).

**Что сложилось как стандарт бизнес-таблиц** (общее у Fiori, Salesforce, AG Grid и Jira):
1. Ширина по умолчанию вычисляется из **типа данных** с нижним и верхним пределом, а не подбирается в px на каждом экране.
2. Числа и суммы — по правому краю, `tabular-nums`, без переноса. Заголовок выравнивается так же, как данные (MD2,
   Polaris, Pencil & Paper).
3. Короткие значения (статус, лицо, номер) — в одну строку с многоточием и подсказкой. Длинный текст переносится **по
   словам**, не больше N строк (Salesforce: обрезка по умолчанию, перенос по выбору).
4. Ширину можно менять вручную; двойной щелчок подгоняет по содержимому; ширина запоминается для пользователя и
   представления; есть «Сбросить».
5. Видимыми столбцами управляет сам пользователь (ProTable, Jira, Linear); плотность — 2–3 уровня.
6. На телефоне — карточки или pop-in для списков, прокрутка вбок с закреплённым первым столбцом для таблиц сравнения.

## 4. Рекомендация

### 4.1 Стандарт «тип столбца → правило»

Ширина по умолчанию зависит только от типа, а не от данных на странице. Поэтому инвариант 6 (столбцы стоят на месте при
смене фильтра и страницы) сохраняется. Так же устроены Fiori (по метаданным) и Salesforce (`fixed` по умолчанию).

| Тип | По умолч. / мин. / макс., px | Растёт | Выравнивание | Перенос |
|---|---|---|---|---|
| `id` — номер документа (`DocNumber`) | по формату номера (~128) / =умолч. / 160 | нет | лево, `tabular-nums` | нет (`nowrap`) |
| `date` / `datetime` | 104 / 96 / 120 · 148 / 140 / 168 | нет | лево | нет |
| `money`, `qty`, `percent` | 136 / 96 / 200 | нет | **право**, `tabular-nums`, заголовок тоже | нет |
| `status` (тег) | по самой длинной подписи словаря в ru, uz, en / =умолч. / 220 | нет | лево | нет: многоточие и подсказка |
| `person` (ответственный, исполнитель) | 176 / 120 / 240 | нет | лево | 1 строка, многоточие и подсказка |
| `name` (клиент, контрагент, товар) | гибкий, вес 1 / 200 / 360 | да | лево | до 2 строк по словам, затем многоточие |
| `text` (тема, описание, «что нужно») | гибкий, вес 2 / 240 / 560 | да | лево | до 2 строк по словам, затем многоточие |
| `action` (кнопки строки) | по кнопке / =умолч. / 160 | нет | право | нет |
| `icon` / флаг | 48 / 48 / 48 | нет | центр | — |

Общие правила:
- Убрать глобальный `overflow-wrap: anywhere` (`data-block.css:93`). Оставить его только для `text` (`break-word`), где
  длинный URL или артикул не должен разрывать таблицу.
- Заголовок — `nowrap`, длинный обрезается многоточием с подсказкой (MD2).
- Излишек ширины делится между гибкими столбцами по весам, но не дальше их предела. Если и после этого остаётся место,
  его получает последний гибкий столбец. Это `flex` + `maxWidth` из AG Grid.
- Подсказку показывать через antd `Tooltip` (доступен с клавиатуры), а не через `title`.

### 4.2 Единый компонент `DataTable` (Платформа, `shared/ui/DataTable`)

- **Поведение по умолчанию:** `columns: { key, title, type, render, weight?, width? }`. Ширины считаются по §4.1 в чистой
  функции (заменяет `tableMinWidth` и `TableCols`) и выводятся в `<colgroup>` при `table-layout: fixed`. Разметка остаётся
  прежней (`caption`, `ScrollRegion`, `pf-col-num`), поэтому `stable-data.spec.ts` и axe продолжают работать.
- **Ручная ширина:** ручка на правой границе заголовка. Двойной щелчок подгоняет по видимым строкам, как в Fiori и AG
  Grid. С клавиатуры ручка — `role="separator"` со стрелками (WAI-ARIA APG, Window Splitter); такую клавиатурную смену
  ширины уже поддерживает Fluent DataGrid. Ширина меняется только действием пользователя, поэтому инвариант 6 не нарушается.
- **Хранение — на пользователя, в `localStorage`.** Ключ `rt-pf-tables-v1`, запись `<пользователь>|<id таблицы>`, по
  образцу `rt-pf-panels-v2` (`platform-frontend.md:135`). В меню заголовка — «Сбросить ширину». Сервер не нужен:
  BFF по архитектуре без БД. Синхронизация между устройствами — после пилота, если о ней попросят.
- **Видимые столбцы:** кнопка «Столбцы» над таблицей, у каждого столбца флажок; обязательный первый столбец снять нельзя.
  Выбор хранится в той же записи (модель ProTable `columnsState` без самого ProTable). Порядок и плотность — после пилота.
- **Телефон 390 px:** у списков остаются **карточки** — они уже есть почти везде (`LeadsList`, `DataList`,
  `ResponsiveList`), и NN/g советует карточки для просмотра по одной записи. Таблицы сравнения (строки КП и расчёта,
  матрица ролей, расходы ИИ) — **прокрутка вбок с закреплённым первым столбцом** (`position: sticky`) и тенью на краю
  (NN/g). `DataTable` получает проп `mobile="cards" | "scroll"`.
- **Cabinet:** те же типы в `ResponsiveList`. В `ListColumn` добавить `type`, а `whitespace-nowrap` и `min-w-*` задавать
  по типу; таблицу перевести на `table-fixed` с `<colgroup>`. Ручная ширина Cabinet не нужна: у клиента 1–5 записей и
  4 экрана (Carbon: таблице — максимум ширины, без лишних элементов).

**Движок:** собственный хук `useColumnLayout`, на нём ширины, ручная настройка и хранение (~150 строк), без новой
зависимости. Если после пилота понадобятся сортировка, порядок и видимость на многих экранах, состояние можно перевести
на TanStack Table (headless, наша разметка сохраняется).

### 4.3 Отвергнутые варианты

| Вариант | Почему нет |
|---|---|
| Вернуть `table-layout: auto` (ширина по содержимому) | Нарушает инвариант 6 и снова даёт S9: столбцы прыгают при смене фильтра и страницы. В Cabinet это уже дало K13. Salesforce держит `fixed` по умолчанию |
| Перевести все экраны на antd `Table` / ProTable | Resize в antd не встроен (нужен `react-resizable`). `ellipsis` принудительно включает `fixed`, а `minWidth` работает только при `auto`, то есть пределы и многоточие несовместимы. ProTable не хранит ширину, а в нашей версии открыт баг персистентности #9688. Переписывать 16 экранов перед пилотом рискованно |
| AG Grid / MUI DataGrid | Тяжёлая зависимость (Enterprise платный), свой вид, которого нет в токенах `ui-tokens`, своя доступность. Это табличный редактор, нам столько не нужно |
| Хранить ширины на сервере | BFF без БД, понадобился бы контракт и домен-хранитель. Jira и Airtable хранят в представлении, но у нас нет сущности «представление» |
| Прокрутка вбок вместо карточек у всех списков на телефоне | NN/g: прокрутка «терпима» только для сравнения; карточки уже сделаны и проверены снимками 390 px |
| Перенос «как получится» (`anywhere`) везде | Рвёт слова и заголовки. Эталоны дают многоточие или перенос по словам с лимитом строк |

### Риски
- **Инвариант 6.** Любое «по содержимому» без действия пользователя возвращает сдвиги. Подгонка — только по двойному
  щелчку; `stable-data.spec.ts` (геометрия столбцов ±2 px) должен остаться зелёным.
- **Снимки и e2e.** T1 меняет вид 16 экранов, поэтому нужны новые снимки `docs/screens/...` и проверка axe. Текст
  заголовков с многоточием должен оставаться доступным (`aria-label` или полный текст в DOM).
- **Сохранённая ширина устаревает,** когда меняется набор столбцов. Нужна версия ключа и сброс неизвестных столбцов (по
  урокам ProTable #8260 и #9688).
- **Доступность ручки** (фокус, стрелки, сенсорный экран) обязательна, иначе axe и WCAG 2.5.7 (перетаскивание должно иметь
  альтернативу).
- **Узбекские подписи** длиннее русских, поэтому статус и заголовки надо мерить по ru, uz и en.
- Экраны, которые параллельно правят P8b и D2, будут конфликтовать с T1 при слиянии; сливать последовательно.
