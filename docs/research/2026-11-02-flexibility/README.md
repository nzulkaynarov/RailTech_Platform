## 2. Общий стандарт — пять правил по эталонам

1. **Значения — данные, поведение — код из закрытого списка.** Бизнес настраивает виды, причины, сроки, шаги, шаблоны,
   тексты; набор действий и переходов остаётся кодом. Так у Odoo, Jira, Bitrix24, Directum RX (§4.3 отчёта 4).
2. **Шаблон + выбор при запуске + правка на месте + снимок.** Шаблон маршрута с версией по виду документа; подбор по
   простым условиям (сумма, вид, контрагент); инициатор или решающий добавляет или убирает участника, срок, параллель;
   запущенный маршрут хранит свою копию. Без BPMN-холста: 1С:ДО 3.0 и Directum RX сами ушли к табличным правилам
   (отчёт 2 §3–4).
3. **Действие контрагента может записать сотрудник — штатный второй путь.** Канал, кто со стороны контрагента, когда,
   комментарий, вложение там, где есть документ; значок «внесено сотрудником» и журнал; дальше та же цепочка, что при
   онлайн-действии. ЭЦП и ЭСФ «за него» — нельзя (ЗРУ-793). Так у Zoho, HubSpot, Salesforce, Odoo, Stripe (отчёт 3 §3).
4. **ИИ по запросу, утверждает человек.** Одна точка вызова, 3–5 готовых действий, предпросмотр с «Вставить / Ещё
   вариант / Отмена», метка ИИ, источники, наружу ничего само не уходит, журнал решений и метрика принятия. Так у Gmail,
   M365 Copilot, Intercom, Zendesk; принципы Microsoft HAX и Google PAIR (отчёт 5 §3).
5. **Интерфейс — лаконичность и логика.** Индекс настроек одной страницей с поиском, 5 групп по задачам, не глубже двух
   уровней; подписи до 60–90 знаков, всё длиннее — в справку «?»; «Что произойдёт» — только у переходов состояния и
   опасных действий. Таблица: ширина по типу столбца (номер, дата, сумма, статус…), ручная ширина и запоминание на
   пользователя, двойной щелчок — по содержимому. Так у Shopify, Stripe, Linear, SAP Fiori, Salesforce, Jira; NN/g
   (отчёты 1 и 4).

## 5. Риски

- **Инвариант 6 (столбцы не прыгают):** подгонка по содержимому — только действием пользователя; `stable-data.spec.ts`
  остаётся зелёным.
- **Дубли настроек не убрать одним фронтендом:** реквизиты, валюта, рабочие часы живут в разных доменах —
  объединение только через контракт и шину.
- **Злоупотребление «за контрагента»:** журнал с атрибуцией, выборка «Отмечено сотрудником» на гейте, уведомление
  директору и позже — контрагенту.
- **ИИ:** галлюцинации чисел в официальных письмах (числа и реквизиты ставит код), prompt injection из входящих писем
  (у помощника нет записывающих действий), «резиновая печать» (метка и метрика правок), низкие дневные лимиты провайдеров.
- **Маршруты:** тупик, если у роли нет держателя (проверка при активации шаблона), пересечение условий (явный
  приоритет), обход обязательного согласующего (убрать может только админ).
