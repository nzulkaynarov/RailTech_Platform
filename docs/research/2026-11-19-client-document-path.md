# Что получает клиент: от письма с КП до кабинета

Дата: 2026-11-19 · Автор: архитектор · Основание: заметки владельца 2026-11-19 после теста на проде (КП ушло клиенту,
клиент нажал «Принять», письмо с кодом попало в спам, в письме чужие данные, ссылка «в Telegram» ведёт в кабинет) и его
идея: ссылка из письма открывает документ в кабинете, действия — по коду, код — он же вход · Решение владельца:
рекомендации приняты ([DECISIONS](../DECISIONS.md) 2026-11-19) · Решение — [ADR-0030](../adr/0030-cabinet-entry-by-document-link.md),
место в очереди — [план](../history/runbooks/plan-2026-11-12.md) §4.0a (СЦ-4) и §4.4 (ДК-1…ДК-5)

## 1. Что клиент получает сейчас

Проверено по коду `main` и журналу писем прода (только чтение; тест владельца — письма 37–39 от 2026-11-19).

| Шаг | Что приходит | Что не так |
|---|---|---|
| КП отправлено | письмо `quote_sent` с PDF и кнопкой «Открыть предложение онлайн»; при привязанном Telegram — сообщение бота | кнопка ведёт на служебный адрес ERP `/api/v1/public/quotes/<токен>/`, а не в кабинет |
| «Принять» на странице | письмо `quote_acceptance_code`: код, 15 минут, 5 попыток | код стоит в теме письма; письмо попало в спам |
| Принято | письмо `quote_accepted_contact`: «менеджер свяжется» | нет ссылки и следующего шага |
| Договор, счёт, оплата, акт, поставка | уведомление `portal_notice` со ссылкой в кабинет | уходит только приглашённым и уже входившим контактам (`portal/services/notices.py`, причина `not_invited`); клиент без кабинета не получает ничего |

Ещё находки:

- **Чужие данные в письме.** В подвале каждого письма — `support@example.com`: адрес поддержки на проде не был задан
  (`SystemSetting.support_email`), а значение по умолчанию — заглушка. Исправлено 2026-11-19: `support@railtech.uz`.
- **«Получать мгновенно в Telegram»** ведёт в «Профиль → Уведомления» кабинета и требует входа; клиенту без кабинета
  ссылка не работает.
- **Спам.** SPF, DKIM и DMARC (`p=none`) у домена `railtech.uz` опубликованы. Вероятные причины: код в теме, почти пустое
  тело, адрес с доменом `example.com` в подвале, второе письмо тому же адресату через шесть минут. Точная причина — в
  заголовках письма (нужна пересылка «как вложение»).
- **Вид писем** — свой шаблон ERP (`templates/emails/base.html`), не стандарт документов §8 (ДОК-7).
- Письма `invoice_issued`, `payment_reminder`, `act_awaiting_acceptance` адресованы участникам компании-покупателя в ERP
  (`buyer_team_user_ids`, прежняя модель). Клиенты теперь — контакты (СУЩ-2), участников у их компаний нет: эти письма
  уходят в пустоту, клиента о счёте и акте извещает только `portal_notice`.

## 2. Как это решают другие

- **Сервисы подписания** (DocuSign): ссылка в письме открывает документ, личность получателя подтверждает код доступа
  или SMS; пересылка письма — известный риск, от него защищает именно второй шаг.
- **Счета** (Stripe): у счёта своя страница по ссылке без входа; управление — в портале клиента со входом по коду из
  почты.
- **Рекомендации по ссылкам входа**: ссылка из письма — ключ на предъявителя; ею открывают малорисковое, а действия с
  последствиями требуют второго шага; срок жизни короткий, ссылка привязана к адресату.

Половина этой схемы у нас есть (ссылка на просмотр и акцепт по коду). Нет второй половины: подтверждение кодом не
становится входом в кабинет, и после акцепта клиент остаётся без следующего шага.

## 3. Решение

[ADR-0030](../adr/0030-cabinet-entry-by-document-link.md): одна ссылка документа ведёт в Кабинет; гость видит только этот
документ; любое действие требует кода с адреса получателя; код — вход в кабинет контакта; права не расширяются; получатель
документа получает дальнейшие уведомления; партнёры — вторым шагом.

Переадресация `support@railtech.uz` — на `info@railtech.uz`: это ящик, который Платформа читает как общий (33 из 41
входящих писем прода адресованы ему), вопрос клиента попадает в очередь «Почта» первой линии.

## 4. Порядок работ

| № | Что |
|---|---|
| СЦ-4 | Ошибки писем сейчас: код не в теме; строка поддержки без заглушки; ссылка про Telegram — только тому, у кого есть кабинет; письмо «Принято» — со следующим шагом и ссылкой |
| ДК-1 | Гость по ссылке в Кабинете: КП, ссылка на получателя, отзыв и срок; старые ссылки ERP перенаправляются |
| ДК-2 | Код — вход: диалог кода на действиях, сессия контакта, оферта при первом подтверждении |
| ДК-3 | Договор, счёт, акт, поставка, письмо — по той же схеме, одно письмо с PDF и кнопкой; уведомления получателю документа |
| ДК-4 | Telegram: код и ссылка в бот, если он привязан |
| ДК-5 | Партнёры: запрос цены и заказ |
