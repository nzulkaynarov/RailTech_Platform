## 2026-10-12 — пакет ответов (Q-009 … Q-013, Q-019)

### Q-010. Уведомление менеджеру о новом сообщении его лида — вариант (а) + браузер

**Решение:** личное сообщение от бота ответственному менеджеру в Telegram (без кнопок, со ссылкой на
карточку в CRM). Правило docs/systems/crm/CONVENTIONS.md §11 «никаких других действий в Telegram» уточнено: личные уведомления
менеджеру — разрешены, действия с лидом — по-прежнему только кнопка «Забрать» в канале и CRM.
Дополнительно рассмотреть звук и уведомления в браузере.

**Оценка агента (звук и браузер):**
- Звук и системное уведомление браузера (Notification API) при открытой вкладке CRM, даже свёрнутой, —
  дёшево: событие уже приходит по SSE. Нужны: переключатель «Звук» в профиле, разрешение браузера по
  клику пользователя, только для своих лидов и новых передач. **Рекомендация: делать вместе с (а).**
- Настоящий Web Push при закрытом браузере — service worker, ключи VAPID, таблица подписок, HTTPS (на
  prod есть). Дублирует личное сообщение в Telegram. **Рекомендация: не делать, пока Telegram справляется.**

Отражено: docs/systems/crm/CONVENTIONS.md §11; бэклог в `docs/PROGRESS.md`.

### Q-011. Контакты клиента — вариант (а)

**Решение:** таблица `client_contacts` (имя, должность, телефон, email) в карточке клиента.
**Вопрос владельца:** почему не берём контакты лида из Telegram?
**Ответ:** берём всё, что Telegram отдаёт без спроса: имя, `@username` (если он есть — у многих его нет)
и id; это видно в карточке лида. Номер телефона Telegram боту **не передаёт** — только если человек сам
нажмёт кнопку «Поделиться номером» (`request_contact`). Сейчас бот такую кнопку не показывает, а
присланный контакт сохраняется только текстом в переписке. Предложение — новый вопрос **Q-020**.

### Q-012. Язык интерфейса CRM — вариант (а) с заделом

**Решение:** CRM пока на русском. Мультиязычность должна оставаться возможной: все тексты интерфейса —
только через словари `frontend/src/i18n/`, без строк в компонентах; при добавлении uz/en — словари той же
структуры и переключатель в профиле. Тексты бота — по-прежнему ru/uz/en.
Отражено: docs/systems/crm/CONVENTIONS.md §11.

### Q-013. Сделка как отдельная сущность — по бенчмарку

**Решение:** владелец доверил выбор бенчмарку (Pipedrive, HubSpot, amoCRM/Kommo). Принято: таблица
`deals` — у клиента может быть несколько сделок; поля: продукт, сумма (необязательно), стадия, ожидаемая
дата закрытия, ответственный, причина отказа из справочника в «Настройках». Лид остаётся точкой входа
из Telegram; сделка создаётся при квалификации или вручную. Дашборд — выигрыш/проигрыш по причинам и
суммам. Детали схемы — ADR перед реализацией.

### Q-019. ИИ-помощь менеджеру при ответе — только по запросу

**Решение:** помощь вызывается отдельно, менеджер всегда может написать сам. Две кнопки у поля ответа:
- «Черновик» — ИИ предлагает ответ по истории диалога и базе знаний; менеджер правит и отправляет сам;
- «Улучшить» — ИИ исправляет грамматику и стиль уже написанного менеджером текста на языке клиента,
  не меняя смысла и не добавляя фактов.
Зачем: без ошибок в ответах клиентам; подсказка новому менеджеру. Ничего не отправляется клиенту без
нажатия «Отправить». Каждый вызов платный — фиксируется в аудите и Langfuse; качество — golden-кейсы и eval.
