## Комментарии архитектора к SPEC-v3 (не требуют решения, учтены в документах)

1. **Резолюция директора на каждой заявке** (шаг 2) делает директора узким местом. Документы закладывают
   метрику «время в шаге Резолюция»; если на пилоте она станет главной задержкой, правило «автоматическая
   резолюция для повторного клиента до суммы N» добавляется настройкой, без смены процесса.
2. **SPEC-v3 §10.1** называет React Router 6 и обёртку над `ProLayout`. Берём React Router 7 (как CRM и Cabinet,
   API совместим) и каркас на `antd Layout` с Pro Components внутри: двухуровневая навигация и правая панель
   выходят за модель `ProLayout` (`docs/architecture/platform-frontend.md` §4). Вид и поведение — ровно по макету.
3. **«—» в ролевой матрице** на макете серого цвета `#bfbfbf` (контраст 1.9:1); в реализации — `#6e6e6e`,
   чтобы пройти критерий SPEC-v3 §11.2 п. 6.
4. **Договор без «подписи кликом».** Для заявок процесса v3 ERP перестаёт считать клик клиента подписью; старые
   договоры, подписанные кликом, остаются как есть и показываются «Подписан».
5. **Шаги «Договор» и «Оплата» считаются по документам**, а не по стадии ERP: ERP сегодня ставит
   `CONTRACT_SIGNED` уже при принятии КП и `CLOSED_WON` при подписи договора. До T5 это скрывает BFF
   (`docs/architecture/integration-map.md` §2).
