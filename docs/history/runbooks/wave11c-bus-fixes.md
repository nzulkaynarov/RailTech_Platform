## 1. Задачи

| Задача | Что | Зоны | Ветка |
|---|---|---|---|
| **F1 Шина** | **C1-G-6:** после восстановления подписчика (предохранитель закрылся, первая доставка успешна) накопленные доставки уходят сразу, а не по расписанию повторов. Приёмник отклоняет событие, чей префикс типа не принадлежит издателю (подпись пары). **G-1:** параллельные `pump` (периодический и пробуждение) не блокируют друг друга при записи `rt_bus_subscriber_state` — единый порядок обновления (по имени подписчика) и/или вставка новой строки состояния вне общей транзакции пачки; одна ошибка не задерживает чужих подписчиков. **G-2 (решение архитектора 2026-10-26):** для подписчика с `enabled: false` раскладка **создаёт** строки доставки в статусе ожидания, ретранслятор их не отправляет, после `enabled: true` они уходят по порядку; «выключить подписчика» больше не теряет события. Отдельно — `enabled: false` с `drop: true` для подписчиков, которым прошлое не нужно (заглушки), по умолчанию `false`. **G-6:** пробуждение не сливается с периодическим проходом, запланированным позже, — свой ключ блокировки очереди или проверка «ближайший проход не позже чем через 1 с»; опрос очереди воркером CRM не добавляет секунды (проверить настройку Procrastinate). ## 2. «Готово, когда»

- **F4:** тесты: просроченный срок — одобрение 200 с отметкой, визы/маржа по-прежнему 409; `due` в прошлом — 422; менеджер `quote.send` — 200, снабженец — 403; ИСХ и комментарий в API КП; отправитель и менеджер у письма; `make check-eds`, `make check-erp`, `make check-crm`, `make contracts`.
- **F1:** тесты на каждый дефект: два параллельных `pump` с новым подписчиком — без взаимной блокировки (тест конкурентный, на
  настоящем PostgreSQL); выключенный подписчик — доставки ждут и уходят после включения, с `drop: true` — не создаются; пробуждение
  при запланированном позже периодическом проходе стартует ≤ 1 с; `make -C packages/rt-bus check`, `make check-crm`, `make check-erp`,
  `make contracts` (схема `subscriptions.yaml`, если меняется) зелёные.
- **F2:** e2e консоли CRM: администратор без прав на лиды — нет запросов к `/stream`, первый экран — доступный раздел; менеджер —
  без изменений; `make check-crm`.
- **F3:** каждый пункт — шаг, результат, строка журнала или снимок; итог «гейт этапа B пройден без оговорок / с оговорками».
