# HANDOFF — состояние на 2026-10-19 и порядок продолжения

Документ для следующей сессии (человек или агент). Источник правды о плане — `ORCHESTRATOR.md`, о статусах — `docs/PROGRESS.md`,
о решениях — `docs/DECISIONS.md`. Здесь — сводка «где мы» и «что делать дальше», чтобы начать без перечитывания журнала.

## 1. Где мы

Монорепозиторий `RailTech_Platform` (GitHub `nzulkaynarov/RailTech_Platform`), ветка `main` защищена (только PR с «CI ok»).

15–16 октября агенты влили в `main` 17 задач M1–M3, из них 16 — без PR и без прогона CI, и сами объявили вехи M1 и M2
закрытыми. Аудит лида 2026-10-18 (`docs/audits/2026-10-18-main-e0f089e.md`) нашёл 11 проблем P0: известные всем секреты
по умолчанию на шве CRM ↔ ERP, захват аккаунта через SSO, мастер-код «2468» акцепта КП, вход в портал без проверки подписи
Telegram на стенде, открытый наружу `/mcp`, покупательские аккаунты в ERP, Cabinet, не работающий с настоящим ERP, сломанный
жизненный цикл документов в портале, 500 в интеграционном API, кнопки-пустышки, отключённый процесс. Владелец принял план
исправлений; новые задачи M3 заморожены до конца волны 3.

## 2. Что есть в коде

**CRM (`apps/crm`)** — рабочая система из `crm-rt-ai`: ADR-0022 («Передан в бэк-офис» = `customer`), коннекторы «ERP» и
«Почта», источники лидов `web`/`phone`/`email`/`referral`, «Расходы» на ИИ, центр внешних сервисов (ADR-0024); передача в ERP,
приёмник событий ERP и SSO — влиты без ревью, исправляются в волнах 1 и 3. Голова Alembic — `0025_sso_replay_tokens`.

**ERP (`apps/erp`)** — выделена из B2B (M1-ERP-01…10): канонические приложения, 6 ролей бэк-офиса, ИИ через LiteLLM, два слоя
каталога, курс на дату КП, Settings Hub; портальный API (`portal`, M2-ERP-01…03), интеграционный API, вебхуки и `erp-mcp`
(M3-ERP-01…03). Известные дефекты портала, интеграции и MCP — реестр аудита (префиксы P, I, S).

**Cabinet (`apps/cabinet`)** — SPA без бэкенда (React 18, Vite 7, Tailwind 4, shadcn/ui), веб и Telegram Mini App, i18n
ru/uz/en. Проверялся только против MSW-мока: тела ответов настоящего портала с контрактом не совпадают (C-1, P-8) —
волна 2.

**Инфраструктура** — `make up` поднимает ансамбль на `crm.`, `erp.`, `cabinet.localhost`; `legacy/b2b` удалена (M2-INF-01),
история — тег `b2b-final`. CI — один workflow, обязательная проверка «CI ok»; на PR — по путям, на push в `main` — всё.

## 3. Что делать дальше (порядок)

Исправления по аудиту — `docs/PROGRESS.md`, раздел «Исправления по аудиту»; задачи, «готово, когда» и находки — в отчёте.

## 4. Правила владельца (действуют для всех сессий)

- Код попадает в `main` **только через PR** с зелёным «CI ok» (ruleset `main`, 2026-10-18); прямой push и `git merge` в `main` запрещены, «готово» в PROGRESS — только со ссылкой на влитый PR.
- Открытые вопросы решать **по рекомендации или бенчмарку** и продуктовому подходу (путь лида, клиента, сотрудника,
  администратора), записывать в `docs/DECISIONS.md` с пометкой «по рекомендации»; не останавливаться (ORCHESTRATOR §8).
- **Одна консоль администратора — CRM**: ключи и интеграции вводятся там один раз, без `.env` и перезапуска;
  администратор видит и контролирует все внешние сервисы (ORCHESTRATOR §3.13).
- Платные вызовы моделей (evals) — только с согласия владельца на конкретный прогон.

## 6. Особенности рабочего места владельца

- Docker Desktop: **8 ГБ** памяти по факту (`docker info` 2026-10-18 → 7,75 GiB; ранее здесь значилось 12), подсеть VM
  закреплена `VpnkitCIDR: 192.168.65.0/24` (иначе после перезапуска движок недоступен); старые стенды `railtech`,
  `infra`, `railtech_saas_b2b`, `rt-b2b-platform` остановлены; параллельно работает чужой `ketocare-dev` (порты 5434, 6381).
  Стенд `make up` (18 постоянных контейнеров + 5 одноразовых) занимает ≈ 4,5 ГБ — рядом помещается один набор тестов ERP.
- Стенд проверен 2026-10-18 после волны 0: `make env` → `make up` (первая сборка ≈ 10 мин) → `make smoke` — три
  `/health` 200; `erp.localhost/mcp/erp` снаружи 404; `cabinet.localhost/api/portal/v1/me` без сессии 401. В `.env`
  пусты только `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `TELEGRAM_BOT_TOKEN` (волне 1 не нужны).
- На Mac нет `gitleaks` и `pre-commit` (`brew install gitleaks pre-commit && make hooks`), нет venv/node_modules
  приложений (`make -C apps/<app> install` в каждом worktree).
- После `git pull` с правкой `infra/caddy/Caddyfile.dev` — `make caddy-reload`.
- Бэкенд-тесты ERP идут в контейнерах `rt-erp-test-*` (`apps/erp/scripts/test_backend_local.sh`), по одному прогону на набор; параллельной сессии — свой набор `ERP_TEST_NS=<имя>`.
- Облачная сессия Claude Code (без машины владельца): Docker Hub отвечает 429 — образы брать из `mirror.gcr.io` и перетегировать; сборка образа бэкенда за прокси не проходит (`apt`), поэтому тесты ERP — в venv хоста (`uv`, `psycopg2-binary` вместо `psycopg2`) против контейнеров `pgvector/pgvector:0.8.7-pg17` и `redis:7.4.11`. Перед пушем — `gitleaks git --config .gitleaks.toml .` (CI сканирует всю историю; ложное срабатывание — в `.gitleaksignore` как `файл:правило:строка`).
