## 0. Начни здесь

1. Прочитай `ORCHESTRATOR.md` целиком, затем этот файл, затем `PROGRESS.md` (разделы «Стратегия: этап 0», «этап B», волна 9).
2. Посмотри живое состояние — оно важнее текста ниже:
   `gh pr list --state open` · `git worktree list` · `docker ps --format '{{.Names}}' | grep -E '^rt-'`.
3. **Архитектор** (Fable; резерв — Opus, ORCHESTRATOR §4.1): запускает лида на каждую волну **одним промптом** (§0 runbook'а волны
   плюс строка «наследство: открытые PR и шаги из HANDOFF §2») фоновым субагентом Opus; пересылает лиду отчёты его исполнителей;
   решает вопросы лидов по рекомендации и пишет их в `DECISIONS.md`; после закрытия волн 10 и 11 — деплой и сброс прода (§3).
4. **Лид** ведёт волну по runbook'у: worktree `.claude/worktrees/<задача>`, исполнители — субагенты Sonnet (Opus — только если
   задача меняет контракт на обе стороны), ревью — свежий субагент, слияние — `gh pr merge --auto --merge` после merge
   `origin/main` и локальных проверок; CI не опрашивает. Закрытие — docs-PR с `PROGRESS.md`, блок для HANDOFF — архитектору.
