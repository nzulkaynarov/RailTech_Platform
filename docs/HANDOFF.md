## 2. Что сделано по системам

**CRM (`apps/crm`)** — рабочая система из `crm-rt-ai` плюс:
- ADR-0022: «Передан в бэк-офис» = стадия `customer`, режим `local`/`erp` по факту настройки коннектора ERP;
- коннектор «ERP» в «Подключениях» с «Проверить связь» и строкой на «Состоянии системы» (адрес в настройках, Q-11);
- источники лидов `web` / `phone` / `email` / `referral`, публичная форма `POST /api/v1/leads/web` с антиспамом и
  обязательным согласием `consent`, ручное создание «Новый лид», склейка с Telegram по номеру;
- коннектор «Почта» (SMTP) и журнал писем, приглашение сотрудника и сброс пароля по почте (ADR-0023);
- страница «Расходы»: дашборд затрат на ИИ по ансамблю из журнала LiteLLM, теги `system/feature/model` на всех вызовах;
- центр внешних сервисов (ADR-0024): реестр, фоновые проверки, метрики, выключатели, инциденты, оповещения.
- Миграции Alembic: голова — `0022_external_services`.

**ERP (`apps/erp`)** — выделенная из B2B система (M1-ERP-01..04):
- Удалены операторская плоскость, лиды, чат, KYC, подписки/entitlements, маршрутизация между продавцами, ЖД-домен (EquipmentGroup/DomainKeyword).
- **M1-ERP-03**: новые канонические имена приложений (`accounts`, `parties`, `catalog`, `sales`, `finance`, `documents`, `ai`, `core`). Свежие squashed-миграции и детерминированные сиды.
- **M1-ERP-04**: Бренд платформы перенесён в `SystemSetting` (`platform_name`, `support_email`, `logo_url`, `domain`) и доступен для редактирования в Platform Settings SPA. Все 22 email-шаблона, печатные формы (PDF) и публичные страницы нейтрализованы. Отраслевые `DomainType` переведены на `GENERAL_GOODS` и `SERVICES`. Подключены токены из `packages/ui-tokens` в `apps/erp/frontend/src/index.css`.
- Полная очистка бренда: `grep -ri railtech apps/erp` возвращает **0 совпадений** (разрешено только в `.env.example`).
- Приёмка M1-ERP-03/04 (2026-10-14): пакеты `crm`, `sourcing`, `master_data`, `notifications` — **переходные пакеты кода** (сервисы, вьюхи, задачи, ре-экспорт моделей) без своих таблиц, кроме `sourcing.Attachment`; новый код — в канонические приложения, остаток переносится в M1-ERP-10 (DECISIONS 2026-10-14). Промпты ИИ и демо-сид без отрасли.
- Тесты и стабильность: бэкенд **1906 passed**, фронтенд **696 passed**, Cabinet **209 passed**, 0 ошибок линтера, миграции применяются на чистой базе без дрифта.

**Cabinet (`apps/cabinet`)** — новое приложение: оболочка, вход Telegram Mini App и magic-link, все экраны клиента,
«Написать менеджеру» (`t.me/<бот>?start=deal_<id>`), форма «Я новый клиент» → лид CRM. Данные — мок MSW по
`packages/contracts/openapi/erp-portal.yaml` до появления портального API в ERP. Тесты: 209, axe 0.

**Инфраструктура** — `make up` поднимает весь ансамбль на `crm.`, `erp.`, `cabinet.localhost` (на машине владельца
порт 8088), PostgreSQL 17, Redis, RustFS, LiteLLM, Langfuse (`make up-obs`), Caddy. `make ci-local` — гейт мержа,
пока GitHub Actions заблокирован биллингом (Q-10).

## 4. Правила владельца (действуют для всех сессий)

- Открытые вопросы решать **по рекомендации или бенчмарку** и продуктовому подходу (путь лида, клиента, сотрудника,
  администратора), записывать в `docs/DECISIONS.md` с пометкой «по рекомендации»; не останавливаться (ORCHESTRATOR §8).
- **Одна консоль администратора — CRM**: ключи и интеграции вводятся там один раз, без `.env` и перезапуска;
  администратор видит и контролирует все внешние сервисы (ORCHESTRATOR §3.13).
- Платные вызовы моделей (evals) — только с согласия владельца на конкретный прогон.
