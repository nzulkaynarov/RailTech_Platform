# Пакет запуска RailTech Platform (`rt_platform`) — три системы: CRM · Cabinet · ERP

Дата пакета: 2026-10-13. Пакет разложен в монорепозиторий `RailTech_Platform` 2026-10-13 (M0-INF-01):
`CLAUDE.md` и `ORCHESTRATOR.md` — в корне, остальные документы и `adr/` — здесь, в `docs/`.

| Файл | Назначение | Кто читает |
|---|---|---|
| `ORCHESTRATOR.md` | **Главный документ.** Цель, системы, инварианты, роли агентов, последовательность вех и задач, протокол работы и передачи, гейты владельца | каждый агент — первым |
| `CLAUDE.md` | Точка входа Claude Code в корне: карта репозитория и отсылка к оркестратору | автоматически |
| `BUSINESS.md` | Ценность трёх систем, действующие лица, путь клиента, пути сотрудников, полный жизненный цикл | перед любой продуктовой задачей |
| `ARCHITECTURE.md` | Целевая архитектура: схема, границы владения, состав ERP/Cabinet/CRM, входы клиента, e-mail, ИИ, SSO, инфраструктура | перед реализацией |
| `CONTRACTS.md` | Контракт между CRM и ERP: интеграционный API, события, `erp-mcp`, SSO-токен, портальная аутентификация | агенты CRM, ERP, Cabinet, infra |
| `MIGRATION-MAP.md` | Что из B2B и CRM куда переезжает, что удаляется, что новое | агенты ERP, Cabinet, CRM |
| `DECISIONS.md` | Решения владельца с датами | все |
| `QUESTIONS.md` | Открытые вопросы владельцу | владелец |
| `OWNER-CHECKLIST.md` | Что делает владелец: репозиторий, сервер, домены, бот, почта, секреты, приёмки | владелец |
| `docs/adr/0001…0007` | Архитектурные решения уровня ансамбля (статус proposed → accepted владельцем) | все |

Исходные документы обсуждения (история рассуждений) лежат в `docs/history/` только для контекста;
в работу они не берутся — при расхождении правы документы этого уровня.
