## 1. Задачи

| Задача | Что | Зоны |
|---|---|---|
| **D1-1 Переписка менеджера** | Клиенты · «Ждут ответа» (передачи от бота с таймером SLA, «Забрать»), лента диалога лида/клиента с вложениями, ответ «От себя / Заметка команде» с подписью «Уйдёт клиенту в Telegram», шаблоны ответов и подсказка ответа (ИИ — через CRM), ошибки отправки с «Повторить» и сохранением текста; живые обновления через SSE BFF (колокольчик и счётчик «Ждут ответа» — без опроса). Сообщение клиента в бота появляется в Платформе ≤ 2 с | BFF `crm` (диалоги, передачи, ответы), web `modules/crm` |
| **D1-2 Лиды, клиенты, «Создать заявку»** | Клиенты · Лиды (список с фильтрами «мои/все/просроченные», карточка в боковом окне), Клиенты (список, карточка 360°: контакты, переписка, заявки, документы), «+ Создать заявку» из лида по SPEC §3.1 шаг 1 (компания, контакт, суть, письмо-файл, срочность) → ERP заявка ЗВ и событие → письмо ВХ в EDS | BFF, web `modules/crm`, CRM/ERP — только если не хватает полей |
| **D1-3 Директор: входящие и резолюция** | Документы · Входящие письма (список, карточка письма со шкалой 7 шагов), боковое окно «Резолюция» по SPEC §7.3: текст, исполнители по зонам, срок, «Маржа не ниже, %»; «Утвердить резолюцию → задание в расчёт», «Вернуть менеджеру», «Отклонить» (комментарий обязателен), блок «Что произойдёт» | BFF `eds` (через обмен токена `aud=eds`), web `modules/eds` |
| **D1-4 Директор: КП и служебки** | Документы · КП на одобрение — карточка КП (строки, итоги, внутренний блок маржи только директору), «Одобрение» с чек-листом (визы, маржа, срок — предупреждением) и каналами отправки; кнопка неактивна с подписью, какой пункт не зелёный; «Вернуть на доработку». На согласовании — служебки: «Согласовать / Вернуть / Отклонить» | BFF `eds`, web `modules/eds` |
| **D1-5 Создать документ** | «+ Создать документ»: тип (служебная записка, заявление, отчёт, письмо), тема, кому (по умолчанию директор), текст, сумма и «нужно до», вложения, связь с проектом → «Отправить на согласование»; черновики; «Мои документы». Документ на бланке с PDF и шаблонами — волна документов D-DOC (ADR-0020), здесь — простой текст | BFF `eds`, web `modules/eds` |
| **D1-6 Очередь и переходы** | Строки «Моей очереди», колокольчика и поиска для сообщений, лидов, писем, КП, служебок открывают новые экраны в боковом окне (снять «мост» H1 для них) | web, BFF `feeds` |
| **D1-7 Гейт D1** | Сквозной сценарий на стенде с ботом-заглушкой: клиент пишет в бота → менеджер видит за ≤ 2 с, отвечает, создаёт заявку → директор накладывает резолюцию → ERP-задание; КП на одобрении → директор одобряет → ИСХ; служебка сотрудника → директор → бухгалтер; роль-универсал проходит всё; отчёт `docs/runbooks/d1_gate_report.md` | стенд, `docs/` |
| **D1-8 Права CRM только из каталога** | Задача безопасности (B-014, B-007): права прямого API CRM сотрудника с ролями Платформы — только из матриц его ролей (тест по `platform-rbac.yaml`), базовая роль CRM — признак по матрице, `storage_key` убран из `MessageOut`; CRM `GET /team?section=&level=` — сотрудники по разделу, BFF кандидатов резолюции переходит на неё; EDS сверяет зону исполнителя резолюции (422 `assignee_zone_mismatch`) по `permissions.sections` из `identity.user.*`. Выкладка: [`deploy.md`](deploy.md), «Права CRM только из каталога» | CRM, `apps/eds`, BFF `eds_letters`, `packages/contracts` |
