## 1. Задачи

| Задача | Что | Зоны |
|---|---|---|
| **P1 Почта: исходящая — один отправитель** (B-INB-6) | Карточка «Почта» в Настройки · Подключения: SMTP вводит админ (секрет только на запись, «Проверить отправку»), CRM владеет почтовым сервисом; ERP (кабинет, КП, приглашения клиентов) и EDS отправляют через CRM (шина или внутренняя операция по наименьшим правам); журнал доставки, строка здоровья; рассылки — нет (после пилота) | CRM, ERP, EDS, BFF, web, контракт |
| **P2 Почта: входящая и помощник канцелярии** (B-INB-5, B-INB-1 минимум) | IMAP общего ящика (пароль приложения вводит админ в той же карточке), без удаления, отметка обработанных, дедупликация по Message-ID; очередь «Входящая почта» у роли с правом канцелярии; карточка помощника: тип (минимум: покупатель · официальное письмо · счёт/документ поставщика · прочее), суть, отправитель/ИНН, предложение действия — зарегистрировать ВХ в EDS · создать лид/прикрепить к переписке · счёт бухгалтеру · ответ шаблоном · архив; подтверждает человек; ответ из платформы в ту же цепочку; ИИ только предлагает, читает только текст; вложения — белый список и предел | CRM, EDS, BFF, web, LiteLLM-алиас |
| **P3 Права переписки отдельно от реестра лидов** (B-076, P1 до пилота) | `chats.external` даёт только диалоги, где сотрудник участвует или назначенные его зоне; реестр лидов — только `crm.leads`; бухгалтеру — переписка по сделкам с выставленным счётом; каталог с обеих сторон, тесты матрицы | CRM, BFF, контракт RBAC |
| **P4 Письмо на бланке в EDS** (D-DOC2 минимум, B-018) | «Создать документ» → письмо: тело — блоки D-DOC1, один бланк компании, PDF через `rt-docs` в фоновом воркере (B-094: параллельность 1, кэш по хешу, без синхронного рендера), предпросмотр, «Отправить адресату» через почтовый сервис P1; реквизиты бланка задаёт админ в интерфейсе | EDS, BFF, web, `packages/rt-docs` |
| **P5 Статьи компании** (B-INB… / B-076 помощь) | Настройки · Статьи компании: админ пишет и правит в интерфейсе, показываются в помощи рядом с продуктовыми (поиск, раздел «Как у нас принято») | CRM (хранение), BFF, web |
| **P6 Отключение старых фронтов** (13b) | После гейтов D1-7 и D2-6: старые CRM и ERP-фронты — только редирект в Платформу (кабинет клиента остаётся), удаление `apps/crm/frontend` и `apps/erp/frontend` по модулям, Caddy-перенаправления старых доменов, мосты H1 сняты; что ещё без экрана — явный список и решение архитектора | apps/*/frontend, infra/caddy, web (мосты) |
| **P7 Гейт пилота** | Сквозной сценарий на проде с реальными каналами (B-003): клиент → бот и почта → менеджер → заявка → резолюция → расчёт → КП → договор → счёт → оплата → акт; почта на вход и выход; письмо на бланке; бэкап на Drive «работает»; роль-универсал; отчёт `docs/runbooks/pilot_readiness_report.md` | прод, `docs/` |
