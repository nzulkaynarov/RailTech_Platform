# docs/runbooks — эксплуатация и действующие волны агентов
Статус: действует · Владелец: лид · Обновлено: 2026-11-27

Здесь — только то, по чему работают сейчас: инструкции эксплуатации (симптом → диагностика → действие → проверка) и
runbook'и идущих волн. Закрытые волны — [`../history/runbooks/`](../history/runbooks/); отчёты гейтов и прогонов
глазами — [`../audits/`](../audits/README.md).

## Эксплуатация ансамбля

| Runbook | Когда открывать |
|---|---|
| [`stand.md`](stand.md) | локальный стенд `make up`: первый запуск, домены, сбои |
| [`servers.md`](servers.md) | серверы VPS1 (приложения) и VPS2 (база), доступ, что где лежит |
| [`deploy.md`](deploy.md) | выкладка `main` на прод, одобрение, откат, первый подъём |
| [`backup-pitr.md`](backup-pitr.md) | WAL-архив PostgreSQL, восстановление на момент времени, ежемесячная проверка |
| [`offsite-gdrive.md`](offsite-gdrive.md) | внешняя копия бэкапов — Яндекс Диск компании (рекомендуется) или общий диск Google Workspace: включение в интерфейсе, восстановление, учения |
| [`crm-erp-pairing.md`](crm-erp-pairing.md) | сопряжение CRM ↔ ERP, «Обновить ключи», сбои подключения |
| [`rt-bus-erp.md`](rt-bus-erp.md) | шина в ERP: журнал, DLQ, повтор, метрики, ротация секрета, код акцепта КП |
| [`rt-bus-crm.md`](rt-bus-crm.md) | шина в CRM: DLQ, повтор, метрики, необработанные события ERP |
| [`crm-bot.md`](crm-bot.md) | Telegram-бот отдельным процессом: запуск, сбои |
| [`request-id.md`](request-id.md) | найти запрос по `X-Request-ID` в журналах Caddy, CRM и ERP |
| [`log-secrets.md`](log-secrets.md) | что не попадает в логи и как это проверить |

Системы: **CRM** — [`crm/`](crm/README.md) (бот, эскалации, расходы ИИ, бэкапы, eval-gate, ротация ключей);
**ERP** — [`erp/`](erp/README.md) (dev-стенд, миграции, воркеры, бэкап базы и медиа).

## Волны агентов

Действующих волн нет: очередь работ одна — [`../LIST.md`](../LIST.md), курс — [`../COURSE.md`](../COURSE.md) (решение владельца
2026-11-27). Runbook'и волн 16–19 и план партий «Шаблоны и маршруты» закрыты и лежат в [`../history/runbooks/`](../history/runbooks/).
Преамбула исполнителя — [`docs/ORCHESTRATOR.md`](../ORCHESTRATOR.md) §4.2. Новый файл с «plan», «wave», «очередь», «волна»
в имени вне `history/` проверка ссылок не пропускает.

Волна закрыта (гейт пройден, задачи влиты) — runbook переносится в `../history/runbooks/` с баннером «История», строка
отсюда удаляется. Отчёт гейта новой волны кладётся в [`../audits/`](../audits/README.md), а не сюда.
