# Runbooks — Эксплуатация RailTech ERP
Статус: действует · Владелец: лид · Обновлено: 2026-10-23

Регламенты обслуживания, диагностики и устранения инцидентов бэк-офиса ERP (`apps/erp`).
Создаются и обновляются в том же PR, что и изменение системы (docs/systems/erp/CONVENTIONS.md §10, ORCHESTRATOR §3.8).

| Runbook | Описание и симптомы | Когда применять |
|---|---|---|
| [dev-stand.md](dev-stand.md) | Запуск и диагностика стенда ансамбля | Первый запуск, `erp.localhost` 502/503, статус unhealthy, `/health/` отвечает 503 |
| [migrations.md](migrations.md) | Управление миграциями и начальными данными | Изменение моделей, проверка `makemigrations --check`, откат, `core_seed` |
| [workers.md](workers.md) | Celery worker, worker-ai и Celery Beat | Зависание PDF, простой очереди `ai`, курсы ЦБ РУз не обновляются, перезапуск воркеров |
| [backup-restore.md](backup-restore.md) | Резервное копирование и восстановление | Снятие дампа базы `erp`, восстановление после сбоя, бэкап медиафайлов (RustFS/S3) |

## Шаблон инцидента и регламента

Каждый новый runbook оформляется по канонической структуре:

```markdown
# <Название регламента / инцидента>

## Когда применять
Симптомы и наблюдаемое поведение глазами инженера или пользователя бэк-офиса.

## Диагностика
Точные команды и критерии нормы (что возвращает здоровая система).

## Действие
1. Пронумерованные идемпотентные шаги с минимальным временем простоя.
2. ⚠️ Опасные шаги, требующие предварительного дампа или остановки трафика.

## Проверка
Команды и запросы, подтверждающие полное восстановление работоспособности.

## Эскалация
К кому обращаться при неуспехе, какие логи (`X-Request-ID`, трейсы, снимки состояния) прикладывать.
```
