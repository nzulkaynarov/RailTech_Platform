## 1. Задачи

| Задача | Что | Зоны | Ветка |
|---|---|---|---|
| **F1 Шина** | **G-1:** параллельные `pump` (периодический и пробуждение) не блокируют друг друга при записи `rt_bus_subscriber_state` — единый порядок обновления (по имени подписчика) и/или вставка новой строки состояния вне общей транзакции пачки; одна ошибка не задерживает чужих подписчиков. **G-2 (решение архитектора 2026-10-26):** для подписчика с `enabled: false` раскладка **создаёт** строки доставки в статусе ожидания, ретранслятор их не отправляет, после `enabled: true` они уходят по порядку; «выключить подписчика» больше не теряет события. Отдельно — `enabled: false` с `drop: true` для подписчиков, которым прошлое не нужно (заглушки), по умолчанию `false`. **G-6:** пробуждение не сливается с периодическим проходом, запланированным позже, — свой ключ блокировки очереди или проверка «ближайший проход не позже чем через 1 с»; опрос очереди воркером CRM не добавляет секунды (проверить настройку Procrastinate). Тексты `rt-bus.md` §5 и `rt-bus-crm.md` п. 4 — под новую семантику | `packages/rt-bus` (ядро, SQLAlchemy и Django-адаптеры, `contrib/procrastinate.py`), `apps/crm`/`apps/erp` — только подключение, `docs/architecture/rt-bus.md`, `docs/runbooks/rt-bus-crm.md` | `w11c/f1-bus` |
| **F2 Консоль администратора CRM** | **G-3:** клиент `/api/v1/stream` не подключается без права чтения потока (нет бесконечных 403 и «Нет связи»); **G-5:** после входа администратор попадает в первый доступный ему раздел (по правам), а не на `/leads` | `apps/crm/frontend` (до C2), `apps/crm/backend` — только если нужен признак прав в `/me` | `w11c/f2-crm-admin-landing` |
| **F3 Повтор гейта (QA)** | После F1: на стенде `-p rt-w11c` — пункты гейта §3.2 (`enabled: false` → события ждут и уходят после включения; с `drop: true` — не уходят), §3.5 (≥ 200 событий, **p95 и max ≤ 2 с** от коммита до BFF), нагрузка на G-1 (новый подписчик + 50 параллельных публикаций, 0 `DeadlockDetected` за 30 мин). ## 2. «Готово, когда»

- **F1:** тесты на каждый дефект: два параллельных `pump` с новым подписчиком — без взаимной блокировки (тест конкурентный, на
  настоящем PostgreSQL); выключенный подписчик — доставки ждут и уходят после включения, с `drop: true` — не создаются; пробуждение
  при запланированном позже периодическом проходе стартует ≤ 1 с; `make -C packages/rt-bus check`, `make check-crm`, `make check-erp`,
  `make contracts` (схема `subscriptions.yaml`, если меняется) зелёные.
- **F2:** e2e консоли CRM: администратор без прав на лиды — нет запросов к `/stream`, первый экран — доступный раздел; менеджер —
  без изменений; `make check-crm`.
- **F3:** каждый пункт — шаг, результат, строка журнала или снимок; итог «гейт этапа B пройден без оговорок / с оговорками».
