### M2: покупательские экраны ERP без аналога в Cabinet (сняты в M1-ERP-02 волна 3 frontend)

Покупательская часть ERP SPA удалена (клиент в ERP не входит); всё ниже было у покупателя в ERP и **не перенесено**
в Cabinet (M2-CAB-02). **Решено 2026-10-14 по продукту** (DECISIONS): п. 1, 2, 5, 7, 8 и поиск из п. 10 → задача M2-CAB-04; п. 3 — после загрузки файлов (Q-14, M2-ERP-01); п. 4, 6, 9 и центр уведомлений — не переносим:

1. **Главная клиента** — полоса «требует решения» (КП к рассмотрению, договоры на подпись, счета к оплате, акты на
   приёмку, поставки на приёмку), недавние запросы и документы, воронка, приветственный онбординг. В Cabinet `/` — редирект.
2. **Черновик заявки до отправки** — правка заголовка и примечания, строки с единицей из справочника / MPN / ГОСТ / примечанием,
   подбор позиции из каталога, удаление строк, явное «Отправить заявку». В Cabinet заявка создаётся сразу (суть + строки
   свободным текстом), правки нет (Q-16).
3. **Импорт строк заявки из Excel** (шаблон или ИИ-разбор) — нет загрузки файлов в портальном контракте (Q-14).
4. **ИИ-помощники заявки**: составление заявки из свободного текста с кандидатами каталога; предполётная проверка строк
   перед отправкой; «КП vs заявка» — проверка покрытия полученного КП. У Cabinet своего ИИ нет (ADR-0005) — если нужно,
   только через портальный API ERP.
5. **Корзина каталога** (несколько позиций → одна заявка). В Cabinet «Запросить» открывает заявку с ОДНОЙ позицией
   (DECISIONS M2-CAB-02, корзины нет).
6. **Фиксация оплаты клиентом** (сумма, дата, способ, скан платёжки) — в портальном контракте платежей нет; в ERP оплату
   теперь фиксирует бэк-офис (бэкенду: `record_payment` пускает только покупателя/суперпользователя — нужен доступ по праву
   финансов, см. DECISIONS 2026-10-14 волна 3).
7. **Приёмка / спор поставки** (DELIVERED → ACCEPTED / DISPUTED, закрывает сделку) — в Cabinet поставки только для чтения
   (`GET /deliveries`). Без этого ACCEPTED ставить некому.
8. **Скан подписанного акта от клиента** (загрузка файла при приёмке) — в Cabinet акт принимается/возвращается без файла.
9. **Книга поставщиков покупателя** («Поставщики», история закупок по продавцам) — не нужна в модели «продавец один»;
   поставщики бэк-офиса — модуль `supply` (M4).
10. **Глобальный поиск документов (⌘K) и центр уведомлений** в приложении — у клиента нет; уведомления клиенту идут ботом CRM
   и письмами ERP (ARCHITECTURE §18).
