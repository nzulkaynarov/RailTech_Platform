# Модули как коробочные решения
Статус: принято владельцем 2026-11-09, пересмотр после бизнес-процесса утверждён 2026-11-10 (этап 1 из 5) · Владелец: владелец · 2026-11-10

Этапы: модули → бизнес-процесс → карта взаимодействий → интерфейс → интеграции и роли. Границы могут уточниться после этапа 2.

**Правила.** Модуль — самостоятельная коробка: сам хранит свои данные и сам проверяет свои правила. С другими связан только контрактом:
событиями шины `rt_bus` и API. BFF собирает интерфейс и экраны из нескольких модулей, бизнес-правил в нём нет. У объекта один дом, кнопка
может стоять где угодно.

Основа: [стратегия экосистемы](../strategy/2026-11-07-ecosystem-and-certification-strategy.md) §2, контракты событий `packages/contracts`, код на 2026-11-09.
Статус функции: **есть** — работает, **част.** — есть не полностью, **нет** — не сделано.

## CRM — кто клиент и что ему нужно

| | |
|---|---|
| Для кого | Продажи, руководитель продаж |
| Владеет | Лиды, клиенты на стадии продаж, диалоги, почтовый ящик компании, база знаний |
| Без других модулей | Ведёт лидов и диалоги, отвечает клиентам |
| Не входит | Расчёт и цены (ERP), регистрация документов (EDS), задачи (WFM) |

| Функция | Статус |
|---|---|
| Лиды, квалификация, передача менеджеру | есть |
| Telegram-бот и ИИ-консультант по базе знаний | есть |
| Единая входящая почта, передача письма в EDS | есть |
| База знаний с фиксацией пробелов | есть |
| Удержание и возврат клиентов | нет |

Публикует: `lead.*`, `client.*`, `contact.*`, `mail.sent/failed`. Получает: события сделок, КП, счетов, поставок от ERP, запросы писем от ERP и EDS.

## EDS — какой документ, кто согласовал, кто подписал

| | |
|---|---|
| Для кого | Делопроизводитель, директор, все инициаторы документов |
| Владеет | Входящие и исходящие, внутренние документы, резолюции, маршруты, реестр права подписи, журналы и номера, бланки и шаблоны |
| Без других модулей | Полный документооборот компании |
| Не входит | Коммерческое содержание сделки (ERP), задачи вне документа (WFM) |

| Функция | Статус |
|---|---|
| Регистрация входящих, резолюция директора | есть |
| Исходящие письма на бланке | част.: можно отправить без подписи |
| Служебные записки, заявления, отчёты с согласованием | есть |
| Заявка на закупку как документ | част.: идёт служебной запиской |
| Реестр права подписи, замещение | есть |
| Подпись документов ERP | част.: влита, на проде нет |
| Настраиваемые маршруты в шаблоне | нет |
| Библиотека шаблонов и редактор | нет |
| Проверка подлинности `/v/<код>`, QR | есть для писем, част. для документов ERP |
| E-IMZO | нет |

Публикует: `letter.*`, `document.*`, `approval.*`, `signing.decided`, `mail.requested`. Получает: `request.created`, `quote.ready_for_approval`, `signing.requested`, документы ERP, сотрудников.

## ERP — что продаём и закупаем, сколько денег и товара

| | |
|---|---|
| Для кого | Менеджеры, расчётчики, снабжение, бухгалтер |
| Владеет | Заявки и сделки, расчёт и КП, договоры как коммерческие объекты, контрагенты, каталог, заказы поставщикам, склад, поставки, счета и оплаты |
| Без других модулей | Полный цикл сделки от запроса до акта |
| Не входит | Подпись документа (EDS), бухгалтерский учёт и отчётность |

| Функция | Статус |
|---|---|
| Заявка, расчёт с визами, КП | есть |
| Договор, счёт, акт | есть, без обязательного маршрута |
| Заказы поставщикам, приёмка, склад | есть |
| Каталог, карточки партнёров, прайсы | есть |
| Прослеживаемость товара | част.; нужна для цели 1000 товаров |
| Счета и оплаты, ручное подтверждение | есть |
| Банки, налоговый ЭДО, таможня | нет |

Публикует: `request.*`, `deal.*`, `quote.*`, `contract.*`, `invoice.*`, `delivery.*`, `act.*`, `signing.requested`. Получает: клиентов и контакты CRM, решения EDS.

## WFM / PM — кто что делает и к какому сроку

| | |
|---|---|
| Для кого | Все сотрудники, директор |
| Владеет | Задачи, поручения, проекты-досье, сроки и просрочки |
| Без других модулей | Задачи и проекты компании |
| Не входит | Содержание документа и сделки: только ссылка на них |

| Функция | Статус |
|---|---|
| Поручения по резолюции | есть, внутри EDS |
| Очередь «Ждут действия» | есть, на главной |
| Задания расчёта | есть, внутри ERP |
| Проекты | есть как карточка сделки, внутри EDS |
| «Мои задачи» единым списком | нет |
| Произвольная задача и проект без сделки | нет |
| Сроки, напоминания, эскалация | част. |

Модуля как отдельной системы нет: сначала раздел поверх данных EDS и ERP, своя база — когда появятся задачи вне документов.

## Чаты — с кем идёт разговор

| | |
|---|---|
| Для кого | Сотрудники, контрагенты |
| Владеет | Сейчас ничего: диалоги лежат в CRM, переписка кабинета — в ERP и CRM |
| Без других модулей | Цель: переписка с клиентами и партнёрами; внутри компании — обсуждения на объектах и личные сообщения (решение владельца 2026-11-10) |
| Не входит | Групповые каналы и звонки |

| Функция | Статус |
|---|---|
| Диалоги с клиентами: API | есть |
| Экран в Платформе | нет, заглушка |
| Чат в кабинете | есть |
| Обсуждение на документе или проекте | нет; есть только чат в расчёте |

## Кабинет — контрагент работает с компанией сам

| | |
|---|---|
| Для кого | Клиенты, поставщики, заводы |
| Владеет | Сессии и настройки контрагента |
| Без других модулей | Сейчас не работает: это витрина портального API ERP |
| Не входит | Правила сделки: их проверяет модуль-владелец |

| Функция | Статус |
|---|---|
| Запросы, КП, договоры, счета, поставки, акты | есть |
| Партнёр: заявка, товары, заказы, запросы цен, оборот | есть |
| Команда компании, уведомления | есть |
| Собственный слой вместо прямой связи с ERP | нет |

## Ядро платформы — что общее у всех

| | |
|---|---|
| Для кого | Администратор, все модули |
| Владеет | Сотрудники и роли, вход, шина, журнал безопасности, каталог уведомлений, единая Платформа (BFF и интерфейс) |
| Не входит | Бизнес-правила модулей |

| Функция | Статус |
|---|---|
| Единый вход, роли, замещение | есть; физически живёт в CRM |
| Шина `rt_bus`, контракты | есть |
| Единый интерфейс сотрудника | есть |
| Каталог уведомлений | част.: тексты разбросаны |
| Коннекторы внешних систем, публичный API | нет |

## Решения владельца 2026-11-09

1. Сотрудники и роли логически относятся к Ядру, физически переносятся из CRM позже.
2. Эталон контрагента — ERP, в CRM только стадия продаж.
3. Коммерческие условия договора — ERP, документ и подпись — EDS.
4. Шаблоны и бланки — в EDS.
5. Закупки и каталог пока внутри ERP.
6. Бухгалтерский учёт и отчётность не делаем, связываемся с 1С.

## Пересмотр после бизнес-процесса

Статус: утверждено владельцем 2026-11-10. Основа — [бизнес-процесс](BUSINESS-PROCESS.md) и сверка с кодом на эту дату.

| Модуль | Вердикт | Почему |
|---|---|---|
| ERP | Усилить, в первую очередь | Здесь деньги и основные риски подлога |
| EDS | Усилить | Маршруты в коде, библиотеки шаблонов нет, роль «Юрист» отсутствует |
| Коннекторы | Новый модуль, после запуска | Didox и E-IMZO подключаются, когда отработаны сценарии кабинета и Платформы (решение владельца) |
| Чаты | Усилить: разговоры с клиентами и партнёрами; внутри компании — обсуждения на объектах и личные сообщения (решение владельца 2026-11-10) | Разговор вне системы — признанный риск |
| Кабинет | Усилить | Цена напрямую от партнёра — главный контроль при одном поставщике |
| CRM | Оставить как есть | Добавляется только проверка основания заявки |
| Ядро | Минимально усилить | Роль «Юрист», журнал показов директору |
| WFM / PM | Пока раздел, не система | Процессу хватает поручений и «Моих задач» поверх EDS и ERP |

### Что усилить в ERP

| Нужно процессу | Сейчас в коде |
|---|---|
| Чистая прибыль в пакете решения директора | Только валовая прибыль: выручка минус себестоимость с доставкой и пошлиной |
| Накладные и операционные расходы в расчёте | Статьи расходов КП есть, полнота не проверяется |
| План и факт по логистике, таможне, брокерам | Факт только по закупке товара (`DealPurchaseActual`), вносится вручную |
| Реестр исходящих платежей: поставщики, логисты, брокеры, обязательства (П8) | Нет: `Payment` — только оплаты клиента; есть служебка с суммой в EDS |
| Договор с поставщиком как объект со сканом | Только договор подключения партнёра |
| Закрытие проекта с обеих сторон | Только клиентская сторона |
| Гарантия и рекламации | Нет процесса, поле гарантии в карточке товара |

Реестр платежей — раздел ERP, это не бухгалтерский учёт (решение 6 в силе). Его граница делается так, чтобы позже выделить в отдельную коробку.

### Новый модуль: Коннекторы

Для кого: все модули, администратор. Владеет: подключения к внешним системам, что и когда отправлено, статусы, отпечаток отправленного файла. Не входит: правила документа и сделки.
Подключения: Didox, E-IMZO, банки, таможня, 1С и публичный API. Какой первым, решается, когда отработаны сценарии. Один из вариантов для Didox: черновик договора, ТТН, акта и ЭСФ создаётся из согласованной редакции, директор подписывает ЭЦП у оператора. Документация Didox закрыта логином, сведения об API из неофициальных источников ([исследование](../research/2026-10-21-business-audit/research-uz-edo.md) §2.2).

До интеграции менеджер загружает документ в Didox вручную, как сейчас, и указывает номер документа в платформе.

### К запуску и после запуска

Эволюция: сначала то, что уже есть, новое — только если без него сценарий не проходит.

| К запуску | После запуска |
|---|---|
| Сценарии кабинета и Платформы целиком: заявка → КП → договор → счёт → акт, партнёр → заказ → приёмка | Коннекторы |
| Редактируемые шаблоны и маршруты, в первую очередь проект договора | Отдельный реестр исходящих платежей: пока служебка с суммой в EDS |
| Основание заявки, чистая прибыль в КП | План и факт по логистике, таможне, брокерам |
| Скан договора с поставщиком как документ в EDS, закрытие проекта с обеих сторон | Гарантия и рекламации |
| Экран диалогов с клиентами в Платформе: переписка в карточке лида, клиента и поставщика ([карта навигации](NAVIGATION.md)) | Собственный слой кабинета |
| Интерфейс новых разделов Платформы целиком, виден в меню с первого дня, без скрытия — Сводка, Календарь, Чаты, Люди: все экраны и состояния, проверка глазами (владелец, 2026-11-10) | Данные и бэкенд новых разделов, которые не успели к запуску |

### Пока не нужно

Удержание клиентов в CRM, отдельная система WFM, отдельная коробка закупок, коннектор таможни (зависит от разрешений и объёмов), магазин модулей (горизонт после 12 месяцев). Фундамент под них уже заложен правилом коробки и контрактами.

### Права по решению владельца

Менеджер, который готовит КП, видит себестоимость и маржу (решение 10 в бизнес-процессе). В ERP право `quote.view_cost_margin` уже есть у ролей «Расчёт», «Каталог и закупки», «Финансы» и «Руководитель». Какая роль достаётся менеджеру, закрепляется на этапе ролевой модели.
