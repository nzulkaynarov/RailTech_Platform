# B5 — замер задержки «событие → обновление экрана» (SSE вместо опроса)

Стенд: отдельный проект compose `rt-w11-b5` (postgres, redis-broker, redis-cache, crm-api, crm-worker, erp-backend, erp-worker, erp-beat,
platform-bff, platform-web, caddy) на коде ветки B5 вместе с B3 и B4 (их ветки влиты в одноразовую ветку стенда, в PR не входят).
Браузер — Chromium (Playwright), менеджер демо-компании, Caddy по http, HTTP/1.1. Нагрузка на машину: чужие проекты, load average 7
(в первом прогоне при load 15 цифры были хуже; см. «Что мерили»). Данные вымышленные.

Измеряется по часам одной машины (Docker Desktop, расхождение сотни мс не больше): момент в браузере — `Date.now()` внутри страницы
(наблюдатель за DOM раз в 10 мс), момент приёма в BFF — метка времени docker-лога строки `POST /bus/v1/events 200`.

## Цепочка и вклад звеньев (медиана / максимум, мс; 8 прогонов на каждый путь)

| Звено | ERP: новая заявка → колокольчик и бейдж меню | CRM: новый лид → «Моя очередь» |
|---|---|---|
| коммит / ответ издателя → приём в BFF (доставка шины, пока без пробуждения B5a) | 67 / 393 | 511 / 880 |
| приём в BFF → кадр `invalidate` в браузере (слияние 300 мс + Redis + SSE) | 309 / 319 | 313 / 375 |
| кадр → экран обновился (перезапрос API с RBAC + отрисовка) | 219 / 731 | 80 / 106 |
| **приём в BFF → экран** | **528 / 1036** | **398 / 481** |
| **коммит / ответ издателя → экран (сквозное)** | **585 / 1088** | **900 / 1256** |

Бюджет «событие → экран ≤ 2 с» выдержан во всех 16 прогонах. Опрос при этом не участвует: при живом потоке он раз в 5 минут.

## Что мерили и оговорки

- Колокольчик (`listNotifications`), бейдж «Моя очередь» (`getMenuCounters`), строки очереди и карточки (`getQueue`, `getQueueCards`) и лента
  «Сегодня» перезапрашиваются одной подсказкой; первое изменение каждого элемента фиксировал наблюдатель.
- Первый прогон при load average 15–16 дал «приём в BFF → колокольчик» 1,5–2,7 с: пять одинаковых запросов экранов одновременно
  читали одни и те же списки ERP, и ERP на загруженной машине отвечал по 1–2 с. После правки (общий вызов бэкенда для
  одновременных одинаковых запросов сессии, `Feed._single_flight`) при том же load — 0,6–1,7 с, при load 7 — как в таблице.
- Звено «издатель → BFF» — это расписание ретранслятора шины. В ERP доставка уходит сразу после коммита (в таблице 67 мс), в CRM —
  по cron раз в 5 с и в прогонах была 0,4–0,9 с (при нагрузке выше — до 5 с). Пробуждение ретранслятора по коммиту в CRM и ERP — задача B5a.
