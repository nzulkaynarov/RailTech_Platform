## Правила

1. Хвост **появляется здесь в PR, который его обнаружил** (строка в таблице, а не только абзац в описании PR или отчёте), и **удаляется в PR, который его закрыл** (в том же diff — удаление строки). Закрытые хвосты не копятся: история — в `git log` и [`PROGRESS.md`](PROGRESS.md).
2. [`PROGRESS.md`](PROGRESS.md), [`HANDOFF.md`](HANDOFF.md) и отчёты гейтов **ссылаются сюда** по ID (`B-0xx`, `B-<задача>-<n>`), а не повторяют хвосты текстом. Открытые вопросы владельцу и архитектору остаются в [`QUESTIONS.md`](QUESTIONS.md); здесь на них — строка со статусом.
3. **ID без общей последовательности** (владелец 2026-10-28, [DECISIONS](DECISIONS.md)): новая строка — `B-<задача>-<n>`, где `<задача>` — код задачи из runbook'а без дефисов и точек (D2-4 → `B-D24-1`, W15-H8b → `B-W15H8b-1`; вне runbook'а — имя worktree задачи), `<n>` — 1, 2, … внутри этой задачи. Параллельные PR так не берут один номер. Уже выданные `B-NNN` (B-001…B-094) не переименовываются. ID не переиспользуются: строка удаляется, ID остаётся свободным. Уникальность и формат проверяет `scripts/backlog.py --check` (в `make docs-links` и CI); конфликт git на соседних строках таблицы — оставить обе строки.
4. Задачи, уже стоящие в runbook'ах волн 15 и 16, **не дублируются** как хвосты (покрытие UX-оценки — в приложении А); здесь только то, чего в этих задачах нет, и хвосты, которые их PR обнаружили сверх runbook'а.
5. Приоритет: **P0** — безопасность или потеря данных или работы; **P1** — надёжность прода и тупики пользователя; **P2** — удобство и долг. План: «до D2» — закрыть до старта волны 17 (D2); «D2», «D-DOC2», «13b», «C3», «E» — этап или волна, где хвост берётся; «отложено — причина»; «владелец» — действие вне кода.
