# 0007. Снабжение (поставщики, субподряд, склад) — контур внутри ERP, не отдельная система

- Статус: accepted (владелец, 2026-10-13) · Дата: 2026-10-13 · Решение владельца 2026-10-13

## Контекст
Вопрос владельца о системе «Supply». Снабжение рождается из строк заказа клиента, меняет остатки,
которые читает расчёт КП, и даёт маржу сделки. Пользователи — те же люди бэк-офиса.

## Решение
Приложения `supply` и `inventory` внутри ERP: поставщик/субподрядчик как тип контрагента, заказ
поставщику из строк подтверждённого заказа (back-to-back, дропшип), приёмка, счёт поставщика, журнал
движений, резервы, «доступно к обещанию». Клиент видит только проекцию статусов. Отдельный «Портал
поставщика» возможен позже как тонкий фронтенд над ERP по образцу Cabinet.

## Варианты
1. Отдельная система Supply — двусторонняя синхронизация остатков, дат и себестоимости; без нового
   главного пользователя. Отклонено.
2. Контур в ERP — выбрано (так в Odoo, ERPNext, SAP B1).

## Последствия
Единый журнал движений, один таймлайн сделки с внутренними и внешними событиями, роли «Каталог и
закупки», «Исполнение и логистика», «Финансы».
