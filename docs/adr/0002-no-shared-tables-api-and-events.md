# 0002. Связь CRM ↔ ERP только через API и события; общих таблиц нет

- Статус: accepted (владелец, 2026-10-13) · Дата: 2026-10-13

## Контекст
Разные стеки (FastAPI/SQLAlchemy/Alembic и Django), разные системы миграций, тесты обеих чистят базу.
Соблазн «одной базы» ради отсутствия синхронизации.

## Решение
Две базы (`crm`, `erp`) на одной инстанции PostgreSQL. Взаимодействие: интеграционный API ERP (CRM
зовёт), подписанные вебхуки ERP → CRM, `erp-mcp` для агента, SSO-токены. Обе стороны хранят внешние
идентификаторы; идемпотентность по ним. Контракт в `packages/contracts` меняется раньше кода.

## Варианты
1. Общие таблицы — две ORM над одной схемой, гонки миграций, тесты ломают друг друга. Отклонено.
2. Общая база через views/FDW — скрытая связность, то же по сути. Отклонено.
3. API + события — выбрано.

## Последствия
Небольшая задержка отражения событий (секунды); журнал доставок и ручной повтор; контрактные тесты с
обеих сторон на стабах.
