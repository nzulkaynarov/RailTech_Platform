# 0020. Документы: бланк, единый формат тела, рендеринг и редактор

- Реализация: D-DOC1 (контракт `packages/contracts/documents/`, пакет `packages/rt-docs`) — [`architecture/rt-docs.md`](../architecture/rt-docs.md);
  дальше D-DOC2 (EDS: документ на бланке и библиотека), D-DOC3 (ERP: коммерческие шаблоны), D-DOC4 после пилота (ЭЦП-готовность, импорт DOCX)

## Контекст

Шаблоны документов — сырой HTML в ERP (`DocumentTemplate.body_html`), правит только `settings.edit`; документ создаётся только
из шаблона, в черновике меняются лишь значения подстановок; предпросмотр — HTML без страниц; письма и служебки EDS — простой
текст без бланка и PDF; «письмо» существует и в ERP (`GeneratedDocument`, номер DOC), и в EDS (`letter_out`, ИСХ). Владелец:
сотрудники не должны просить администратора, чтобы написать письмо; лист А4 должен заполняться предсказуемо (то слишком плотно,
то слишком пусто). Эталоны (Odoo, ERPNext, PandaDoc, Google Docs, 1С/Directum) сходятся на трёх вещах: бланк отдельно от тела,
автор не пишет исходник (поля-чипы, блоки с замком), предпросмотр — настоящий документ со страницами.

## Варианты

A. Оставить HTML-шаблоны ERP и улучшить экран. B. DOCX-шаблоны с плейсхолдерами (письма) + HTML (коммерческие). C. Новый сервис
«Документы». **D. Единый структурный формат тела, общий пакет рендеринга, хранение у владельца домена** (выбран).

Почему не B: PDF из DOCX требует LibreOffice (≈ 420 МБ) на VPS с CPU `qemu64`, вёрстка расходится с Word, предпросмотр — только
через конвертацию, обязательные блоки и замок в DOCX почти не проверить. Почему не C: ещё один сервис со своей базой, SSO и
бэкапом и синхронная зависимость обоих доменов без выигрыша — пакет можно вынести в сервис на этапе G/H без смены интерфейса.

## Решение

1. **Документ = бланк + тело; шаблон = тело с метаданными** (вид, язык, область — платформа, компания или личный, версия,
   статус). «Создать из шаблона» — копия тела с данными; «Сохранить как шаблон» — обратная операция.
2. **Тело — JSON по схеме `packages/contracts/documents/body.schema.json`** (узлы ProseMirror/Tiptap: абзац, заголовок 1–3,
   списки, таблица с ширинами колонок в %, жирный/курсив/подчёркнутый, ссылка по белому списку схем, переменная-чип с кодом из
   каталога `documents/variables.yaml`, блок с замком `block {code, locked, required}`, подпись и место печати, разрыв страницы)
   плюс параметры страницы (ориентация, плотность, сохранённая подгонка). **Цвет и шрифт — только из бланка.** Рендерится
   только известное, весь текст экранируется: HTML-тело и санитайзер выводятся из употребления. Каталог переменных и блоков —
   с подписями ru, uz (латиница), en; обязательные блоки видов — там же (`required_for`).
3. **PDF — WeasyPrint через общий пакет `packages/rt-docs`** (Python ≥ 3.12, без фреймворков; ставится в EDS и ERP):
   CSS Paged Media, три макета бланка — «письмо», «внутренний», «коммерческий»; плотность «Компактно/Обычно/Просторно» и
   «Подогнать» (не больше трёх дополнительных рендеров, результат хранится в теле); «Стр. N из M» только при M > 1; шапка
   таблицы повторяется, строка не рвётся, итоги не отрываются от таблицы, подпись не уходит на страницу одна. Шрифты вшиты в
   пакет (Noto Sans/Serif, OFL-1.1, с ʻ и ўқғҳ), системные документ не видит; ресурсы — только по белому списку (вшитые
   шрифты, логотип бланка байтами, растровые `data:`), сеть и файловая система закрыты. **DOCX — только экспорт из того же
   JSON** (python-docx) **и импорт в JSON при миграции** (HTML ERP — D-DOC3, DOCX — D-DOC4); DOCX не является форматом шаблона.
4. **Предпросмотр — PDF, отрендеренный сервером** (pdf.js в Платформе), рядом — число страниц, заполненность последней и
   «Подогнать»; тот же эндпоинт отдаёт файл для «Скачать PDF» — предпросмотр и итог не расходятся.
5. **Где живёт** (уточняет ADR-0015 п. 1–2, 5): письма, служебки, заявления, отчёты и их библиотека — EDS; КП, договор, счёт,
   акт и их шаблоны — ERP; **бланк** (реквизиты, логотип, макеты по видам) — ERP как владелец реквизитов, проекция в EDS
   событием `erp.company.letterhead.updated.v1` (контракт — D-DOC2/D-DOC3). Редактор — один компонент Платформы для обоих доменов.
6. **Права** (решено по рекомендации): любой сотрудник с `eds.documents.create` создаёт документ на бланке без шаблона и
   сохраняет личные шаблоны; библиотеку компании публикует **право `eds.templates.manage` в каталоге ролей** (`platform-rbac.yaml`),
   а не отдельная роль «делопроизводитель»; коммерческие шаблоны — `erp.templates.manage`; бланк — `company.letterhead.manage`.
   Коды заводятся в каталоге вместе с экранами (D-DOC2, D-DOC3).
7. **Выпущенный документ неизменяем:** снимок тела, данных и бланка; PDF/A и хеш — для документов, которые будут подписываться
   ЭЦП (D-DOC4).
8. ERP `GeneratedDocument` видов LETTER/REPORT/CUSTOM — только чтение, их шаблоны переносятся в EDS (D-DOC3).
9. **Языки** (решено по рекомендации): узбекский — латиница (`lang: uz`); кириллица — позже отдельным значением `uz-Cyrl`
   (расширение enum — минор схемы). Язык документа задаёт подписи блоков, формат дат и сумм и сумму прописью
   (ru, uz-латиница, en).
10. **Импорт своих DOCX-шаблонов** (решено по рекомендации) — после пилота, D-DOC4: с лучшим возможным качеством и отчётом о
    потерях; документы партнёров в Word и PDF остаются вложениями EDS, а не шаблонами.
11. **Версии** (ADR-0016): у `body.schema.json` и `variables.schema.json` — semver в `$comment`. Тела хранятся годами, поэтому в
    пределах мажора схема только **расширяется** (новые узлы, атрибуты, значения enum), коды каталога не удаляются; машинная
    проверка — `scripts/documents_compat.py` в `make contracts` (каждое тело-пример базы проходит схему head, semver растёт).
    Мажор 2 — новый файл `body.v2.schema.json` и конвертер в пакете.
12. **Лимиты входа** (ревью #295): вложенность узлов ≤ 20, таблица ≤ 500 строк, тело ≤ 1 МБ; управляющие символы, кроме `\t`
    и `\n`, вычищаются на входе (в сохранённом теле схема их не допускает); класс в HTML — только из фиксированного набора;
    рендер — в воркере с тайм-аутом и лимитом памяти.

## Последствия

\+ Сотрудник пишет письмо сам; предпросмотр совпадает с PDF; один формат, один CSS, один редактор на все виды; лист заполняется
предсказуемо (плотность и «Подогнать»); готовность к ЭЦП (PDF/A, хеш, блок отметки); универсально для маленькой и большой
компании; узбекский текст печатается одним шрифтом (сейчас PT Sans ERP не содержит ʻ — `oʻ` и `gʻ` идут запасным шрифтом).

− Миграция HTML → JSON и двойное чтение до этапа E; WeasyPrint, pango и шрифты в образе EDS; новое событие и проекция бланка;
импорт DOCX — с лучшим возможным качеством, сложная вёрстка Word переносится не 1:1; изоляция шрифтов опирается на внутренности
WeasyPrint (`FontConfiguration`) — при обновлении версии её проверяют тесты пакета (контрольный тест «без изоляции берётся
системный шрифт»).
