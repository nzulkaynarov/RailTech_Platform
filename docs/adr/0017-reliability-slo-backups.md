## Решение
1. SLO: интерфейс и API сотрудников — 99,5 % в месяц и p95 < 800 мс; кабинет — 99,5 %; шина — p95 доставки < 1 мин, событие
   старше 15 мин — тревога; коннекторы — 99 % за час, DLQ разобрана к концу дня; бюджет ошибок ядра и коннекторов раздельный.
2. Данные: WAL-архив PostgreSQL (WAL-G) — RPO ≤ 5 мин, RTO ≤ 4 ч; ежемесячная проверка восстановления на стенде; все файлы в
   S3 с копией вне площадки; хранилище вне площадки — в Узбекистане.
3. Изоляция: Redis — брокер и кэш раздельно; бот — отдельный процесс от API CRM; коннектор — своя очередь и контейнер;
   Caddy не ждёт здоровья второстепенных сервисов; машинные API и админки — только во внутренней сети.
4. Наблюдаемость: OpenTelemetry во всех сервисах, сквозной идентификатор запроса и события; журналы доступа Caddy; метрики,
   журналы и ошибки (VictoriaMetrics, VictoriaLogs, Grafana, GlitchTip) — на третьем сервере (этап F), до него — минимум на VPS1.
