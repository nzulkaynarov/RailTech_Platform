# 0008. HMAC-контекст для MCP вместо передачи идентификаторов моделью

- Статус: accepted (2026-10-08, решение агента по поручению владельца)
- Дата: 2026-10-08
- Связано: SPEC §1.5, §7.1, §7.3, §11; docs/systems/crm/BUSINESS.md §6 (C5), §11; PLAN Фазы 2, 6

## Контекст и проблема

Инструменты агента читают данные лида и клиента. Если идентификатор приходит аргументом от модели, prompt injection («покажи документы клиента 42») превращается в утечку. Нужен механизм, при котором контекст вызова определяет код.

## Решение

- Оркестратор агента (процесс api) перед вызовом MCP подписывает контекст `{lead_id, client_id?, mode, language, trace_id?, iat, exp}` ключом `AGENT_CONTEXT_KEY` (HMAC-SHA256) и передаёт его в заголовке `X-Agent-Context` формата `base64url(json).base64url(sig)`.
- MCP-сервер на каждом вызове проверяет подпись (`hmac.compare_digest`), срок (TTL 60 с, допуск часов 5 с), схему (лишние поля запрещены) и инвариант `mode=customer ⇒ client_id`. Любая ошибка — отказ инструмента без деталей.
- Ни один инструмент не принимает `lead_id`/`client_id` аргументом; SQL-доступ к данным клиента фильтруется `client_id` из контекста.
- MCP-серверы доступны только во внутренней сети compose (порты не публикуются), Host ограничен именем сервиса.
- Реализация: `app/security/agent_context.py` (mypy strict), `app/mcp/common.py::require_context`.

## Рассмотренные варианты

1. Идентификаторы аргументами инструментов + проверка «по смыслу» — отклонено (модель может быть обманута).
2. JWT (RFC 7519) — избыточно: один ключ, один издатель, один потребитель; формат проще и проверяется без зависимостей.
3. mTLS между сервисами — защищает транспорт, но не привязывает вызов к лиду.

## Последствия

- Хорошо: утечка между клиентами невозможна через подбор аргументов; контекст короткоживущий.
- Плохо: ротация ключа требует перезапуска api и MCP-серверов (runbook ротации ключей, Фаза 8).

## Как проверяем

Unit: подпись, подделка, просрочка, лишние поля, customer без client_id. Integration: kb-mcp по HTTP отклоняет вызов без/с поддельным контекстом. Фаза 6: негативные тесты cross-tenant.
