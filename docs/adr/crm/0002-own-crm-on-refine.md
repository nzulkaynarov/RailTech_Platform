# 0002. Собственный CRM на Refine, а не готовая CRM как ядро

- Статус: accepted (2026-10-08, решение владельца продукта в обсуждении Фазы 0)
- Дата: 2026-10-08
- Связано: SPEC §1.1, §1.7, §2, §10; docs/systems/crm/BUSINESS.md §2, §9

## Контекст и проблема

Команде нужен единый веб-интерфейс: лиды, переписка, стадии, причины эскалаций, документы клиентов, KB, настройки, роли. Центральная сущность — диалог (SPEC §1.1), чего нет в классических CRM. Варианты — взять готовую open-source CRM (Twenty, Odoo, EspoCRM) как ядро или построить свой интерфейс на фреймворке админок.

## Драйверы решения

- Диалог и объяснимость решений ИИ — в центре интерфейса.
- Единая модель данных и RBAC с ботом и агентами (одна БД, Casbin, аудит).
- «Готовое вместо кастомного» (SPEC §1.7): не писать CRUD, таблицы, формы, auth-обвязку руками.
- Рост к интеграциям (ERP, календарь) без переписывания (docs/systems/crm/BUSINESS.md §9).

## Рассмотренные варианты

1. Twenty / Odoo / EspoCRM как ядро + интеграция бота через их API.
2. Собственный бэкенд (FastAPI) + фронт на Refine + Ant Design.
3. Полностью кастомный React без фреймворка админок.

## Решение

Вариант 2. Refine даёт `authProvider`, `accessControlProvider`, раскладку и уведомления; Ant Design — компоненты. Слой данных — хуки TanStack Query, которые генерирует orval (уточнено ADR-0021, 2026-10-12: `dataProvider` и CRUD-страницы Refine не используются). Свой код — только доменные экраны (ChatThread, «Почему система так решила»). Клиент API генерируется из OpenAPI (orval).

### Последствия

- Хорошо: модель данных под диалог; одна БД и одна ролевая модель; провайдер auth заменяем на Keycloak без смены фронта.
- Плохо: базовые CRM-функции (воронки, отчёты) пишем сами; нет готовых интеграций чужой CRM.
- Фаза 0 содержит только каркас Vite + React + TS; Refine и Ant Design подключаются в Фазе 4 (docs/history/crm/PLAN.md).

### Как проверяем

Фаза 4–5: сценарии C2–C4, C6 выполняются без выхода из CRM. Пересмотр — если объём «обычных CRM-функций» в Фазе 10 превысит доменный.

## Плюсы и минусы вариантов

### Готовая CRM как ядро

- Плюс: много функций сразу.
- Минус: диалог и решения ИИ — «чужеродный» модуль; две модели данных и две ролевые модели; синхронизация; ограничения кастомизации и лицензий.

### Полностью кастомный React

- Плюс: полный контроль.
- Минус: CRUD, таблицы, права, формы — с нуля; противоречит SPEC §1.7.
