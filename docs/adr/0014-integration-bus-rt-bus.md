# 0014. Шина `rt_bus` и правило «интеграции только через шину»

- Статус: accepted (владелец, 2026-10-23) · Дата: 2026-10-23 · Меняет: ADR-0011 п. 5 (Redis Streams для интерфейса)
- Основание: стратегия §1.2, §3.4; `docs/research/2026-10-23-architecture/arch-research-benchmark.md` §2–§3

## Контекст
Сейчас интеграции точка-точка: один получатель событий ERP строкой окружения, CRM событий не публикует, BFF опрашивает
бэкенды. Подключение второго потребителя (Платформа, 1С, банк) требует переделки, а сбой внешней системы может задеть ядро.

## Решение
1. Каждый сервис публикует события своих сущностей и подписывается на чужие только через библиотеку `rt_bus`
   (`packages/rt-bus`): `publish()` в той же транзакции, что и изменение (transactional outbox), `@subscribe()` с inbox и
   дедупликацией.
2. Конверт — CloudEvents 1.0 + расширения `tenant`, `correlationid`, `traceparent`; тип —
   `uz.railtech.<домен>.<сущность>.<действие>.v<N>`; схема каждого типа — AsyncAPI 3 + JSON Schema в
   `packages/contracts/events/`; модели генерируются для всех сторон.
3. Транспорт v1 — PostgreSQL outbox + ретранслятор (Procrastinate, в ERP — Celery) + доставка подписчикам подписанным HTTP
   (HMAC v2), у каждого подписчика свой повтор с backoff и jitter, журнал, DLQ, «повторить», предохранитель. Транспорт v2 —
   NATS JetStream на третьем сервере, v3 — кластер NATS; бизнес-код транспорт не видит.
4. Платформа получает события через BFF (SSE в браузер) как обычный подписчик.
5. Внешние системы — только через коннекторы: своя очередь, свой контейнер с лимитом, манифест (версия, подписки, права,
   настройки, секреты, флаг включения); три шаблона — «API с опросом», «входящие вызовы», «ручной адаптер»; ежедневная сверка.
6. В пути пользователя нет синхронных вызовов внешних систем, кроме справочных с таймаутом и кэшем.

## Варианты
Kafka/Redpanda/Debezium/ESB на Java — отклонены (память, JVM, CPU, сложность). Redis Streams — отклонены как отдельный канал:
один механизм для всех потребителей.

## Последствия
Журнал вебхуков ERP (`IntegrationWebhookEvent`) становится outbox `rt_bus`; сигналы ERP с «глотанием» ошибок уходят; CRM
получает outbox; Admin получает «Журнал интеграций».
