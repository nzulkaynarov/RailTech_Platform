# 0001. Три системы: CRM, ERP, Cabinet — по одному главному пользователю

- Статус: proposed · Дата: 2026-10-13 · Авторы: агент, владелец

## Контекст
Две готовые системы (CRM для лидов в Telegram; B2B-платформа с КП, документами и маркетплейс-слоем)
пересекаются по лиду, клиенту и переписке и не покрывают снабжение. Владелец решил собрать из них три
системы по ролям пользователей.

## Решение
CRM — фронт-офис (лид, диалог, квалификация). ERP — бэк-офис (заявка → КП → договор → снабжение →
исполнение → финансы). Cabinet — клиент (отражение ERP, действия клиента). Каждая система служит одному
главному пользователю; чужие пользователи в неё не входят. Монорепозиторий `apps/crm`, `apps/erp`,
`apps/cabinet`; `legacy/b2b` временно.

## Рассмотренные варианты
1. Склеить две системы как есть через API — не убирает дублей и маркетплейс-балласта.
2. Один монолит — переписывание ~40 тыс. строк и смешение пользователей в одном UI.
3. Три системы по пользователям — выбрано.

## Последствия
Чёткие границы владения (BUSINESS §6), три фронтенда, два бэкенда, общая инфраструктура. Передачи между
системами формализованы (CONTRACTS).
