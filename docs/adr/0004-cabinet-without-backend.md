# 0004. Cabinet — фронтенд без собственного бэкенда над портальным API ERP

- Статус: proposed · Дата: 2026-10-13

## Контекст
Cabinet «отражает ERP и принимает действия клиента». Собственная база потребовала бы синхронизации
статусов, КП и документов — самых горячих данных.

## Решение
`apps/cabinet` — SPA на своём домене; данные и аутентификация клиента — в ERP (`/api/portal/v1/*`,
приложение `portal`). Все ответы отфильтрованы по компании сессии; негативные тесты на каждый эндпоинт.
Mini App Telegram открывает тот же SPA; подпись `initData` проверяет ERP токеном бота CRM.

## Варианты
1. Cabinet со своим бэкендом и базой — дублирование и синхронизация. Отклонено.
2. Cabinet как часть ERP SPA — смешение пользователей, нарушает ADR-0001. Отклонено.
3. Отдельный SPA над портальным API — выбрано (паттерн портала Odoo/ERPNext).

## Последствия
Отдельный деплой и домен при нулевом дублировании данных; портальный API — часть контракта.
