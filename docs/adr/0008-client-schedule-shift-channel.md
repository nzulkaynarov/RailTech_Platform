# 0008. Уведомление клиента о сдвиге срока поставки — канал по контакту, политика в ERP

- Статус: accepted (по рекомендации, архитектор — резерв Opus, 2026-10-20) · Дата: 2026-10-20 · Вопрос Q-FIX42-2

## Контекст
FIX-42 скрыл флаг `CompanySettings.notify_client_on_schedule_shift`: ERP его не читала. Лид волны 4 решил, что о сдвиге
извещает только CRM (бот) по событию `delivery.eta_changed`. Это расходится с ARCHITECTURE §7 (политика уведомлений —
настройка ERP), §15 (письмо «сдвиг срока поставки» — транзакционное письмо ERP клиенту) и BUSINESS §9 п. 6 (уведомление,
если политика «сообщать о сдвигах» включена). Бот принадлежит CRM, ERP в Telegram не пишет (ARCHITECTURE §18); но не у
каждого контакта клиента есть Telegram — клиент, работающий через Cabinet и почту, через бота сообщения не получит.

## Решение
1. ERP при любом изменении обещанной даты строки поставки шлёт событие `delivery.eta_changed` (уже есть в контракте шва).
2. **Канал выбирается по контакту**: у контакта есть Telegram, известный CRM, — сообщает бот CRM по событию; нет — ERP
   отправляет транзакционное письмо (`notifications`, шаблон компании, журнал писем). Один контакт — одно уведомление.
3. **Политика «сообщать о сдвигах»** (вкл/выкл, порог в днях, только сдвиг позже) — настройка ERP, вводится в
   M4-ERP-03 вместе с пересчётом даты клиенту из дат поставщика. Флаг FIX-42 удаляется (FIX-4xb) — до M4 автоматических
   сдвигов нет, ручное изменение даты менеджером даёт событие, и CRM ведёт себя как сейчас.
4. Тексты: бот — `settings.texts` CRM (ru/uz/en), письмо — шаблоны ERP (ru/uz/en).

## Варианты
1. Только CRM/бот — клиенты без Telegram не узнают о сдвиге. Отклонено.
2. Только письмо ERP — дублирует бота для Telegram-клиентов, ломает «один канал разговора». Отклонено.
3. Канал по контакту, политика в ERP — выбрано (так в Odoo/ERPNext: уведомление по предпочтительному каналу контакта).

## Последствия
ARCHITECTURE §7 и §15 остаются верными с уточнением «канал по контакту (ADR-0008)»; BUSINESS §9 п. 6 — без изменений.
В M4-ERP-03: настройка политики, выбор канала (`Contact.telegram_user_id` / сопоставление в CRM), тест «одно уведомление
на контакт». Решение лида волны 4 «только CRM» — уточнено этим ADR.
