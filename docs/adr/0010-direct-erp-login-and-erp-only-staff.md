# 0010. Прямой вход в ERP через общую страницу входа; сотрудники только с доступом к ERP

- Статус: accepted (владелец, 2026-10-21) · Дата: 2026-10-21 · Дополняет ADR-0003

## Контекст
ADR-0003: людей, пароли и `platform_access` ведёт CRM, ERP получает сотрудника провижинингом (без пароля —
`set_unusable_password`), переход — одноразовый SSO-токен из CRM. На проде 2026-10-21 владелец не смог войти прямо в
`erp.railtech.uz`: там осталась форма «e-mail + пароль», которая для провижиненных сотрудников не работает, а другой точки
входа в ERP нет. Узким специалистам бэк-офиса (закупки, финансы, логистика) CRM не нужна — им нужен вход прямо в ERP.

## Решение
1. **Один вход на ансамбль.** Страница входа — одна (сейчас CRM `/login`). В ERP вместо формы пароля — кнопка «Войти»:
   переход на страницу входа с `return_to` (только адреса ERP из конфигурации — без открытого редиректа), после входа CRM
   выпускает SSO-токен (ADR-0003, 60 с, одноразовый) и возвращает в ERP. Уже вошедший в CRM попадает в ERP без пароля.
2. **Доступы раздельны.** `platform_access` — независимые `crm` и `erp`; роль ERP выдаётся из CRM (FIX-63). Сотрудник
   только с `erp`: после входа сразу уходит в ERP, интерфейс и API CRM ему недоступны (403), переключатель CRM ↔ ERP
   виден только при обоих доступах. Приглашение сотрудника только с `erp` — письмо «задайте пароль» → вход → ERP.
3. **Пароль один, отключение одно.** Отдельных паролей в ERP нет; форма пароля ERP удаляется. Отключение в CRM гасит
   сессии ERP (FIX-11). Аварийный вход администратора — тот же путь.
4. Страницу входа можно позже вынести на нейтральный адрес (`id.railtech.uz`) без смены логики.

## Варианты
1. Отдельный пароль в ERP — две базы паролей, двойной сброс и двойное увольнение, против «одной консоли админа»
   (ORCHESTRATOR §3.13). Отклонено.
2. Отдельный провайдер (Keycloak) — путь миграции из ADR-0003, на пилоте лишний сервис. Отложено.
3. Общая страница входа CRM с возвратом в ERP — выбрано.

## Последствия
Задача FIX-71 (лид волны 6): кнопка «Войти» в ERP с `return_to`, сотрудник только с `erp` в CRM, удаление формы пароля
ERP, тест «специалист только ERP: приглашение → пароль → вход прямо в ERP» на чистой базе.
