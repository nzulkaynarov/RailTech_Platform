# Формат документа базы знаний CRM

Источник правды (M5-CRM-02). База знаний принимает **только Markdown (`.md`)**. PDF, Word, Excel, сканы, `.txt` и HTML
в систему не загружаются: их превращает в Markdown кто угодно вне системы — человек или сторонний ИИ-агент
(готовый промпт — [PROMPT.md](PROMPT.md)). CRM проверяет файл при загрузке и режет на фрагменты для поиска бота.
Пример правильного документа — [example.md](example.md).

## Зачем такие правила

Бот отвечает клиенту по **фрагментам** (чанкам, ≈ 500 токенов), а не по документу целиком. Фрагменты режутся по
заголовкам `##`/`###`, и путь заголовков («Гарантия > Сроки») добавляется к каждому фрагменту. Поэтому:
хорошо озаглавленный раздел = хорошо находимый ответ; «простыня» без заголовков находится хуже.

## Правила

1. **Расширение `.md`, кодировка UTF-8.** Другие расширения отклоняются сразу.
2. **Front matter YAML** в самом начале файла, между строками `---`. Поля:

   | Поле | Обязательно | Значение |
   |---|---|---|
   | `title` | да | название документа (строка) |
   | `language` | да | `ru`, `uz` или `en`; совпадает с языком, выбранным при загрузке |
   | `source` | да | откуда документ: «Прайс-лист 2026», «Договор поставки № 12» (строка) |
   | `updated` | да | дата актуальности `ГГГГ-ММ-ДД` |
   | `tags` | нет | список: `[доставка, гарантия]` |
   | `audience` | нет | для кого: `клиенты`, `менеджеры` … |

3. **Одна тема — один документ.** Прайс, гарантия и доставка — три документа. Документ на несколько тем плохо находится
   и не обновляется по частям.
4. **Один заголовок `# …`** сразу после front matter (совпадает по смыслу с `title`). Разделы — `##`, подразделы — `###`;
   глубже `###` не нужно. Заголовок описывает содержимое («Сроки гарантии»), а не «Раздел 2».
5. **Таблицы — GFM** (`| a | b |` и строка `|---|---|`). Первая строка — шапка. Таблица целиком, без разрывов и объединённых ячеек;
   единицы измерения — в шапке или в ячейке.
6. **Без картинок и ссылок на файлы.** `![...](...)`, `<img>` и ссылки на `.pdf/.docx/.xlsx/.png…` отклоняются.
   Смысл картинки, схемы или скана передаётся словами или таблицей. Ссылки на сайты (`https://…`) допустимы.
7. **Без персональных данных клиентов** (ФИО, телефоны, адреса, номера договоров конкретных клиентов) и без **внутренних
   цен/себестоимости**: бот может процитировать всё, что есть в базе. Только то, что можно сказать клиенту.
8. **Размер — не больше 100 КБ (≈ 50 страниц текста).** Обоснование: ~500 токенов на фрагмент даёт 25–50 фрагментов на
   документ; больше — признак нескольких тем в одном файле (правило 3). Большой источник разбейте на несколько документов.
9. Цифры, единицы, названия моделей и сроки переносятся **без изменений**. Нельзя ничего дописывать от себя.

## Что проверяет CRM при загрузке

Расширение `.md` → UTF-8 → размер → front matter есть и это YAML → обязательные поля → `language` из `ru|uz|en` и совпадает с формой →
`updated` — дата → `tags` — список → ровно один `# Заголовок` (строки внутри блоков кода не считаются) → нет картинок и ссылок на файлы.
При нарушении загрузка отклоняется с текстом, что исправить (ru/uz/en). Ручной документ («Написать документ» в админке) формат
не проверяет: заголовок добавляется автоматически.

Front matter не попадает в текст фрагментов; метаданные документа (название, язык, продукт) задаются в форме загрузки.
