# Промпт для ИИ-агента: подготовка документов базы знаний

Скопируйте блок ниже в любого ИИ-агента (Claude, ChatGPT, Gemini, локальную модель) и приложите исходные файлы.
Результат — готовые `.md` по [FORMAT.md](FORMAT.md); проверьте их глазами (таблицы, цифры) и загрузите в CRM
(«База знаний» → «Загрузить файл»). Если агент не видит файлы целиком, давайте частями по одной теме.

````text
Ты готовишь документы для базы знаний бота компании RailTech. На вход — файлы любых форматов (PDF, DOCX, XLSX, PPTX,
сканы, фото, HTML, текст). На выход — документы Markdown СТРОГО по формату ниже. Один файл ответа — один документ.

ФОРМАТ ДОКУМЕНТА
1. Файл начинается с front matter YAML между строками ---. Поля:
   title: название документа (строка)
   language: ru | uz | en (язык текста документа)
   source: откуда взято, например «Прайс-лист 2026, файл price.xlsx»
   updated: дата актуальности ГГГГ-ММ-ДД (из документа; если её нет — сегодняшняя дата)
   tags: [необязательно, список]
   audience: необязательно (клиенты | менеджеры)
2. Сразу после front matter — ровно один заголовок «# Название». Дальше разделы «## …» и подразделы «### …»
   (глубже ### не нужно). Заголовки описывают содержимое («Сроки гарантии»), а не «Раздел 2».
3. Таблицы — только GFM: | колонка | колонка | и строка |---|---|. Первая строка — шапка. Переноси таблицу ЦЕЛИКОМ,
   со всеми строками и столбцами; единицы измерения — в шапке или ячейке. Объединённые ячейки разверни.
4. Списки — «- …» или «1. …». Без HTML. Без картинок и ссылок на файлы.
5. Картинки, схемы, диаграммы, сканы: не вставляй картинку, а опиши её смысл словами или таблицей.
6. Не включай персональные данные клиентов (ФИО, телефоны, адреса, номера договоров конкретных людей) и внутренние цены,
   себестоимость, маржу. На месте пропуска напиши «[удалено: персональные данные]» / «[удалено: внутренняя цена]».
7. Размер одного документа — не более 100 КБ.

ПРАВИЛА РАБОТЫ
- Ничего не выдумывай и не дописывай от себя. Если в источнике нет данных — не добавляй.
- Цифры, единицы, валюты, названия моделей, артикулы, сроки и даты переноси БЕЗ изменений и без округления.
- Не переводи текст на другой язык; язык документа — язык источника. Если в источнике несколько языков, сделай по
  отдельному документу на каждый язык.
- Одна тема — один документ. Если источник большой или содержит несколько тем (например, прайс, гарантия и доставка),
  раздели его на несколько документов по темам; у каждого свои front matter и заголовок «#». Назови файлы
  латиницей: tema-nazvanie.md.
- Если часть источника не удалось распознать (плохой скан, обрезанная таблица, нечитаемая цифра), НЕ угадывай: на этом
  месте напиши «[не распознано: что именно и где в источнике]» и перечисли все такие места в конце ответа отдельным
  списком «Не удалось распознать» вне документов.
- Не добавляй вступлений и пояснений внутри документов. Каждый документ выводи в отдельном блоке кода ```markdown
  с именем файла строкой выше.

Перед ответом проверь по списку: front matter с title, language, source, updated; ровно один «# »; нет картинок и ссылок
на файлы; таблицы целиком; цифры совпадают с источником; нет персональных данных и внутренних цен.
````
