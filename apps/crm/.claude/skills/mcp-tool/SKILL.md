# Инструмент MCP

Инварианты: `SPEC §1.5`, `§7.1`, ADR-0008. Инструмент **никогда** не принимает `lead_id`/`client_id` аргументом — только из проверенного заголовка `X-Agent-Context` (HMAC, TTL 60 с).

## Шаги

1. Проверь, что инструмент есть в таблице `SPEC §7.1` и в текущей фазе `PLAN.md`. Нет — вопрос человеку.
2. Сверь API FastMCP с установленной версией: `cd backend && uv run python -c "import mcp; print(mcp.__version__)"` и документацией (WebFetch). Не выдумывай декораторы/параметры.
3. Реализация в `backend/app/mcp/<server>_server.py`:
   - входная схема — Pydantic-модель, описание полей для модели;
   - контекст (`lead_id`, `client_id`, `mode`) — из зависимости проверки HMAC; ошибка подписи/срока → отказ без деталей;
   - доступ к данным — через сервис/репозиторий; для данных клиента SQL-фильтр по `client_id` из контекста обязателен;
   - логи structlog без PII.
4. Тесты:
   - unit: схема, маппинг ошибок;
   - негативные: без заголовка, поддельная подпись, просроченный контекст, попытка передать идентификатор аргументом (схема его не принимает), чужой `client_id` (integration);
   - integration: реальный Postgres.
5. Обнови таблицу `SPEC §7.1` (если изменилась сигнатура — сначала одобрение) и профиль инструментов агента.
6. `make check`; в PR — шаг «Проверить на dev» с вопросом в боте, который вызывает инструмент, и ожидаемым трейсом в Langfuse.
