# Изменение промпта

Промпты только в `backend/prompts/*.md` (CLAUDE.md §4). Пользовательский текст и фрагменты KB — в отдельных XML-блоках. Решения (стадия, эскалация, доступ) в промпт не переносятся (`SPEC §1.3`).

## Шаги

1. Сформулируй, какое поведение меняется и какой golden-кейс это покажет. Нет кейса — сначала добавь (`eval-case`), убедись, что он падает на старом промпте.
2. Правь файл промпта; подстановка — только через явный шаблон, без f-строк с пользовательским вводом.
3. Unit-тест рендера шаблона (`tests/unit/`): все плейсхолдеры подставлены, XML-блоки экранированы.
4. Golden: обнови/добавь кейсы в `backend/evals/golden/*.yaml`; ожидания проверяемы кодом (язык, отсутствие чисел вне KB, эскалация).
5. Версия в Langfuse Prompt Management: имя = путь файла, версия = git sha (`SPEC §7.4`) — синхронизация выполняется кодом/CI, вручную не правь в UI.
6. `make check`; локально `make eval` не запускается без ключей — eval-gate отработает в CI (Фаза 7+). До Фазы 7 — приложи к PR результаты `make eval`, прогнанные человеком, или запроси прогон.
7. В PR: какие метрики `SPEC §12` затронуты, до/после; раздел «Проверить на dev» с 2–3 диалогами.
