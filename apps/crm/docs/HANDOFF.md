## Что сделать владельцу

1. **Пополнить кредиты моделей.** Anthropic: «credit balance is too low» (Plans & Billing); Gemini: «exceeded your current quota» (Google AI Studio → billing). Пока не пополнено, бот отвечает «не могу сейчас ответить», в канале висят алерты «⚠️ Модель …» — снимутся сами (проба раз в час).
2. **Разделить ключи.** В GitHub Secrets — отдельные ключи с месячным лимитом в консоли провайдера; ключи стенда — свои.
3. **Один контрольный прогон качества** после пополнения: `make eval-quick CONFIRM=yes` (≈20 вызовов, потолок $0.3). Полный eval-gate в CI — меткой `run-evals` на PR, один раз перед мержем.
4. **Ответить на вопросы** Q-010…Q-013 (`docs/QUESTIONS.md`): личные уведомления менеджеру в Telegram, контакты клиента, язык интерфейса CRM, сделка как сущность.
5. **Приёмка на dev** по чек-листам PR #7, #8 и гейтам в `docs/PROGRESS.md`.

## Запуск на новом компьютере

```bash
git clone git@github.com:nzulkaynarov/crm-rt-ai.git && cd crm-rt-ai
scripts/bootstrap_dev.sh          # .env со случайными секретами, make up, ждёт /ready
```

- Docker Desktop должен быть запущен (`open -a Docker` на macOS).
- Вписать в `.env` вручную (в git их нет и быть не должно): `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`, `TELEGRAM_BOT_TOKEN`; затем `make up`.
- **Один токен бота — один стенд.** Перед запуском на новом компьютере остановить старый: `make down` (иначе `TelegramConflictError`, бот «молчит»).
- Порт занят другим проектом — `DEV_API_PORT`, `DEV_POSTGRES_PORT` и др. в `.env` (см. `.env.example`).
- Данные стенда (лиды, клиенты, настройки, канал) живут в Docker-томах старого компьютера и не переезжают. Либо начать заново: `make kb-demo`, `make create-admin email=…`, `make settings key=notifications value='{"channel_id": -100…}'`, Telegram ID пользователей в «Пользователях»; либо перенести по `docs/runbooks/backup-restore.md`.
- Тестовая учётка аудита `audit-admin@demo.local` и демо-данные `make seed` остались на старом стенде — на новом их не будет.

## Правила работы, выученные в этой сессии (для Claude и людей)

- **Платные вызовы моделей — только с явного согласия владельца** и с названной стоимостью: `make eval`, `make eval-quick`, `make promptfoo`, `make load-test`, метка `run-evals`. Цели требуют `CONFIRM=yes`, потолок `EVAL_MAX_USD`. Юнит-, интеграционные и e2e-тесты бесплатны (подставные модели).
- **Бизнес-правила — в настройках, а не в коде.** Код — механизм, критерии задаёт админ (пример: «Настройки → Квалификация», флаг цены в «Правилах эскалации»).
- **Integration-тесты делают `TRUNCATE` всех таблиц** — никогда не направлять их на БД dev-стенда; только одноразовые контейнеры (как в CI).
- Проверка типов фронтенда — `pnpm typecheck` (`tsc -b`); `tsc -p .` ничего не проверяет.
- Eval gate в CI на пуш только напоминает; прогон — метка `run-evals` (снимается после прогона).
