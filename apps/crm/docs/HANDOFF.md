## Запуск на новом компьютере

```bash
git clone git@github.com:nzulkaynarov/crm-rt-ai.git && cd crm-rt-ai
scripts/bootstrap_dev.sh          # .env со случайными секретами, make up, ждёт /ready
```

- Docker Desktop должен быть запущен (`open -a Docker` на macOS).
- Вписать в `.env` вручную (в git их нет и быть не должно): `ANTHROPIC_API_KEY`, `GEMINI_API_KEY`,
  `TELEGRAM_BOT_TOKEN`; затем `make up`.
- **Один токен бота — один стенд.** Перед запуском на новом компьютере остановить старый: `make down`
  (иначе `TelegramConflictError`, бот «молчит»).
- Порт занят другим проектом — `DEV_API_PORT`, `DEV_POSTGRES_PORT` и др. в `.env` (см. `.env.example`).
- Данные стенда живут в Docker-томах и не переезжают: `make kb-demo`, `make create-admin email=…`,
  `make settings key=notifications value='{"channel_id": -100…}'`, Telegram ID пользователей в
  «Пользователях»; либо перенос по `docs/runbooks/backup-restore.md`.
- После `make up` контейнеры `worker`, `crm-mcp`, `kb-mcp`, `docs-mcp` не перечитывают код сами —
  `docker compose restart worker crm-mcp kb-mcp docs-mcp` (api и web перезагружаются).

## Правила работы, выученные в этих сессиях (для Claude и людей)

- **Платные вызовы моделей — только с явного согласия владельца** и с названной стоимостью: `make eval`,
  `make eval-quick`, `make promptfoo`, `make load-test`, метка `run-evals`. Цели требуют `CONFIRM=yes`,
  потолок `EVAL_MAX_USD`. Юнит-, интеграционные и e2e-тесты бесплатны (подставные модели).
- **Бизнес-правила — в настройках, а не в коде.** Код — механизм, критерии задаёт админ.
- **Integration-тесты делают `TRUNCATE` всех таблиц** — только одноразовые контейнеры, никогда БД стенда.
- **Решения владельца по дизайну = рекомендации аудита и бенчмарк** (Intercom, Front, HubSpot, Linear).
  Спорное решаем «как принято в лучших продуктах», а не «как привычно».
- **antd в режиме `cssVar`**: переопределение палитры (`green7` и т. п.) в теме не доходит до компонентов —
  цвета тегов задаются CSS-переменными `--crm-tag-*` (`app/theme.ts`, `styles/a11y.css`).
- Проверка типов фронтенда — `pnpm typecheck` (`tsc -b`); `tsc -p .` ничего не проверяет.
- Eval gate в CI на пуш только напоминает; прогон — метка `run-evals` (снимается после прогона).
